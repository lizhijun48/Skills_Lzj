# 图表绘制元技能 (Chart & Diagram Generator)

根据任务特征自动选择最优渲染引擎（SVG / Mermaid / React），实现"输入需求→选择工具→生成图表→验证输出"的全程可控。

## 核心原则

- **工具匹配任务**：不同图表类型对应不同渲染引擎，选对工具事半功倍。
- **可控性优先**：人对图表内容有清晰认知，才能准确描述需求、验证输出。
- **渐进式生成**：先确认结构和数据，再生成图表，避免返工。

## 一、三大渲染引擎选择决策树

```
需要画什么？
│
├── 结构/关系类（流程图、架构图、关系图）
│   ├── 需要精确像素控制、品牌定制、嵌入文档？
│   │   └── 是 → SVG矢量图
│   └── 需要快速生成、代码友好、可编辑？
│       └── 是 → Mermaid图表
│
├── 数据可视化类（折线图、柱状图、饼图等）
│   ├── 需要交互性、动态数据、复杂图表？
│   │   ── 是 → React图表
│   └── 需要静态展示、简单图表？
│       └── 是 → Mermaid图表（简单场景）或 SVG（定制场景）
│
└── 创意/插图类（图标、简单插图）
    └── → SVG矢量图
```

## 二、三种渲染引擎能力矩阵

### 1. SVG矢量图

**适用场景**：需要精确控制、品牌定制、嵌入文档、高质量输出的场景。

| 能力 | 说明 |
|------|------|
| 基础图形 | 矩形、圆形、多边形、路径等 |
| 图标 | 自定义图标设计和生成 |
| 简单插图 | 扁平化插图、示意图 |
| 流程图 | 精确控制的流程图 |
| 组织架构图 | 层级结构图 |

**优势**：
- 矢量无损，任意缩放
- 可精确控制每个元素的位置、颜色、样式
- 可直接嵌入HTML/Markdown
- 适合品牌化、定制化需求

**劣势**：
- 代码量大，复杂图表编写成本高
- 不适合动态数据可视化

**提示语模板**：
```
请生成一个SVG[图表类型]，要求：
- 尺寸：[宽度]x[高度]
- 配色方案：[主色/辅色/背景色]
- 内容：[具体元素描述]
- 样式：[字体/线条粗细/圆角等]
```

### 2. Mermaid图表

**适用场景**：需要快速生成、代码友好、可编辑、技术文档嵌入的场景。

| 能力 | 说明 |
|------|------|
| 流程图 (flowchart) | 业务流程、决策流程 |
| 时序图 (sequenceDiagram) | 系统交互、API调用流程 |
| 类图 (classDiagram) | 面向对象设计、类关系 |
| 状态图 (stateDiagram) | 状态机、生命周期 |
| 实体关系图 (erDiagram) | 数据库设计、实体关系 |
| 思维导图 (mindmap) | 知识梳理、头脑风暴 |

**优势**：
- 语法简洁，学习成本低
- 代码即图表，易于版本管理
- 支持多种图表类型
- 可嵌入Markdown直接渲染

**劣势**：
- 样式定制能力有限
- 复杂布局控制不足
- 不适合数据可视化

**提示语模板**：
```
请生成一个Mermaid [图表类型]代码，描述[主题]：
- 节点：[列出关键节点]
- 关系：[描述节点间的关系]
- 方向：[TB/LR/RL/BT]
- 样式要求：[如有特殊样式需求]
```

**Mermaid语法速查**：

```mermaid
%% 流程图
flowchart TB
    A[开始] --> B{判断}
    B -->|是| C[执行A]
    B -->|否| D[执行B]
    C --> E[结束]
    D --> E

%% 时序图
sequenceDiagram
    participant 用户
    participant 系统
    用户->>系统: 请求
    系统->>系统: 处理
    系统-->>用户: 响应

%% 类图
classDiagram
    class 用户 {
        +String 姓名
        +登录()
    }
    class 订单 {
        +int 订单号
        +创建()
    }
    用户 --> 订单 : 创建

%% 状态图
stateDiagram-v2
    [*] --> 待处理
    待处理 --> 进行中 : 开始
    进行中 --> 已完成 : 完成
    进行中 --> 已取消 : 取消
    已完成 --> [*]

%% 实体关系图
erDiagram
    用户 ||--o{ 订单 : 创建
    订单 ||--|{ 订单详情 : 包含
    产品 ||--o{ 订单详情 : 属于

%% 思维导图
mindmap
  root((主题))
    分支1
      子分支1.1
      子分支1.2
    分支2
      子分支2.1
```

### 3. React图表

**适用场景**：需要数据可视化、交互性、动态更新、复杂图表的场景。

| 能力 | 说明 |
|------|------|
| 折线图 (LineChart) | 趋势分析、时间序列 |
| 柱状图 (BarChart) | 对比分析、分类数据 |
| 饼图 (PieChart) | 占比分析、构成分析 |
| 散点图 (ScatterChart) | 相关性分析、分布分析 |
| 雷达图 (RadarChart) | 多维度对比、能力评估 |
| 组合图表 (ComposedChart) | 多类型数据混合展示 |

**优势**：
- 强大的数据可视化能力
- 支持交互（悬停、点击、缩放）
- 可动态更新数据
- 丰富的图表类型和配置选项

**劣势**：
- 需要React环境
- 代码复杂度较高
- 不适合纯静态文档

**提示语模板**：
```
请生成一个React [图表类型]组件，使用recharts库：
- 数据：[提供数据或描述数据结构]
- X轴：[X轴字段和标签]
- Y轴：[Y轴字段和标签]
- 颜色方案：[配色要求]
- 交互：[是否需要tooltip/legend等]
- 尺寸：[宽度x高度]
```

**React图表代码模板**：

```jsx
import { LineChart, Line, XAxis, YAxis, CartesianGrid, Tooltip, Legend, ResponsiveContainer } from 'recharts';

const data = [
  { name: '1月', value: 400 },
  { name: '2月', value: 300 },
  { name: '3月', value: 500 },
];

export default function SalesChart() {
  return (
    <ResponsiveContainer width="100%" height={300}>
      <LineChart data={data}>
        <CartesianGrid strokeDasharray="3 3" />
        <XAxis dataKey="name" />
        <YAxis />
        <Tooltip />
        <Legend />
        <Line type="monotone" dataKey="value" stroke="#8884d8" />
      </LineChart>
    </ResponsiveContainer>
  );
}
```

## 四、可控性保障：图表生成四步法

### 第一步：明确需求（输入控制）
- 确定图表类型和用途
- 明确要展示的数据或关系
- 确定受众和使用场景

**提示语**：
```
我需要生成一个[图表类型]，用于[用途]，受众是[受众描述]。
核心要展示的内容是：[列出关键点]
```

### 第二步：选择工具（工具控制）
- 根据任务-工具匹配矩阵选择渲染引擎
- 考虑输出格式要求（静态/动态/可交互）

**提示语**：
```
基于以上需求，建议使用[SVG/Mermaid/React]，原因是[说明理由]。
```

### 第三步：生成图表（过程控制）
- 提供清晰的数据和结构描述
- 指定样式和布局要求
- 分步生成，逐步确认

**提示语**：
```
请使用[工具]生成图表，数据如下：
[提供数据]
样式要求：[配色/字体/尺寸等]
```

### 第四步：验证输出（质量控制）
- 检查数据准确性
- 验证逻辑关系正确性
- 确认样式符合预期
- 必要时迭代优化

**提示语**：
```
请检查生成的图表：
1. 数据是否准确反映了[关键数据点]
2. 关系/流程是否正确表达了[逻辑关系]
3. 样式是否符合[品牌/场景]要求
如有问题，请调整[具体问题]
```

## 五、模型选择建议

| 图表任务 | 推荐模型 | 原因 |
|---------|---------|------|
| Mermaid语法生成 | 推理模型 | 需要严格的语法逻辑和结构推理 |
| SVG复杂布局 | 推理模型 | 需要精确的坐标计算和空间推理 |
| React图表代码 | 通用模型 | 需要代码生成和组件设计能力 |
| 图表需求分析 | 推理模型 | 需要理解业务逻辑和数据关系 |
| 图表样式优化 | 通用模型 | 需要创意和审美判断 |
| 数据可视化方案 | 推理模型 | 需要分析数据特征选择最佳图表类型 |

## 六、常见陷阱与应对

| 陷阱 | 症状 | 应对策略 |
|------|------|---------|
| 工具选错 | 生成的图表不符合需求 | 先用决策树确定工具，不要凭感觉选 |
| 数据不准确 | 图表展示的数据有误 | 生成后必须验证数据，不要盲目信任 |
| 样式不统一 | 多个图表风格不一致 | 建立配色和样式规范，统一应用 |
| 过度复杂 | 图表信息过载 | 遵循"一图一主题"原则，复杂内容分图展示 |
| 语法错误 | Mermaid/SVG代码无法渲染 | 使用在线工具验证语法，逐步调试 |

## 使用建议

1. **先选工具再动手**：用决策树确定渲染引擎，避免返工。
2. **数据先行**：先确认数据准确，再生成图表。
3. **渐进式生成**：简单版本→验证→逐步完善，不要一次追求完美。
4. **建立图表库**：常用图表类型保存为模板，提高复用效率。
5. **验证不可省略**：生成的图表必须人工验证，特别是数据和逻辑关系。
