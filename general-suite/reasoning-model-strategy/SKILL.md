# 推理模型使用策略 (Reasoning Model Strategy)

基于清华大学《DeepSeek：从入门到精通》提炼的推理模型与通用模型选择及提示语策略。

## 三大关键原则（PDF原文提炼）

> 这是使用AI时最核心的三条原则，适用于所有场景。

| 原则 | 核心要点 | 推理模型 | 通用模型 |
|------|---------|---------|---------|
| **1. 模型选择** | 优先根据任务类型而非模型热度选择 | 数学任务、逻辑分析、代码生成 → 选推理模型 | 创意任务、文本生成、开放问答 → 选通用模型 |
| **2. 提示语设计** | 因模型特性调整提示语风格 | 简洁指令，聚焦目标，信任其内化能力（"要什么直接说"） | 结构化、补偿性引导（"缺什么补什么"） |
| **3. 避免误区** | 不要反向使用提示语策略 | 不要用"启发式"提示（如角色扮演），可能干扰逻辑主线 | 不要"过度信任"（如直接询问复杂推理问题，需分步验证结果） |

## 核心原则

- **模型选择因任务而异**：优先根据任务类型而非模型热度选择。
- **推理模型要"信任"**：简洁指令，聚焦目标，信任其内化推理能力。
- **通用模型要"补偿"**：结构化引导，分步提示，缺什么补什么。
- **不要反向使用**：不要对推理模型过度拆解步骤，不要对通用模型过度信任。
- **可控性优先**：无论选哪种模型，核心诉求是从输入到输出全程可控——这要求人对任务本身有较高认知，才能知道输入什么、判断输出结果。
- **提示语是认知外化**：提示语工程的本质是把人的专业判断转化为AI可执行的指令，认知深度决定提示语质量。

## 一、推理模型 vs 通用模型

### 核心差异

| 维度 | 推理模型 | 通用模型 |
|------|---------|---------|
| 代表产品 | DeepSeek-R1, GPT-o3 | GPT-4, Claude, Gemini |
| 优势领域 | 数学推导、逻辑分析、代码生成、复杂问题拆解 | 文本生成、创意写作、多轮对话、开放性问答 |
| 劣势领域 | 发散性任务（如诗歌创作） | 需要严格逻辑链的任务（如数学证明） |
| 运算原理 | 链式思维(CoT)，逐步推理 | 概率预测，快速生成 |
| 响应速度 | 较慢，算力成本高 | 较快，算力成本低 |
| 创造力 | 能生成新创意和解决方案 | 限于模式识别和优化 |

### 选择决策树

```
任务是什么？
├── 需要严格逻辑推理？
│   ├── 是 → 推理模型（数学证明、逻辑分析、代码调试）
│   └── 否 → 继续判断
├── 需要创意发散？
│   ├── 是 → 通用模型（创意写作、头脑风暴、开放讨论）
│   └── 否 → 继续判断
├── 需要快速响应？
│   ├── 是 → 通用模型（即时对话、简单问答）
│   └── 否 → 推理模型（复杂分析、多步推理）
```

## 二、提示语策略差异

### 推理模型的提示语设计

**核心要诀：要什么直接说**

- 提示语更简洁，只需明确任务目标和需求
- 无需逐步指导，模型自动生成结构化推理过程
- 若强行拆解步骤，反而可能限制其能力
- 避免使用"启发式"提示（如角色扮演），可能干扰逻辑主线

**好的推理模型提示语**：
```
证明勾股定理
```
```
用Python实现快速排序
```
```
分析"电车难题"中的功利主义与道德主义冲突
```

**应避免的**：
```
请先画图，再列公式，一步一步推导勾股定理  ← 过度拆解
假设你是一位数学家，用你的专业知识来...  ← 角色扮演干扰逻辑
```

### 通用模型的提示语设计

**核心要诀：缺什么补什么**

- 需显式引导推理步骤（如通过CoT提示）
- 否则可能跳过关键逻辑
- 依赖提示语补偿能力短板
- 要求分步思考、提供示例

**好的通用模型提示语**：
```
请分三步推导勾股定理：
1. 画直角三角形，标注各边
2. 列出面积关系式
3. 推导出a²+b²=c²
```
```
先解释快速排序原理，再写出代码并测试示例
```

**应避免的**：
```
写个排序代码  ← 过于模糊
你觉得AI的未来会怎样？分三点回答  ← 强制逻辑链条
```

## 三、从"下达指令"到"表达需求"

### 四大提示策略

| 策略 | 定义 | 适用场景 | 推理模型 | 通用模型 |
|------|------|---------|---------|---------|
| 指令驱动 | 直接给出明确步骤或格式要求 | 简单任务、需快速执行 | 结果精准高效 | 限制模型自主优化空间 |
| 需求导向 | 描述问题背景与目标，由模型规划路径 | 复杂问题、需模型自主推理 | 激发深层推理 | 需清晰定义需求边界 |
| 混合模式 | 结合需求描述与约束条件 | 兼顾目标与细节 | 平衡灵活性与可控性 | 需避免过度约束 |
| 启发式提问 | 通过提问引导模型主动思考 | 探索性问题、需模型解释逻辑 | 可能偏离核心目标 | 触发自解释能力 |

### 关键原则

**推理模型**：优先使用"需求导向"策略——描述问题和目标，信任模型自主规划解决路径。

**通用模型**：优先使用"指令驱动"+"混合模式"——给出明确步骤和约束，补偿其推理短板。

## 四、任务-模型-提示语匹配矩阵

| 任务类型 | 适用模型 | 提示语侧重点 | 有效示例 | 需避免的策略 |
|---------|---------|------------|---------|------------|
| 数学证明 | 推理模型 | 直接提问，无需分步引导 | "证明勾股定理" | 冗余拆解步骤 |
| 数学证明 | 通用模型 | 显式要求分步思考 | "分三步推导勾股定理：1...2...3..." | 直接提问 |
| 创意写作 | 推理模型 | 鼓励发散性，设定角色/风格 | "以海明威的风格写冒险故事" | 过度约束逻辑 |
| 创意写作 | 通用模型 | 需明确约束目标 | "写含'量子'和'沙漠'的短篇，不超200字" | 开放式指令 |
| 代码生成 | 推理模型 | 简洁需求，信任模型逻辑 | "用Python实现快速排序" | 分步指导 |
| 代码生成 | 通用模型 | 细化步骤，明确输入输出 | "先解释原理，再写代码并测试" | 模糊需求 |
| 多轮对话 | 通用模型 | 自然交互，无需结构化指令 | "你觉得AI的未来会怎样？" | 强制逻辑链条 |
| 逻辑分析 | 推理模型 | 直接抛出复杂问题 | "分析电车难题中的伦理冲突" | 添加主观引导 |
| 逻辑分析 | 通用模型 | 拆分问题，逐步追问 | "先解释定义，再对比两种观点" | 一次性提问复杂逻辑 |

## 五、快思慢想：效能兼顾

理解"快系统"和"慢系统"的互补关系：

| 维度 | 概率预测（快系统） | 链式推理（慢系统） |
|------|------------------|------------------|
| 代表 | ChatGPT-4o等 | DeepSeek-R1, OpenAI-o1等 |
| 响应速度 | 快 | 慢 |
| 运算原理 | 大量数据训练快速预测 | 逐步推理每个步骤 |
| 决策能力 | 依赖预设算法和规则 | 自主分析，实时决策 |
| 问题解决 | 擅长结构化、定义明确的问题 | 处理多维度和非结构化问题 |
| 适用场景 | 日常对话、简单问答、快速反馈 | 复杂分析、数学推导、代码生成 |

**最佳实践**：简单任务用快系统，复杂任务用慢系统，两者结合实现效能最优。

## 六、可控性原则：从输入到输出的全程掌控

### 核心理念

无论选择推理模型还是通用模型，核心诉求是**从输入到输出全程可控**。可控性的前提是：人对任务本身有较高认知，才能知道输入什么、判断输出结果。

### 可控性三层模型

```
输入可控 → 过程可控 → 输出可控
   ↓           ↓           ↓
知道要什么   知道怎么给   知道对不对
```

**输入可控**：
- 明确任务目标和期望输出
- 提供充分的上下文和约束条件
- 基于对任务的深度理解设计提示语

**过程可控**：
- 选择合适的模型类型（推理/通用）
- 采用匹配的提示语策略
- 分步验证关键节点

**输出可控**：
- 建立输出质量评估标准
- 交叉验证关键信息
- 必要时迭代优化

### 认知深度决定提示语质量

提示语工程的本质是**认知外化**——把人的专业判断转化为AI可执行的指令。

| 认知层次 | 提示语特征 | 输出质量 |
|---------|-----------|---------|
| 浅层认知 | 模糊、泛化、缺乏约束 | 随机性强，质量不稳定 |
| 中层认知 | 有结构、有约束、有示例 | 质量可控，但可能缺乏深度 |
| 深层认知 | 精准、结构化、有验证机制 | 质量高且稳定，可预测性强 |

### 可控性检查清单

**输入阶段**：
- [ ] 我是否清楚这个任务的目标和期望输出？
- [ ] 我是否提供了足够的上下文和背景信息？
- [ ] 我是否明确了输出的格式和质量标准？
- [ ] 我是否识别了任务的关键约束和边界条件？

**过程阶段**：
- [ ] 我是否选择了合适的模型类型？
- [ ] 我的提示语策略是否匹配模型特性？
- [ ] 我是否设计了验证节点来检查中间结果？
- [ ] 我是否预留了迭代优化的空间？

**输出阶段**：
- [ ] 我是否有明确的标准来判断输出质量？
- [ ] 我是否验证了关键数据和逻辑关系？
- [ ] 我是否识别了可能的偏见或错误？
- [ ] 我是否知道如何迭代优化不满意的部分？

### 认知提升路径

1. **领域知识积累**：深入学习任务相关领域，建立专业判断力
2. **AI能力边界认知**：了解不同AI的优劣势，知道什么能做什么不能做
3. **提示语模式积累**：建立个人提示语库，沉淀有效的提示语模式
4. **输出评估能力**：培养快速识别AI输出质量的能力
5. **迭代优化经验**：通过实践积累迭代优化的经验和直觉

## 七、多模型协同工作模式

### 7.1 核心理念

不同模型有不同的能力侧重——一个擅长发散创意，另一个擅长收敛验证。将多个模型组合使用，让各自发挥优势，可以产生"1+1>2"的协同效果。

> **核心原则**：不是"选一个最好的模型"，而是"让对的模型做对的事"。

### 7.2 三种协同模式

#### 模式一：发散 + 收敛（头脑风暴 → 精炼筛选）

```
┌──────────────────┐      ┌──────────────────┐
│  通用模型（发散）   │ ──→  │  推理模型（收敛）   │
│  创意生成、头脑风暴  │      │  数据分析、效果预测  │
│  开放式探索         │      │  精准筛选、逻辑验证  │
└──────────────────┘      └──────────────────┘
```

**典型场景**：
- 用通用模型生成10个营销方案创意 → 用推理模型分析哪些最能引起目标受众共鸣
- 用通用模型列出产品改进方向 → 用推理模型评估技术可行性和ROI

**示例工作流**：
```
第1步（通用模型）："为环保产品线生成10个社交媒体营销创意"
第2步（推理模型）："分析以下10个创意，基于目标受众（25-35岁女性）、
     预算（5万元）和预期ROI，筛选出最优的3个并说明理由"
```

#### 模式二：创作 + 分析（内容生成 → 质量验证）

```
┌──────────────────┐      ┌──────────────────┐
│  通用模型（创作）   │ ──→  │  推理模型（分析）   │
│  文章撰写、文案起草  │      │  事实核查、数据验证  │
│  语言表达、风格塑造  │      │  逻辑审查、SEO优化  │
└──────────────────┘      └──────────────────┘
```

**典型场景**：
- 用通用模型起草博客文章 → 用推理模型进行数据事实核查并优化SEO
- 用通用模型撰写社交媒体广告 → 用推理模型分析参与度预测并调整文案

**示例工作流**：
```
第1步（通用模型）："撰写一篇关于AI趋势的博客文章初稿"
第2步（推理模型）："对以下文章进行：1.事实核查（标注需要验证的数据）
     2.逻辑审查（检查论证链条） 3.SEO优化建议"
```

#### 模式三：教学 + 练习（知识讲解 → 巩固强化）

```
┌──────────────────┐      ┌──────────────────┐
│  通用模型（教学）   │ ──→  │  推理模型（练习）   │
│  概念解释、知识传授  │      │  题目生成、测验评估  │
│  类比说明、简化表达  │      │  个性化反馈、难度调整 │
└──────────────────┘      └──────────────────┘
```

**典型场景**：
- 用通用模型用通俗语言解释复杂概念（如区块链） → 用推理模型生成练习题和测验巩固理解
- 用通用模型讲解方法论框架 → 用推理模型设计案例分析题检验掌握程度

### 7.3 协同模式选择决策

```
任务的核心挑战是什么？
├── 需要创意突破？
│   └── 是 → 发散+收敛模式（先广撒网，再精准筛选）
├── 需要内容质量保障？
│   └── 是 → 创作+分析模式（先生成，再验证优化）
├── 需要知识传递效果？
│   └── 是 → 教学+练习模式（先讲解，再巩固）
└── 单一模型即可完成？
    └── 是 → 无需协同，选择最合适的单一模型
```

### 7.4 协同工作流设计原则

| 原则 | 说明 | 反模式 |
|------|------|--------|
| **职责分明** | 每个模型只做自己最擅长的事 | 让推理模型做创意发散、让通用模型做逻辑验证 |
| **信息传递清晰** | 上游模型的输出要结构化传递给下游 | 直接把原始输出丢给下一个模型不做整理 |
| **人在回路** | 在模型切换的关键节点进行人工审核 | 全自动串联，中间不做质量把关 |
| **迭代反馈** | 下游模型的发现可以反馈给上游模型重新生成 | 单向流动，不做回溯优化 |

## 八、专用AI vs 通用AI 决策框架

### 8.1 两类AI的定位

| 类型 | 特征 | 代表工具 | 适用场景 |
|------|------|---------|---------|
| **通用AI** | 跨领域广泛适用，擅长理解、推理、生成 | ChatGPT、DeepSeek、Claude、Gemini | 头脑风暴、策略规划、内容构思、基础分析 |
| **专用AI** | 特定领域深度优化，擅长精准执行 | MidJourney（视觉设计）、Grammarly（写作润色）、Zapier（流程自动化）、DALL-E（图像生成） | 需要高精度和专业度的特定任务执行 |

### 8.2 选择决策树

```
你要完成的任务是什么？
├── 需要跨领域理解、创意生成、策略规划？
│   └── 是 → 通用AI（DeepSeek/ChatGPT）
├── 需要特定领域的高精度输出？
│   ├── 视觉设计 → MidJourney / DALL-E
│   ├── 写作润色 → Grammarly
│   ├── 流程自动化 → Zapier / Make
│   └── 其他专业领域 → 对应的专用AI
├── 任务包含多个阶段？
│   └── 是 → 通用AI做策略 → 专用AI做执行（见8.3）
└── 不确定？
    └── 先用通用AI探索，明确需求后再引入专用AI
```

### 8.3 最佳实践：通用定策略 + 专用精执行

大多数高质量产出来自"通用AI + 专用AI"的组合使用：

```
┌────────────────────────────────────────────────┐
│  阶段一：通用AI（策略层）                         │
│  · 理解需求、明确目标                             │
│  · 制定方案和策略                                 │
│  · 生成内容框架和方向                             │
└───────────────────┬────────────────────────────┘
                    ↓
┌────────────────────────────────────────────────┐
│  阶段二：专用AI（执行层）                         │
│  · 基于策略进行精准执行                            │
│  · 生成高质量的领域特定产出                         │
│  · 满足专业标准和精度要求                           │
└───────────────────┬────────────────────────────┘
                    ↓
┌────────────────────────────────────────────────┐
│  阶段三：通用AI（整合层）                         │
│  · 汇总各专用AI的产出                             │
│  · 统一风格和质量把控                              │
│  · 形成最终交付物                                  │
└────────────────────────────────────────────────┘
```

**真实案例**：
```
小企业主的社交媒体营销工作流：
1. DeepSeek（通用）→ 制定营销策略、起草广告文案
2. MidJourney（专用）→ 基于文案生成配套视觉素材
3. Zapier（专用）→ 自动化发布到多个社交平台
4. DeepSeek（通用）→ 分析发布后的数据反馈，优化下一轮策略
```

### 8.4 工作流自动化三步法

| 步骤 | 行动 | 关键问题 |
|------|------|---------|
| **1. 识别重复性任务** | 找出工作流中耗时但低创造力的环节 | "哪些任务我在重复做？哪些不需要深度思考？" |
| **2. 构建自动化流程** | 用集成工具（Zapier/Make）将AI串联 | "哪些环节可以用AI替代？数据如何在工具间流转？" |
| **3. 监控与优化** | 定期评估自动化效果，调整参数 | "节省了多少时间？质量是否达标？瓶颈在哪？" |

### 8.5 构建个人AI工具生态

```
┌─────────────────────────────────────────┐
│  核心层：通用AI（策略+整合）               │
│  DeepSeek / ChatGPT / Claude             │
├─────────────────────────────────────────┤
│  执行层：专用AI（精准执行）                │
│  MidJourney · Grammarly · Zapier · ...   │
├─────────────────────────────────────────┤
│  连接层：自动化工具（流程串联）             │
│  Zapier · Make · IFTTT                   │
├─────────────────────────────────────────┤
│  管理层：项目管理（产出组织）               │
│  Notion · Trello · Slack                 │
└─────────────────────────────────────────┘
```

**构建原则**：
- 通用AI是核心，专用AI是延伸——先做好核心，再扩展工具链
- 工具服务于流程，流程服务于目标——不要为了用工具而用工具
- 逐步添加，验证后再扩展——每增加一个工具，先验证其在流程中的价值

## 使用建议

1. **拿到任务先判断类型**：逻辑密集型选推理模型，创意开放型选通用模型。
2. **推理模型的提示语做减法**：去掉不必要的步骤拆解和角色扮演，直接说需求。
3. **通用模型的提示语做加法**：补充步骤引导、示例、格式要求等补偿性内容。
4. **不要迷信单一模型**：可以快系统做初稿，慢系统做审核和优化。
5. **多模型协同提升质量**：对复杂任务，用"发散+收敛"或"创作+分析"模式组合不同模型。
6. **通用定策略，专用做执行**：先用通用AI明确方向，再用专用AI精准产出。
7. **提升任务认知**：在使用AI前，先深化对任务本身的理解，这是可控性的基础。
8. **建立评估标准**：提前定义什么是"好的输出"，才能有效判断和迭代。
