# 提示语工程基础 (Prompt Engineering Basics)

基于清华大学《DeepSeek：从入门到精通》系统提炼的提示语工程核心知识与实操框架。

## 核心原则

- **AI是合格的咨询师**：不是问答机器，而是能根据实际情况诊断问题、给出建议并推动落地的角色。一个好的咨询师先问诊（诊断需求类型和缺失信息），再开方（选择匹配的策略和模型），最后跟踪（确保建议可落地、可验证）。本技能的所有框架和工具，都是这个咨询师角色的"诊疗工具箱"。
- **结构决定质量**：提示语 = 指令(Instruction) + 上下文(Context) + 期望(Expectation)，三要素缺一不可。
- **元素协同增效**：信息类、结构类、控制类三大元素互补增强，产生1+1>2的效果。
- **策略因境而变**：根据任务类型、模型类型、需求类型灵活选择提示语策略。

## 一、提示语的DNA——三大基本元素

### 1. 信息类元素
决定AI需要处理的具体内容，为AI提供必要的知识和上下文。
- **主题元素**：核心话题和讨论对象
- **背景元素**：任务相关的背景信息
- **数据元素**：具体数据、事实、参考材料
- **知识域元素**：专业领域知识范围

### 2. 结构类元素
定义生成内容的组织形式和呈现方式。
- **任务指令元素**：明确指定AI要完成的任务
- **结构元素**：输出的组织方式（如分段、列表、表格）
- **格式元素**：输出格式要求（如字数、语言、文件类型）
- **风格元素**：语言风格和表达基调

### 3. 控制类元素
管理和引导AI的生成过程，确保输出符合预期。
- **约束条件元素**：限制范围和边界
- **质量控制元素**：输出质量标准和验证方法
- **迭代指令元素**：多轮交互和逐步优化
- **输出验证元素**：结果检查和自我评估

### 元素组合矩阵

| 目标 | 主要元素组合 | 次要元素组合 |
|------|------------|------------|
| 提高输出准确性 | 主题 + 数据 + 质量控制 | 知识域 + 输出验证 |
| 增强创造性思维 | 主题 + 背景 + 约束条件 | 参考 + 迭代指令 |
| 优化任务执行效率 | 任务指令 + 结构 + 格式长度 | 风格元素 |
| 提升输出一致性 | 风格 + 知识域 + 约束条件 | 格式 + 质量控制 |
| 增强交互体验 | 迭代指令 + 输出验证 + 质量控制 | 任务指令 + 背景 |

## 二、六大提示语类型

| 类型 | 定义 | 示例 |
|------|------|------|
| 指令型 | 直接告诉AI执行什么任务 | "将以下内容翻译为法语" |
| 问答型 | 向AI提出问题获取答案 | "解释量子计算的基本原理" |
| 角色扮演型 | 要求AI扮演特定角色 | "假设你是一位资深产品经理" |
| 创意型 | 引导AI进行创意内容生成 | "用科幻风格写一个短篇故事" |
| 分析型 | 要求AI对信息进行分析和推理 | "对比分析这两种方案的优劣" |
| 多模态型 | 结合文本、图像等多种形式输入 | "根据这张图片写一段描述" |

## 三、五大核心调教策略

### 策略一：精准定义任务，减少模糊性
- 明确核心问题，具体化生成指令
- 去除多余信息，避免歧义

### 策略二：适当分解复杂任务，降低AI认知负荷
- 分段生成、逐层深入
- 设置逻辑结构，明确各段关系

### 策略三：引入引导性问题，提升生成内容深度
- 设置多层次问题
- 促使AI对比或论证
- 引导思维的多样性

### 策略四：控制提示语长度，确保生成准确性
- 避免嵌套复杂指令
- 保持简洁性
- 使用分步提示

### 策略五：灵活运用开放式与封闭式提示
- **开放式**：提出开放性问题，允许多角度生成
- **封闭式**：提出具体问题或设定明确限制，要求精准回答

## 四、任务需求与提示语策略（PDF原文完整矩阵）

> 这是最实用的速查表——针对每种任务类型，明确该用什么模型、怎么写提示语、要避免什么。

| 任务类型 | 适用模型 | 提示语侧重点 | 有效提示示例 | 需避免的提示策略 |
|---------|---------|------------|------------|----------------|
| **数学证明** | 推理模型 | 直接提问，无需分步引导 | "证明勾股定理" | 冗余拆解（如"先画图，再列公式"） |
| **数学证明** | 通用模型 | 显式要求分步思考，提供示例 | "请分三步推导勾股定理，参考：1.画直角三角形…" | 直接提问（易跳过关键步骤） |
| **创意写作** | 推理模型 | 鼓励发散性，设定角色/风格 | "以海明威的风格写一个冒险故事" | 过度约束逻辑（如"按时间顺序列出"） |
| **创意写作** | 通用模型 | 需明确约束目标，避免自由发挥 | "写一个包含'量子'和'沙漠'的短篇小说，不超过200字" | 开放式指令（如"自由创作"） |
| **代码生成** | 推理模型 | 简洁需求，信任模型逻辑 | "用Python实现快速排序" | 分步指导（如"先写递归函数"） |
| **代码生成** | 通用模型 | 细化步骤，明确输入输出格式 | "先解释快速排序原理，再写出代码并测试示例" | 模糊需求（如"写个排序代码"） |
| **多轮对话** | 通用模型 | 自然交互，无需结构化指令 | "你觉得人工智能的未来会怎样？" | 强制逻辑链条（如"分三点回答"） |
| **多轮对话** | 推理模型 | 需明确对话目标，避免开放发散 | "从技术、伦理、经济三方面分析AI的未来" | 情感化提问（如"你害怕AI吗？"） |
| **逻辑分析** | 推理模型 | 直接抛出复杂问题 | "分析'电车难题'中的功利主义与道德主义冲突" | 添加主观引导（如"你认为哪种对？"） |
| **逻辑分析** | 通用模型 | 需拆分问题，逐步追问 | "先解释电车难题的定义，再对比两种伦理观的差异" | 一次性提问复杂逻辑 |

## 五、如何向AI表达需求（5类需求×双模型适配）

> 不同类型的需求，有不同的表达公式和模型适配策略。

| 需求类型 | 特点 | 需求表达公式 | 推理模型适配策略 | 通用模型适配策略 |
|---------|------|------------|----------------|----------------|
| **1. 决策需求** | 需权衡选项、评估风险、选择最优解 | 目标 + 选项 + 评估标准 | 要求逻辑推演和量化分析 | 直接建议，依赖模型经验归纳 |
| **2. 分析需求** | 需深度理解数据/信息、发现模式或因果关系 | 问题 + 数据/信息 + 分析方法 | 触发因果链推导与假设验证 | 表层总结或分类 |
| **3. 创造性需求** | 需生成新颖内容（文本/设计/方案） | 主题 + 风格/约束 + 创新方向 | 结合逻辑框架生成结构化创意 | 自由发散，依赖示例引导 |
| **4. 验证需求** | 需检查逻辑自洽性、数据可靠性或方案可行性 | 结论/方案 + 验证方法 + 风险点 | 自主设计验证路径并排查矛盾 | 简单确认，缺乏深度推演 |
| **5. 执行需求** | 需完成具体操作（代码/计算/流程） | 任务 + 步骤约束 + 输出格式 | 自主优化步骤，兼顾效率与正确性 | 严格按指令执行，无自主优化 |

### 实操案例

**决策需求**：
> "为降低物流成本，现有两种方案：自建区域仓库（初期投入高，长期成本低）②与第三方合作（按需付费，灵活性高）。请根据ROI计算模型，对比5年内的总成本并推荐最优解。"

**分析需求**：
> "分析近三年新能源汽车销量数据（附CSV），说明：①增长趋势与政策关联性；②预测2025年市占率，需使用ARIMA模型并解释参数选择依据。"

**创造性需求**：
> "设计一款智能家居产品，要求：①解决独居老人安全问题；②结合传感器网络和AI预警；③提供三种不同技术路线的原型草图说明。"

**验证性需求**：
> "以下是某论文结论：'神经网络模型A优于传统方法B'。请验证：①实验数据是否支持该结论；②检查对照组设置是否存在偏差；③重新计算p值并判断显著性。"

**执行需求**：
> "将以下C语言代码转换为Python，要求：①保持时间复杂度不变；②使用numpy优化数组操作；③输出带时间测试案例的完整代码。"

### 需求识别信号：怎么判断自己是哪类需求？

很多时候"知道要什么"说起来容易，但一到表达就模糊——因为没分清需求类型。下表帮你快速自我诊断：

| 你的内心状态 | 对应需求类型 | 你真正需要的是 | 最容易犯的错误 |
|------------|------------|-------------|-------------|
| "有几个选项拿不定主意" | **决策需求** | 对比分析+推荐 | 只说"帮我选一个"但不给评估标准 |
| "一堆数据/信息看不懂" | **分析需求** | 找规律+解释因果 | 只丢数据不说要用什么分析方法 |
| "想要个新东西但没头绪" | **创造性需求** | 灵感+方案原型 | 说"帮我创新"但不给约束和方向 |
| "有个结论不确定对不对" | **验证需求** | 检查+反驳+风险评估 | 只说"帮我看看"不说从哪个角度验证 |
| "知道要做什么，需要执行" | **执行需求** | 精确操作+格式化输出 | 步骤约束不够细，输出格式没指定 |

### 填空模板：直接套用的表达公式

每种需求类型对应一个填空模板，降低"说清楚"的门槛：

**决策需求模板**：
```
我需要做一个决策：[一句话描述决策目标]
现有以下选项：
① [选项A]：优势是[ ]，劣势是[ ]
② [选项B]：优势是[ ]，劣势是[ ]
我的评估标准是：[列出2-3个关键标准，按重要性排序]
请根据以上标准对比分析，并给出推荐和理由。
```

**分析需求模板**：
```
请分析以下信息：[描述数据来源和范围]
核心问题：[你想通过发现什么规律/因果关系]
分析方法：[希望使用的分析框架或模型，如不确定可留空让AI建议]
输出要求：①[关键发现] ②[原因解释] ③[趋势预测]
```

**创造性需求模板**：
```
请帮我设计/创作：[一句话描述目标产出]
约束条件：①[必须满足的硬约束] ②[风格/调性要求]
创新方向：希望在[某个维度]上有突破
参考：[可选，提供参考案例或灵感来源]
请提供[2-3]个不同方向的方案草案。
```

**验证需求模板**：
```
请帮我验证以下结论/方案：[描述待验证的内容]
验证角度：①[数据是否支持] ②[逻辑是否自洽] ③[是否有遗漏的风险点]
已知前提：[列出你确认的前提条件]
请明确指出哪些部分可信、哪些存疑，并给出进一步验证建议。
```

**执行需求模板**：
```
任务：[一句话描述要完成的具体操作]
输入：[提供必要的输入数据/代码/文件]
步骤约束：①[步骤1要求] ②[步骤2要求] ③[步骤3要求]
输出格式：[明确期望的输出格式和标准]
验收标准：[什么算"做完了"、什么算"做好了"]
```

## 六、高级提示语框架

### TASTE框架

TASTE框架专注于精确控制输出的格式和风格，特别适合需要明确受众定位和表达风格的任务。

| 要素 | 说明 | 示例 |
|------|------|------|
| **T**ask（任务） | 定义模型主要任务或生成内容 | 写一篇关于数据隐私的重要性的简短博客文章 |
| **A**udience（目标受众） | 明确说明目标受众 | 普通的互联网用户，非技术背景 |
| **S**tructure（结构） | 为输出的内容提供明确的组织结构 | 文章需要有明确的开头、中间讨论和结尾 |
| **T**one（语气） | 指定模型回答时的语气或风格 | 采用友好、易懂的语气 |
| **E**xample（示例） | 例子或模板可帮助模型理解输出风格或格式 | 类似于《纽约时报》科技专栏的风格 |

**适用场景**：需要精确控制输出格式和风格，如营销文案、博客文章、社交媒体内容等。

**独特价值**：Example要素提供风格锚定，让模型有明确的参照标准。

### ALIGN框架

ALIGN框架专注于控制内容的难度级别和创新程度，适合需要平衡可理解性与原创性的任务。

| 要素 | 说明 | 示例 |
|------|------|------|
| **A**im（目标） | 明确任务的最终目标 | 创建一篇关于"可持续发展"的文章 |
| **L**evel（难度级别） | 定义输出的难度级别 | 适合高中生阅读，不需要专业术语 |
| **I**nput（输入） | 指定需要处理的输入数据或信息 | 提供目前的环境问题的背景 |
| **G**uidelines（指导原则） | 提供模型在执行任务时应该遵循的规则或约束 | 文章应使用简洁明了的语言 |
| **N**ovelty（新颖性） | 明确是否需要模型提供原创性、创新性的内容 | 要求结合最新的环境数据，提出新颖的观点 |

**适用场景**：需要控制内容深度和创新程度，如教育材料、科普文章、技术文档等。

**独特价值**：Novelty要素明确创新边界，避免模型过度保守或过度发散。

### 框架对比与选择

| 维度 | TASTE | ALIGN |
|------|-------|-------|
| 侧重方向 | 输出控制（受众/结构/语气/示例） | 难度与创新性控制 |
| 适用场景 | 需要精确控制输出格式和风格 | 需要控制内容深度和创新程度 |
| 独特价值 | Example要素提供风格锚定 | Novelty要素明确创新边界 |
| 典型任务 | 营销文案、博客文章、社交媒体 | 教育材料、科普文章、技术文档 |

**选择建议**：
- 如果你更关心"输出看起来像什么"（风格、格式、语气）→ 选TASTE
- 如果你更关心"内容有多深、多新"（难度、创新性）→ 选ALIGN
- 复杂任务可以组合使用：用TASTE控制形式，用ALIGN控制内容深度

## 七、常见陷阱与应对（PDF原文详细版）

### 陷阱1：缺乏迭代——期待一次性完美结果

| 维度 | 内容 |
|------|------|
| **陷阱症状** | ①过度复杂的初始提示语 ②对初次输出结果不满意就放弃 ③缺乏对AI输出的分析和反馈 |
| **应对策略** | ①采用增量方法：从基础提示语开始，逐步添加细节和要求 ②主动寻求反馈：要求AI对其输出进行自我评估，并提供改进建议 ③准备多轮对话：设计一系列后续问题，用于澄清和改进初始输出 |

### 陷阱2：过度指令和模糊指令——当细节淹没重点或意图不明确

| 维度 | 内容 |
|------|------|
| **陷阱症状** | ①提示语异常冗长或过于简短 ②AI输出与期望严重不符 频繁需要澄清或重新解释需求 |
| **应对策略** | ①平衡详细度：提供足够的上下文，但避免过多限制 ②明确关键点：突出最重要的2-3个要求 ③使用结构化格式：采用清晰的结构来组织需求 提供示例：如果可能，给出期望输出的简短示例 |

### 陷阱3：假设偏见——当AI只告诉你想听的

| 维度 | 内容 |
|------|------|
| **陷阱症状** | ①提示语中包含明显立场或倾向 ②获得的信息总是支持特定观点 缺乏对立或不同观点的呈现 |
| **应对策略** | ①自我审视：在设计提示语时，反思自己可能存在的偏见 ②使用中立语言：避免在提示语中包含偏见或预设立场 ③要求多角度分析：明确要求AI提供不同的观点或论据 ④批判性思考：对AI的输出保持警惕，交叉验证重要信息 |

### 陷阱4：幻觉生成——当AI自信地胡说八道

| 维度 | 内容 |
|------|------|
| **陷阱症状** | ①AI提供的具体数据或事实无法验证 输出中包含看似专业但实际上不存在的术语或概念 ③对未来或不确定事件做出过于具体的预测 |
| **应对策略** | ①明确不确定性：鼓励AI在不确定时明确说明 ②事实核查提示：要求AI区分已知事实和推测 ③多源验证：要求AI从多个角度或来源验证信息 ④要求引用：明确要求AI提供信息来源，便于验证 |

> **深度工具**：幻觉的系统性识别与防范，参见 `ai-content-quality` 技能中的"五类×七特交叉映射矩阵"和"七特快速检测清单"。

### 陷阱5：忽视伦理边界——低估AI的伦理限制

| 维度 | 内容 |
|------|------|
| **陷阱症状** | ①要求AI生成有争议、不道德或非法内容 ②对AI的拒绝或警告感到困惑或不满 尝试绕过AI的安全机制 ④忽视AI输出可能带来的伦理影响 |
| **应对策略** | ①了解界限：熟悉AI系统的基本伦理准则和限制 ②合法合规：确保你的请求符合法律和道德标准 ③伦理指南：在提示语中明确包含伦理考虑和指导原则 ④影响评估：要求AI评估其建议或输出的潜在社会影响 |

### 提示语设计检查清单

每次编写提示语前，快速过一遍：
- [ ] **目标明确性**：任务目标是否清晰？
- [ ] **信息充分性**：是否提供了足够的背景信息？
- [ ] **结构合理性**：输出格式要求是否明确？
- [ ] **语言中立性**：是否避免了偏见和预设立场？
- [ ] **难度适中**：任务难度是否匹配模型能力？
- [ ] **输出格式**：是否明确了期望的输出格式？
- [ ] **可验证性**：是否设计了验证输出质量的方法？
- [ ] **迭代空间**：是否预留了优化和改进的空间？
- [ ] **伦理合规性**：内容是否符合伦理标准？
- [ ] **多样性考虑**：是否考虑了多元视角？

## 八、从问题到落地：咨询师工作流

> 提示语设计的所有技巧，最终服务于一个目标——让AI成为合格的咨询师：根据实际情况给出建议，并推动落地。

这个工作流把本技能和 `prompt-chain-design`（诊断式引导）、`reasoning-model-strategy`（模型适配）串联成一个端到端的闭环：

```
用户带着问题来
       ↓
 ┌──────────────────┐
 │ 第1步：咨询师问诊  │ ← 不急着回答，先判断"问题定义清楚了吗？"
 │ （诊断式引导）     │   不清楚 → 用反向引导问题帮用户想清楚
 └────────┬─────────┘   （详见 prompt-chain-design 第八节）
          ↓
 ┌──────────────────┐
 │ 第2步：需求分类    │ ← 用户想清楚后，判断是哪类需求
 │ （五类需求识别）   │   决策/分析/创造/验证/执行？
 └────────┬─────────┘   （用"需求识别信号"表快速定位）
          ↓
 ┌──────────────────┐
 │ 第3步：选模型+策略 │ ← 根据需求类型选择模型和提示语策略
 │ （双模型适配）     │   推理模型→简洁聚焦 / 通用模型→结构化补偿
 └────────┬─────────┘   （用"填空模板"套用表达公式）
          ↓
 ┌──────────────────┐
 │ 第4步：执行+落地   │ ← AI输出不是终点，落地才是
 │ （可执行交付）     │   输出必须包含：结论+依据+下一步行动
 └────────┬─────────┘
          ↓
 ┌──────────────────┐
 │ 第5步：验证+迭代   │ ← 用七特清单扫描输出质量
 │ （质量闭环）       │   不满意 → 回到第1步重新诊断
 └──────────────────┘   （详见 ai-content-quality 七特检测清单）
```

### 咨询师原则的落地标准

一个"合格的咨询师"的每次输出，都应满足四个标准：

| 标准 | 含义 | 自检问题 |
|------|------|---------|
| **有针对性** | 基于用户的具体情况，而非泛泛而谈 | "这个回答换个名字还能用吗？"——如果能，说明不够具体 |
| **有依据** | 结论有数据/逻辑支撑，不是拍脑袋 | "关键结论能追溯到一个可靠来源吗？" |
| **可执行** | 给出明确的下一步行动，而非停留在分析 | "看完之后我知道该做什么吗？" |
| **有边界** | 明确说明适用范围和局限性 | "在什么条件下这个建议会失效？" |

### PM实战示例

**产品经理**："帮我分析一下竞品"

咨询师工作流执行过程：
1. **问诊**："你想分析竞品的哪些方面？功能对比、定价策略、用户体验还是市场定位？你最想通过竞品分析回答什么决策问题？"
2. **分类**：用户补充后判断——这是**决策需求**（最终要决定自己做不做某个功能）。
3. **选模型+策略**：用推理模型做对比分析，套用决策需求模板——填入评估标准（市场规模、开发成本、用户价值）。
4. **执行+落地**：输出不只是竞品对比表，而是"基于对比分析，建议优先做X功能，因为[依据]，下一步建议[具体行动]"。
5. **验证**：用七特清单检查——有没有虚构数据（特1）？是否过度自信（特2）？推理是否一致（特7）？

## 使用建议

1. **初学者**：从TASTE框架开始，确保每次提示语都包含五个要素。
2. **进阶者**：运用元素组合矩阵，有意识地搭配信息类/结构类/控制类元素。
3. **高手**：根据任务-模型-需求三维矩阵，动态调整策略组合。
4. **面对模糊需求时**：先走"咨询师工作流"五步——问诊→分类→选模型→执行→验证。不要跳过第1步（问诊），问题定义清楚就解决了80%。
5. **不确定需求类型时**：用"需求识别信号"表对照自己的内心状态，快速定位是哪类需求，再套用对应的填空模板。
6. **跨技能联动**：诊断式引导用 `prompt-chain-design` 第八节，模型选择用 `reasoning-model-strategy`，质量检测用 `ai-content-quality` 七特清单——本技能的咨询师工作流是串联这三个技能的"主线流程"。
