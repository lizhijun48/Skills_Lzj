# 表达净化工作流：四遍扫描

> 供 `general-suite/expression-purifier`（S-070）Step 2 使用。
> 原则：**四遍扫描分开走，每遍只查一类问题**。混在一起扫会漏，也会互相干扰。

---

## 扫描顺序

```
输入：成稿 + 文体判定
  ↓
第 1 遍  词表扫描（词汇层）
  ↓
第 2 遍  句式与结构扫描（句法层）
  ↓
第 3 遍  信息密度扫描（内容层）
  ↓
第 4 遍  朗读检查（节奏层）
  ↓
汇总 → 分级（必改/建议改/人工复核/保留）→ 输出净化报告
```

---

## 第 1 遍：词表扫描

**输入**：`references/ai-tone-wordlist.md`

**方法**：按表逐类比对，命中即记录「位置 + 原词 + 所属类别」。

**判定规则**：

| 情况 | 处置 |
|------|------|
| 词为纯形式，删掉不改变句意 | **必改** |
| 词承载实义（如"生态"实指某平台生态） | **保留**，记入保留说明 |
| 文体需要（营销文案的"颠覆性"是修辞） | **保留**，注明文体理由 |
| 命中「内部策略词」或「夸张词」类 | 对外文档一律 **必改**，无例外 |

**常见漏检**：同一套路词在全文重复出现（如"深度"出现 12 次）。因此第 1 遍必须**统计词频**，重复 3 次以上的套路词即使单次无害，也应整体降频。

---

## 第 2 遍：句式与结构扫描

对照 `ai-tone-wordlist.md` 第五、六节。

**方法**：不看词，只看**形状**。

**快速判据**：
- 把每段首句连起来读——若读起来像提纲、且句式雷同，说明结构机械
- 数段落字数——标准差过低即"机器均齐"
- 看标题——字数/结构完全一致即对称痕迹
- 找段尾——是否每段都有总结句

**处置优先级**：
1. 删元叙述（"本文将…"）
2. 删升华段
3. 打散排比三连
4. 打破段落等长
5. 减少列表，恢复段落叙述

---

## 第 3 遍：信息密度扫描

**方法**：逐段打勾。

| 检查项 | 通过标准 |
|--------|----------|
| 有具体数字 | 全篇含数字句子 ≥20%（技术/商务文档） |
| 有专有名词 | 每段至少一个明确主体 |
| 有时间锚点 | 涉及动作的句子应能回答"什么时候/多久一次" |
| 有因果 | 不只断言"重要"，要说明"影响什么" |
| 主语明确 | 抽掉主语后句子不成立 |

**低密度段落的两种处置**：
- 能补信息 → 补（首选）
- 补不出 → **整段删除**。凑字数比留白危害更大。

---

## 第 4 遍：朗读检查

**方法**：出声读一遍（或在脑中读）。

| 现象 | 说明 |
|------|------|
| 一口气读不完的长句 | 需拆句 |
| 读起来"太顺"、节奏均匀 | 需打破均齐，插入短句 |
| 读完记不住任何一句 | 信息密度不足，回第 3 遍 |
| 某句读着想跳过 | 多半是套话，直接删 |

---

## 分级规则汇总

| 等级 | 判定 | 处置 |
|------|------|------|
| **必改** | 纯形式套路 / 内部策略词 / 夸张词 / 元叙述 / 升华段 | 直接替换或删除 |
| **建议改** | 略套路但无害 | 给方案，供选择 |
| **人工复核** | 涉及事实、数据、专业判断、法律效力、对外承诺 | **只标不改** |
| **保留** | 承载实义或文体需要 | 注明理由 |

**人工复核的红线**：以下四类即使语言再啰嗦也不擅自改写——
1. 数字与单位
2. 法规/标准/条款引用
3. 权利义务与承诺性表述
4. 专业术语（可能看似黑话，实为行业标准用语）

```

**扫描范围**：<章节 · 约 X 字>

### 一、必改项（N 处）
| # | 位置 | 原句 | 问题类型 | 建议替换为 |
|---|------|------|----------|------------|

### 二、建议改（N 处）
（同表结构）

### 三、人工复核项（未改动，N 处）
| # | 位置 | 原句 | 需人工判断的原因 |

### 四、保留说明
| 位置 | 保留内容 | 理由 |
|------|----------|------|
| 2.1 | "生态" | 实指某具体平台生态，非泛称 |

### 五、密度检查
- 含数字句子占比：__%（阈值 ≥20%）
- 含专名句子占比：__%
- 段落长度标准差：__（过低提示机械均齐）
- 低密度段落：第 X、Y 段

### 六、净化后复核
- [ ] 逐项回读，确认无新歧义
- [ ] 数字、单位、条款引用未被改动
- [ ] 未因去 AI 味而丢失信息
```

## 与 pm-bid-proposal B23 的调用约定

`pm-suite/pm-bid-proposal`（JT-008）工作流中的 **B23「表达净化」步骤调用本技能**，约定如下：

1. 文体固定为「投标/公文」，净化强度=**强**
2. 在第 1 遍词表扫描中，内部策略词与夸张词部分**必改无例外**
3. 另须叠加 `pm-suite/pm-bid-proposal/references/forbidden_content.md` 的招投标专项红线
4. 输出填入 `references/bid-assistant-templates/review_report.md` 的 `{{ ai_tone_check }}` 与 `consistency_check_report.md` 的对应占位

> 词表只在本技能维护一份，pm-bid-proposal 通过引用复用，不另建副本（GOV v3.6 原则九·功能相近模块必须评估融合）。
