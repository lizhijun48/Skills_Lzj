# Skill架构治理原则（general-suite补充）

> 本文档定义general-suite Skill的架构治理原则，作为GOV_SkillGovernance.md的补充。
> 适用于从清华DeepSeek PDF提炼的所有Skill（S-026~S-039），以及后续新建的Skill。
> 状态：v0.2.0 (2026-08-09) 首次定义

## 原则一：质量检查点（Quality Checkpoints）

workflow-chains关键衔接点必须定义"交付标准"——上游Skill的输出必须满足什么条件，才能作为下游Skill的输入。

### 实施方式

每个Skill在"调用关系"章节中，明确定义：
- **输出标准**：本Skill的输出必须包含哪些要素，下游才能使用
- **验收条件**：调用方如何判断输出质量达标
- **回退机制**：输出不达标时，回到哪个环节修正

### 示例（品牌三模块）

```
brand-positioning → value-proposition 衔接标准：
  ✅ 品牌定位8组件全部填写完整
  ✅ 目标用户明确（非"所有用户"）
  ✅ 差异化理由通过"换成竞品名还成立吗"测试
  ❌ 未达标 → 回到brand-positioning补充，不进入value-proposition
```

## 原则二：动态路由（Dynamic Routing）

Skill内部增加条件分支和回环机制，而非线性执行。

### 实施方式

采用"诊断→选路→执行"模式的Skill，在诊断阶段根据输入条件动态选择执行路径：

```
用户输入
   ↓
诊断（2-3个问题判断场景）
   ↓
┌── 条件A → 路径A（模板A）
├── 条件B → 路径B（模板B）
└── 条件C → 路径C（模板C）
   ↓
执行 → 质量检查
   ↓
├── 达标 → 输出
└── 不达标 → 回环到诊断/执行阶段
```

### 当前落地状态

| Skill | 动态路由机制 | 路由维度 |
|-------|------------|---------|
| copywriting | 诊断式工作流：场景→模板选择 | 6种文案类型（产品/品牌/广告/社交/长文/邮件） |
| marketing-planning | 诊断式工作流：产品阶段+营销目标 | 预热期/上线期/成长期/成熟期 |
| brand-positioning | 战略层级分层：企业/产品线/单品 | 3个战略层级 |
| value-proposition | 战略层级分层 | 3个战略层级 |
| future-vision | 战略层级分层 | 3个战略层级 |
| prompt-engineering-basics | 咨询师工作流：需求识别→分类→选路 | 5类需求（决策/分析/创造/验证/执行） |
| prompt-chain-design | 诊断式引导：机制失效→反问→选路 | 7个机制匹配 |

## 原则三：Skill内部CIRS闭环

每个Skill内部应实现CIRS（Context→Instruction→Refinement→Synthesis）闭环，而非一次性输出。

### 实施方式

| CIRS环节 | 在Skill中的映射 | 说明 |
|---------|---------------|------|
| **Context** | 诊断阶段 | 通过反问获取上下文，确保理解用户真实需求 |
| **Instruction** | 选路+执行阶段 | 根据诊断结果选择模板/路径，执行生成 |
| **Refinement** | 质量检查阶段 | 用评估清单/矩阵检查输出质量 |
| **Synthesis** | 输出+调用关系 | 整合输出，声明与上下游Skill的衔接 |

### 当前落地状态

所有新建的6个Skill（S-034~S-039）均遵循CIRS闭环：
- Context = 诊断引导问题（每个Skill都有"诊断问题"章节）
- Instruction = 模板+执行流程（每个Skill都有模板和步骤）
- Refinement = 评估标准/检查清单（每个Skill都有评估标准）
- Synthesis = 调用关系声明（每个Skill末尾都有"调用关系"章节）

## 原则四：MECE原则（相互独立、完全穷尽）

任务分解和分类必须满足MECE——子项之间不重叠（Mutually Exclusive），所有子项之和等于父任务100%（Collectively Exhaustive）。

### 实施方式

在Skill中涉及"分解""分类""拆分"的地方，必须检查MECE：

| 检查维度 | 检查问题 | 常见问题 |
|---------|---------|---------|
| **相互独立** | 任意两个子项之间是否有交叉？ | 分类标准不统一导致重叠 |
| **完全穷尽** | 所有子项之和是否覆盖全部情况？ | 遗漏了"其他"或边界情况 |
| **100%规则** | 子项之和是否恰好等于父任务？ | 多出无关项或缺少关键项 |

### 当前落地状态

| Skill | MECE应用点 | 状态 |
|-------|----------|------|
| prompt-chain-design | SPECTRA第1步要求"满足MECE原则——相互独立、完全穷尽" | 已落地 |
| prompt-chain-design | 任务分解七步骤中"识别主要任务"要求3-5个核心组成部分互斥穷尽 | 已落地 |
| copywriting | 六大文案模板覆盖所有常见PM文案场景（产品/品牌/广告/社交/长文/邮件） | 已落地 |
| ai-content-quality | 五类幻觉模型（数据误用/语境误解/信息缺失/推理错误/无中生有）互斥穷尽 | 已落地 |
| creative-prompt-techniques | 九大框架覆盖发散/聚合/跨界/映射/嫁接/极端/约束/迁移/随机 | 已落地 |

## 原则五：WBS优化（渐进复杂性+100%规则）

将WBS（工作分解结构）的项目管理思想应用到Skill的任务分解中。

### 实施方式

| WBS原则 | 在Skill中的应用 |
|---------|---------------|
| **渐进复杂性** | 任务分解从粗到细，先识别主要组成部分，再逐层细化到可执行的微任务 |
| **100%规则** | 子任务之和 = 父任务100%，不多不少 |
| **可交付物导向** | 每个分解后的子任务都有明确的交付物（而非"了解""研究"等模糊动作） |
| **层级控制** | 分解层级不超过3-4层，过深则说明粒度不够或分类不当 |

### 与提示语链的等价性

WBS分解"交付物"与提示语链分解"认知步骤"本质相同——都是分而治之。

| WBS概念 | 提示语链等价概念 | 对应Skill |
|---------|---------------|----------|
| 项目总目标 | 提示语链的最终输出目标 | prompt-chain-design |
| 工作包 | 单个提示语的执行步骤 | prompt-chain-design（CIRS） |
| WBS字典 | 每个提示语的设计要点 | prompt-chain-design（SPECTRA七步技巧） |
| 依赖关系 | 提示语之间的逻辑衔接 | prompt-chain-design（机制1+6） |
| 里程碑 | 质量检查点 | prompt-chain-design（机制5） |

### 当前落地状态

| Skill | WBS应用点 | 状态 |
|-------|----------|------|
| prompt-chain-design | SPECTRA模型（7步分解）+ 任务分解七步骤 + PM实战案例 | 已落地 |
| prompt-chain-design | AIDA框架（4阶段，每阶段有明确交付物） | 已落地 |
| marketing-planning | 三模块分解（创意概念→传播策略→执行方案），每模块有独立交付物 | 已落地 |
