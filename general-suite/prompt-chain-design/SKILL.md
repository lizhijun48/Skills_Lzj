# 提示语链设计 (Prompt Chain Design)

基于清华大学《DeepSeek：从入门到精通》提炼的提示语链设计方法论与实操框架。

## 核心原则

- **分而治之**：将复杂任务分解为多个可操作的子任务，逐步引导AI完成。
- **逻辑连贯**：提示语之间存在清晰的逻辑关系，形成连贯的思维链条。
- **渐进复杂**：从简单到复杂逐步推进，控制每个步骤的认知负荷。
- **反馈闭环**：每个步骤完成后进行评估和调整，确保最终输出质量。

## 一、提示语链的概念

提示语链是用于引导AI生成内容的连续性提示语序列。本质上是一种"元提示"(meta-prompt)策略，不仅告诉AI"做什么"，更指导AI"如何做"。

### 七大作用机制与实战技巧

提示语链通过七个机制系统性地引导AI生成高质量内容。每个机制不仅是"如何设计提示语链"的操作指南，更映射了用户自身需要具备的结构化思维能力。

#### 机制1：任务分解与整合

将复杂主题分解为子任务，逐一处理后综合为整体。

**实战技巧**：
1. 将复杂主题分解为几个主要部分，逐一讨论每个部分
2. 对每个子任务设定具体目标和预期成果
3. 每个子任务完成后，总结关键点并与整体主题关联
4. 通过层次结构图或思维导图展示分解后的各部分及其关系
5. 结合各部分结果，撰写总结性内容，确保整体连贯

#### 机制2：知识激活与联想

列出关键知识点，建立跨领域联想，将复杂概念与日常经验联系。

**实战技巧**：
1. 列出与主题相关的所有关键知识点，逐一详细解释
2. 从不同领域中寻找与问题相关的知识点，进行创造性联想
3. 通过比喻或类比，将复杂概念与日常经验联系起来
4. 使用头脑风暴技术，生成多个可能的联想和创新点
5. 将联想到的新观点或概念整合进现有知识体系

#### 机制3：思维框架构建

按照"问题定义→信息收集→分析综合→结论形成"的路径构建完整思维链。

**实战技巧**：
1. 明确问题的核心要点，系统收集相关信息进行分析
2. 列出与主题相关的所有关键概念和理论，进行系统梳理
3. 使用逻辑框架图展示信息收集、分析和结论的过程
4. 针对每个关键概念撰写简要解释并说明其在文章中的作用
5. 通过案例分析或实例应用，验证思维框架的有效性和适用性

#### 机制4：创意引导与拓展

多角度激发创新思维，挑战常规观点，探索非常规解决路径。

**实战技巧**：
1. 从全新角度重新思考问题，提出与众不同的见解
2. 将其他领域看似不相关的概念结合起来，探索跨界应用
3. 设定全新情境，讨论在此情境下问题会有怎样的发展
4. 挑战现有常规观点，从反面角度思考并提出新的可能性
5. 结合不同学科的理论，提出创新解决方案
6. 从结果出发倒推原因和过程，探索新的解决途径

#### 机制5：质量控制与优化

每步完成后自我评估和质量检查，设立检查点。

**实战技巧**：
1. 每个步骤完成后进行自我评估和质量检查
2. 使用清单核对每个部分是否满足预期目标和质量标准
3. 设立中期检查点，对任务进度和质量进行评估和调整
4. 请求同行或专家对内容进行审阅并提供反馈
5. 根据反馈意见逐步优化和完善各个部分

#### 机制6：反馈整合与动态调整

根据反馈逐步修改和完善，动态调整后续提示语方向。

**实战技巧**：
1. 对当前内容评估优缺点，提出具体改进建议
2. 根据前一阶段反馈逐步修改完善，列出具体修改步骤
3. 根据生成过程中出现的新问题动态调整后续提示语，解释调整原因
4. 收集多方反馈综合考虑，列出不同来源反馈及其对内容的影响
5. 定期检查各部分内容协调一致，列出检查方法和步骤
6. 将新信息和反馈整合到已有内容中，描述整合步骤和方法

#### 机制7：多模态信息处理

融合文本、数据、可视化等多种形式，增强内容丰富性。

**实战技巧**：
1. 将文本描述与数据结合，生成全面的分析报告
2. 创建包含图像和数据可视化的报告，描述可视化方法
3. 设计融合文本、图像、音频或视频元素的多媒体内容
4. 设计互动数据展示方案，使读者可以与数据进行互动
5. 将不同媒体形式的内容联动展示（文字+图像+数据可视化）
6. 选用合适的数据可视化工具，描述使用方法并生成可视化内容
7. 将具体案例与数据分析结合，生成包含案例分析的多模态报告

### 反向诊断：从提示链效果看思维短板

> **核心理念**：提示语链的效果是用户结构化思维水平的"镜像"。输出质量不佳时，问题往往不在AI，而在用户的输入端——你对任务是否有足够清晰的认知，决定了你能输入什么、以及能否判断输出结果。

七大机制不仅是"怎么用"的操作指南，更是"哪里没想清楚"的诊断工具。当提示链效果不理想时，对照下表定位自身的思维盲区：

| 机制 | 提示链失效信号 | 映射的思维短板 | 反向引导问题 |
|------|-------------|-------------|------------|
| 1.任务分解与整合 | AI输出混乱、遗漏关键部分、各部分不连贯 | **目标拆解能力不足**：没有想清楚整体由哪些部分组成 | "你能否用一句话定义最终目标？能否列出3-5个核心组成部分？" |
| 2.知识激活与联想 | AI输出缺乏深度、浮于表面、缺少专业视角 | **领域认知不足**：对该领域的关键概念和知识版图不够清晰 | "这个任务涉及哪些核心概念？你能列出5个以上关键知识点吗？" |
| 3.思维框架构建 | AI回答逻辑跳跃、结论与论据脱节、论证不完整 | **逻辑结构能力不足**：没有想清楚从问题到结论的推理路径 | "从问题到结论，你的推理路径是什么？每一步的依据是什么？" |
| 4.创意引导与拓展 | AI输出平庸、缺乏新意、重复常见观点 | **思维定式**：被既有框架限制，没有意识到需要突破的边界 | "你期望的创新点是什么？有没有尝试从反面或跨界角度思考？" |
| 5.质量控制与优化 | AI输出质量波动大、错误未被纠正、越改越偏 | **标准模糊**：没有明确的验收标准，不知道"好"长什么样 | "你对'好输出'的定义是什么？有哪些可量化的质量标准？" |
| 6.反馈整合与调整 | AI反复修改但方向混乱、越改越偏离主题 | **反馈表达能力不足**：无法精确描述"哪里不对、应该怎样" | "你能具体指出哪里不满意吗？是方向问题还是细节问题？" |
| 7.多模态信息处理 | AI输出形式单一、数据与文字脱节、可视化不当 | **表达形式认知不足**：没有想清楚什么信息适合什么呈现形式 | "这些数据用图表还是文字更直观？不同信息之间是什么关系？" |

**使用方法**：当AI输出不理想时，不要急于修改提示语措辞，先对照上表问自己三个问题：
1. **哪个机制失效了？**（看"失效信号"列）
2. **我的思维在哪里断了？**（看"思维短板"列）
3. **我能否回答这个引导问题？**（看"反向引导问题"列）

回答完这三个问题再调整提示语，往往比反复修改措辞更有效——因为你调整的不是"怎么说"，而是"怎么想"。

## 二、六大设计原则

| 原则 | 说明 |
|------|------|
| 01 目标明确性 | 每个提示语都服务于清晰的子目标 |
| 02 逻辑连贯性 | 提示语之间自然过渡，形成思维链 |
| 03 渐进复杂性 | 从简单到复杂，逐步增加难度 |
| 04 灵活适应性 | 模块化设计，易于调整和重用 |
| 05 多样性思考 | 引导AI从多个角度思考问题 |
| 06 反馈整合机制 | 内置检查点，支持动态调整 |

## 三、CIRS设计模型

提示语链设计的四个关键环节：

```
Context（上下文）→ Instruction（指令）→ Refinement（优化）→ Synthesis（综合）
     提供背景信息        给出具体指示        修改完善初步输出      整合形成最终成果
```

### 实施要点

**Context阶段**：
- 提供任务概述和背景信息
- 明确相关约束和前提条件
- 设定角色和语境

**Instruction阶段**：
- 给出清晰、具体的任务指令
- 明确期望的输出格式和标准
- 提供必要的参考信息

**Refinement阶段**：
- 对初步输出进行评估
- 指出需要改进的具体方面
- 引导AI进行自我修正

**Synthesis阶段**：
- 整合所有子任务的输出
- 确保整体连贯性和一致性
- 形成最终交付成果

## 四、SPECTRA任务分解模型

Systematic Partitioning for Enhanced Cognitive Task Resolution in AI

为了更有效地进行任务分解，采用SPECTRA模型将复杂任务系统性地拆解为可执行的子任务序列。

### 模型总览

| 步骤 | 英文 | 操作 | 核心问题 |
|------|------|------|---------|
| S | Segmentation（分割） | 将大任务分为独立但相关的部分 | "这件事由哪几部分组成？" |
| P | Prioritization（优先级） | 确定子任务的重要性和执行顺序 | "先做哪个、后做哪个？" |
| E | Elaboration（细化） | 深入探讨每个子任务的细节 | "每个部分具体要做什么？" |
| C | Connection（连接） | 建立子任务之间的逻辑关联 | "各部分之间怎么衔接？" |
| T | Temporal Arrangement（时序安排） | 考虑任务的时间维度 | "每个部分需要多少时间？" |
| R | Resource Allocation（资源分配） | 为每个子任务分配适当的注意力资源 | "哪个部分最需要集中精力？" |
| A | Adaptation（适应） | 根据AI反馈动态调整任务结构 | "做完一步后，后续计划要改吗？" |

### 七步提示语设计技巧

每一步对应一个专门的提示语，串联起来就构成一条完整的任务分解链：

**第1步 · 分割提示**：
> "将[总任务描述]分解为3-5个主要组成部分，确保每个部分都是相对独立但与整体目标相关的。"

设计要点：要求AI输出的每个部分必须满足MECE原则——相互独立（不重叠）、完全穷尽（不遗漏）。如果AI分解出的部分有交叉，追问"这几个部分之间是否有重叠？请重新划分确保互斥。"

**第2步 · 优先级提示**：
> "对上述分解的任务进行优先级排序，考虑它们对总体目标的重要性和逻辑顺序。"

设计要点：要求AI给出排序理由，而不只是列一个序号。好的输出应该说明"为什么A排在B前面"——是因为依赖关系、还是因为重要性、还是因为时间紧迫性。

**第3步 · 细化提示**：
> "选择优先级最高的子任务，将其进一步细化为2-3个具体的行动项或小目标。"

设计要点：对每个高优先级子任务都执行一次细化。细化后的行动项应该是"可执行的"——看到就知道该做什么，而不是还需要再猜。

**第4步 · 连接提示**：
> "分析各个子任务之间的关系，确定它们如何相互支持和影响，以及如何共同推进总体目标的实现。"

设计要点：这一步的关键产出是"依赖图"——哪些任务可以并行、哪些必须串行、哪个任务是瓶颈。如果AI只是泛泛说"它们相互关联"，追问"具体来说，A的输出是B的输入吗？哪些任务可以同时进行？"

**第5步 · 时序提示**：
> "为每个子任务制定一个粗略的时间表，考虑它们的依赖关系和完成所需的相对时间。"

设计要点：不需要精确到小时，但需要"相对时间"——哪个任务耗时最长、哪个是快速能完成的。这帮助判断整体节奏和关键路径。

**第6步 · 资源分配提示**：
> "评估每个子任务的复杂度，分配1-10的'注意力分数'，指导在执行过程中如何分配精力和计算资源。"

设计要点：注意力分数高的任务，在后续执行时应该投入更多轮对话、更详细的提示语、更严格的质量检查。分数低的任务可以简化处理。

**第7步 · 适应提示**：
> "在执行每个子任务后，评估其输出质量和对总体目标的贡献，必要时调整后续任务的优先级或内容。"

设计要点：这是SPECTRA的"闭环机制"——不是拆完就僵化执行，而是每完成一步都回头审视：原来的分解还合理吗？需要调整后续计划吗？

### 实战案例：用SPECTRA分解"编写产品上线方案"

**总任务**：编写一份SaaS产品上线方案

**S（分割）**：
> "将'编写SaaS产品上线方案'分解为主要组成部分。"

AI输出：①上线目标与成功标准 ②技术准备（部署/测试/回滚） ③运营准备（定价/渠道/物料） ④用户迁移方案 ⑤风险预案

**P（优先级）**：
> "对上述5个部分进行优先级排序。"

AI输出：①上线目标与成功标准（优先级最高——决定其他所有部分的方向）→ ②技术准备 → ③风险预案 → ④运营准备 → ⑤用户迁移方案

**E（细化）**：
> "将'上线目标与成功标准'细化为具体行动项。"

AI输出：a. 定义上线核心指标（DAU/转化率/收入目标） b. 设定上线后7天/30天/90天的阶段性里程碑 c. 明确"上线成功"和"需要回滚"的判断标准

**C（连接）**：
> "分析5个部分之间的依赖关系。"

AI输出：目标与成功标准 → 决定技术准备的测试标准 → 决定风险预案的触发条件 → 影响运营准备的推广节奏。用户迁移方案依赖技术准备中的部署完成。①②可并行准备，③④⑤需等①②基本确定后启动。

**T（时序）**：
> "制定粗略时间表。"

AI输出：第1周完成①②（目标+技术），第2周完成③④（运营+迁移），贯穿全程迭代⑤（风险预案）。上线前3天做全流程演练。

**R（资源分配）**：
> "评估复杂度，分配注意力分数。"

AI输出：①目标定义=8（决定全局方向）、②技术准备=9（出错代价最高）、③运营准备=5、④用户迁移=7（直接影响用户体验）、⑤风险预案=6

→ 执行建议：②技术准备投入最多精力（9分），用多轮对话反复验证；③运营准备可简化处理（5分），用模板快速生成。

**A（适应）**：
> 假设执行①后发现"成功标准"难以量化——
> 调整：回到①补充"可量化指标定义"，同时推迟②③④⑤直到①明确后再启动。原计划的并行策略改为串行。

## 五、任务分解七步骤

```
明确总体目标 → 识别主要任务 → 细化子任务 → 定义微任务 → 设计对应提示语 → 建立任务间联系 → 加入反馈调整机制
```

### 操作步骤

1. **明确总体目标**：用一句话定义最终要达成的结果
2. **识别主要任务**：拆解出3-5个核心组成部分
3. **细化子任务**：每个主要任务再分解为2-3个具体行动项
4. **定义微任务**：将子任务细化到可独立执行的最小单元
5. **设计对应提示语**：为每个微任务编写专门的提示语
6. **建立任务间联系**：明确各步骤之间的依赖和衔接关系
7. **加入反馈调整机制**：在关键节点设置检查点和修正指令

## 六、三链融合优化系统

高质量提示语链需要整合三条核心链条：

### 逻辑链 (Logic Chain)
- 确保推理的严密性和论证的连贯性
- 应用形式逻辑原理
- 构建论证结构图
- 使用逻辑关系词强化连接

### 知识链 (Knowledge Chain)
- 激活和应用相关领域知识
- 构建多层次知识图谱
- 实施知识检索与集成
- 进行跨域知识映射

### 创意链 (Creativity Chain)
- 促进创新思维和独特见解
- 应用创造性思维技巧
- 实施概念重组与融合
- 进行情境转换与类比

### 为什么要三链融合？——好处分析

单独使用任何一条链，都会产生"偏科"问题：

| 只用单链 | 优势 | 典型缺陷 |
|---------|------|---------|
| 只用逻辑链 | 论证严密、结构清晰 | 内容干瘪、缺乏新意、像教科书 |
| 只用知识链 | 信息丰富、专业度高 | 堆砌知识、缺乏洞察、像资料汇编 |
| 只用创意链 | 想法新颖、角度独特 | 缺乏论证、难以落地、像头脑风暴记录 |

三链融合的好处：**逻辑链保证"说得通"，知识链保证"说得对"，创意链保证"说得新"**。三者协同，输出的内容既有说服力、又有深度、还有差异化价值。

### 融合策略
- **交叉强化**：利用一个链条的强点补强另一个链条的弱点
- **整合检查点**：定期综合评估输出的逻辑性、知识深度和创新度
- **平衡评估器**：实时评估三链的贡献度，确保均衡发展
- **适应性切换**：根据任务需求动态切换侧重点

### 8维度评估框架

每次完成提示链设计后，用以下8个维度评估三链的融合质量：

| 维度 | 评估问题 | 所属链条 | 评分标准（1-5） |
|------|---------|---------|--------------|
| 1. 论证严密性 | 结论是否有充分论据支撑？有无逻辑跳跃？ | 逻辑链 | 1=完全无论证 3=基本通顺有小漏洞 5=论证严密无懈可击 |
| 2. 结构连贯性 | 各部分之间过渡是否自然？读者能否顺畅跟随？ | 逻辑链 | 1=结构混乱 3=基本连贯有断裂 5=行云流水 |
| 3. 知识准确性 | 引用的数据、概念、理论是否准确？ | 知识链 | 1=大量错误 3=基本正确有小瑕疵 5=完全准确且来源可靠 |
| 4. 知识深度 | 是否触及问题的本质？还是停留在表面？ | 知识链 | 1=完全表面 3=有一定深度 5=深入本质有独到见解 |
| 5. 知识广度 | 是否整合了多个相关领域的知识？ | 知识链 | 1=单一视角 3=涉及2-3个视角 5=跨领域整合 |
| 6. 原创性 | 是否提出了新颖的观点或解决方案？ | 创意链 | 1=完全老套 3=有一定新意 5=突破性创新 |
| 7. 实用性 | 输出的方案是否可落地执行？ | 创意链+逻辑链 | 1=完全不可操作 3=有方向缺细节 5=可直接执行 |
| 8. 表达感染力 | 内容是否吸引人？读者是否愿意读下去？ | 创意链+知识链 | 1=枯燥乏味 3=可读但无亮点 5=引人入胜 |

**使用方法**：逐项打分后，找出得分最低的1-2个维度，针对性补强。例如：
- 维度6（原创性）得分低 → 加入创意链技巧（BRIDGE跨界、EHS极端假设）
- 维度1（论证严密性）得分低 → 加强逻辑链（构建论证结构图、补充推理步骤）
- 维度4（知识深度）得分低 → 激活知识链（补充领域知识、引入专业理论）

### PM场景案例：用三链融合写"智能硬件产品立项报告"

**任务**：产品经理需要撰写一份智能门锁的产品立项报告，提交给管理层审批。

**逻辑链应用**（保证"说得通"）：
```
论证结构：
市场机会（TAM/SAM/SOM）→ 用户需求验证（调研数据）→ 产品方案（功能定义）
→ 技术可行性 → 财务模型（ROI）→ 风险评估 → 立项建议

每个环节必须有数据支撑，环节之间用"因为…所以…"连接。
```

**知识链应用**（保证"说得对"）：
```
需要激活的知识领域：
- 智能门锁市场规模和增长率（行业数据）
- 用户痛点：忘带钥匙、远程开锁、安全焦虑（用户调研）
- 技术方案：指纹/人脸/密码/NFC各方案的优劣对比
- 竞品分析：小米/鹿客/凯迪仕的定价和市场份额
- 供应链：主要元器件成本和供应商格局
```

**创意链应用**（保证"说得新"）：
```
差异化创新点（用IDEA框架发散）：
- I: 如果门锁不只是"开门工具"，而是"家庭安全入口"？
- D: 从安防视角、家居联动视角、社区服务视角分别思考
- E: 结合AI异常行为检测（如老人长时间未出门自动报警）
- A: 替代方案——不卖硬件，卖"家庭安全服务"订阅模式

用FOCUS框架筛选：选择"AI异常行为检测+家庭安全服务"作为差异化方向
```

**三链融合效果**：
- 逻辑链确保立项报告的论证链条完整（市场→需求→方案→财务→风险→建议）
- 知识链确保每个环节有扎实的数据和专业分析支撑
- 创意链确保方案不是"又一个智能门锁"，而是有差异化的创新定位

## 七、AIDA四步提示语链框架

适用于文章/报告类内容生成：

| 阶段 | 功能 | 操作要点 |
|------|------|---------|
| Analysis（分析） | 明确任务目标和关键问题 | 收集信息、识别核心议题 |
| Ideation（构思） | 创新性思维，探索多种方案 | 多角度思考、头脑风暴 |
| Development（发展） | 逐步深化构思形成具体方案 | 分步展开、细节填充 |
| Assessment（评估） | 反思和优化，确保符合标准 | 质量检查、迭代改进 |

### 考虑因素

使用AIDA框架时需要注意以下关键因素，直接影响提示链的效果：

| 因素 | 说明 | 常见误区 |
|------|------|---------|
| **任务适配性** | AIDA适合结构化内容（报告、文章、方案），不适合创意发散或简单问答 | 用AIDA写诗歌→结构过重；用AIDA回答事实问题→步骤冗余 |
| **Analysis深度** | 分析阶段的深度决定了后续所有步骤的质量上限 | 急于跳到构思，分析阶段草草了事→后续方向跑偏 |
| **Ideation开放性** | 构思阶段应鼓励发散，不要过早收敛 | 构思阶段只给1-2个选项就进入发展→选择空间不足 |
| **Development节奏** | 发展阶段要控制粒度，太粗则空洞，太细则碎片化 | 每个子点展开过多→文章臃肿；展开过少→缺乏说服力 |
| **Assessment标准** | 评估阶段需要有明确的验收标准，不能只说"再优化一下" | 没有标准就反复修改→越改越偏，陷入无限循环 |
| **步骤间衔接** | 每个阶段的输出是下一阶段的输入，需要明确传递 | 阶段之间断裂→分析阶段的结论没有传递到构思阶段 |

### 执行技巧

**技巧1：Analysis阶段用"5W1H"确保全面**
```
请用5W1H框架分析以下任务：
- What：任务的核心是什么？
- Who：目标受众是谁？
- Why：为什么要做这件事？期望达到什么效果？
- Where：内容将在什么场景/平台使用？
- When：时间约束是什么？
- How：有哪些资源/限制条件？
```

**技巧2：Ideation阶段强制"至少3个方向"**
```
基于以上分析，请提出至少3个不同方向的方案：
- 方向A：保守稳妥型（最小风险）
- 方向B：创新突破型（最大差异化）
- 方向C：平衡兼顾型（风险与创新的折中）
每个方向用2-3句话描述核心思路。
```

**技巧3：Development阶段用"骨架→血肉"两步法**
```
第一步（骨架）：为方向B列出文章大纲（标题+每段核心论点）
第二步（血肉）：逐段展开，每段包含：
  - 1个核心论点
  - 1个数据/案例支撑
  - 1句过渡到下一段
```

**技巧4：Assessment阶段用"三维度检查表"**
```
请从以下三个维度评估当前内容：
1. 逻辑性（1-10分）：论证是否严密？有无逻辑跳跃？
2. 完整性（1-10分）：是否覆盖了Analysis阶段的所有关键问题？
3. 可读性（1-10分）：目标受众能否顺畅理解？

对低于7分的维度，指出具体问题并给出修改建议。
```

### 提示语链的优势与挑战

| 类别 | 优势 | 挑战 |
|------|------|------|
| 结构化思维 | 引导AI按照预设逻辑进行创作 | 设计合理的逻辑结构需要经验和技巧 |
| 内容深度 | 通过多步引导，实现更深入的内容探讨 | 控制每个步骤的输出深度，避免冗余 |
| 创意激发 | 多角度提示激发AI的创造性思维 | 在创意和连贯之间找到平衡 |
| 质量控制 | 多次迭代提高内容质量 | 需要更多的实践和计算资源 |
| 灵活调整 | 可根据中间结果随时调整后续提示 | 实时调整需要较高的判断和决策能力 |

> 注意：挑战列中的每一项，恰恰对应反向诊断矩阵中的"思维短板"——这些挑战本质上是对用户自身能力的要求，而非AI的局限。

## 八、诊断式引导工作流（事前干预模式）

> "能够很好地将问题描述出来，那么这个问题就解决了80%。"

反向诊断矩阵是"事后复盘"——输出不理想时回头找原因。诊断式引导则是"事前干预"——在用户提出问题的第一时间，主动引导用户把问题想清楚、说明白。这对产品经理/项目经理尤为关键：他们的核心价值就是定义问题，而非仅仅解决问题。

### 工作流程

```
用户提出问题/需求
       ↓
  ┌─────────────┐
  │ 诊断：缺了什么？│ ← 对照7个机制，扫描用户输入的信息完整度
  └──────┬──────┘
         ↓
  ┌─────────────┐
  │ 反问：引导补全 │ ← 选择最薄弱的1-2个机制，提出针对性问题
  └──────┬──────┘
         ↓
  用户补充信息（认知升级后的输入）
         ↓
  ┌─────────────┐
  │ 选路：匹配机制 │ ← 根据问题性质+已有信息，选择最合适的机制执行
  └──────┬──────┘
         ↓
  以选定机制为主线，启动提示语链执行
```

### 诊断引导表：7个机制的反问策略

当用户提出问题时，对照下表判断"用户的输入缺了什么"，然后选择最薄弱的环节进行反问引导：

| 机制 | 用户输入的信号（缺了什么） | 反问引导（帮用户想清楚） | 引导后选路（匹配执行机制） |
|------|------------------------|----------------------|------------------------|
| **1.任务分解** | 问题很大很笼统，如"帮我做个方案""分析一下市场" | "这个任务如果要分3-5个部分来做，你会怎么分？每个部分的核心交付物是什么？" | → 用SPECTRA模型分解任务，逐步执行 |
| **2.知识激活** | 缺少领域背景、关键概念、行业术语，如"帮我优化一下这个流程" | "这个流程涉及哪些关键环节？目前最大的痛点在哪个节点？有没有参考标杆？" | → 先构建领域知识框架，再深入分析 |
| **3.思维框架** | 有目标但路径不清，如"我想提升用户留存"但不知道从哪入手 | "你目前掌握了哪些数据？从问题到结论，你觉得可能的推理路径是什么？" | → 用CIRS模型构建"问题定义→信息收集→分析→结论"链路 |
| **4.创意拓展** | 已有基本方案但缺乏创新，如"这个方案太普通了" | "你期望的差异化在哪里？有没有尝试从用户视角/竞品视角/技术视角分别思考？" | → 用IDEA/BRIDGE框架激发跨界创意 |
| **5.质量控制** | 没有明确验收标准，如"帮我写个报告"但不知道什么样的报告算好 | "这个报告给谁看？他们最关心什么？你觉得'好报告'的标准是什么？" | → 先建立质量检查清单，再执行生成 |
| **6.反馈整合** | 已有迭代但方向混乱，如"改了好几版都不满意" | "前面几版具体哪里不满意？是方向问题（不该做这个）还是细节问题（做得不够好）？" | → 用反馈整合机制，明确修改方向后集中优化 |
| **7.多模态处理** | 信息呈现形式不当，如"数据很多但看不懂" | "这些数据之间的关系是什么？用趋势图、对比表还是流程图更直观？受众是谁？" | → 用chart-diagram-generator选择合适可视化方式 |

### 诊断原则

1. **一次只问1-2个最关键的问题**：不要一次性抛出7个问题，那会让用户更迷茫。找到当前最薄弱的环节，精准反问。
2. **用用户的语言反问**：不要说"你的任务分解不够"，而是说"如果要分几步来做，你会怎么分？"
3. **引导而非替代**：目标是帮用户自己想清楚，而不是替用户做决定。好的反问让用户"顿悟"，而不是"被教育"。
4. **识别问题类型，快速选路**：
   - 定义类问题（"这是什么"）→ 机制2+3（知识激活+思维框架）
   - 决策类问题（"该选哪个"）→ 机制1+5（任务分解+质量控制）
   - 创造类问题（"怎么做出新东西"）→ 机制4+7（创意拓展+多模态）
   - 优化类问题（"怎么做得更好"）→ 机制6+5（反馈整合+质量控制）

### PM/产品经理实战场景示例

**场景1**：产品经理说"帮我分析一下竞品"

诊断：机制1（任务分解）缺失——"分析竞品"太笼统。
反问："你想分析竞品的哪些方面？是功能对比、定价策略、用户体验，还是市场定位？你最想通过竞品分析回答什么问题？"
→ 用户补充后，选路机制1+3，分解为具体分析维度，构建分析框架。

**场景2**：项目经理说"帮我写个风险应对方案"

诊断：机制2（知识激活）+机制5（质量控制）缺失——不知道项目背景和验收标准。
反问："这个项目的主要风险点你已经识别了哪些？这个方案是给团队内部用还是给领导汇报？"
→ 用户补充后，选路机制2+5，先激活项目知识，再按受众需求建立方案标准。

**场景3**：产品经理说"这个需求文档AI写得太泛了"

诊断：机制6（反馈整合）缺失——无法精确表达"哪里不对"。
反问："具体来说，是需求范围定义得不对（方向问题），还是用户故事写得不够细（细节问题），还是验收标准缺失（结构问题）？"
→ 用户定位后，选路机制6，针对性修改具体部分。

## 使用建议

1. **简单任务**（1-2步即可完成）：无需提示语链，直接使用单个提示语。
2. **中等任务**（3-5步）：使用CIRS模型，确保上下文→指令→优化→综合完整闭环。
3. **复杂任务**（5步以上）：使用SPECTRA模型进行系统分解，配合三链融合确保质量。
4. **创意任务**：在提示语链中融入发散思维（IDEA框架）和聚合思维（FOCUS框架）的交替环节。
5. **输出不理想时**：先不要改措辞——用"反向诊断矩阵"定位是哪个机制失效，再对照"反向引导问题"检查自己的思维是否到位。调整"怎么想"比调整"怎么说"更有效。
6. **与幻觉防范联动**：提示链的机制1-3主要防范"语境误解"和"信息缺失"，机制4防范"数据缺乏/过拟合"，机制5-6防范"推理不一致"，机制7防范"指令模糊"。详见 `ai-content-quality` 技能的五类×七特映射矩阵。
7. **面对模糊需求时**：不要急着执行——先用"诊断式引导工作流"（第八节），判断用户输入缺了什么，用1-2个精准反问帮用户把问题想清楚，再选路执行。记住：问题定义清楚了，就已经解决了80%。
