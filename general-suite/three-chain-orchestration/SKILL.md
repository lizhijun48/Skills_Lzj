# 三链平衡编排 (Three-Chain Orchestration)

这是一个**元Skill**——不直接生成内容，而是诊断其他Skill/输出的质量短板，然后调用对应Skill补强。本质是跨Skill的质量保障编排层。

## 核心原则

- **三链均衡**：高质量输出需要逻辑链（说得通）、知识链（说得对）、创意链（说得新）三者协同。任何一条链弱，输出就"偏科"。
- **诊断先行**：不急于修改，先诊断哪条链弱、弱在哪里。
- **精准调用**：诊断结果直接映射到对应Skill，不盲目调用所有Skill。
- **闭环验证**：补强后重新评估，确保三链达到均衡。

## 一、三链诊断模型

### 诊断矩阵

收到AI输出（或任何待评估内容）后，用以下9个信号判断哪条链出了问题：

| 链条 | 弱信号（出现这些说明该链弱） | 强信号（出现这些说明该链强） |
|------|--------------------------|--------------------------|
| **逻辑链** | 论证跳跃、前后矛盾、结构混乱、因果关系不清、结论与论据脱节 | 论证严密、结构清晰、过渡自然、因果明确、自洽无矛盾 |
| **知识链** | 信息空洞、缺乏数据、概念错误、视角单一、浮于表面 | 数据丰富、引用准确、多视角、有深度、专业性强 |
| **创意链** | 内容平庸、缺乏新意、重复常见观点、没有差异化、像模板 | 观点新颖、角度独特、有洞察力、差异化明显、让人眼前一亮 |

### 快速诊断流程

```
收到AI输出
    ↓
逐项扫描9个弱信号
    ↓
统计每条链的弱信号数量
    ↓
弱信号最多的链 = 最短板
    ↓
调用对应Skill补强
```

**诊断规则**：
- 逻辑链弱信号 ≥ 2个 → 逻辑链偏弱
- 知识链弱信号 ≥ 2个 → 知识链偏弱
- 创意链弱信号 ≥ 2个 → 创意链偏弱
- 多条链同时偏弱 → 按弱信号数量排序，先补最弱的

## 二、补强调用映射

### 逻辑链补强

当诊断出逻辑链偏弱时：

| 弱信号 | 补强方法 | 调用Skill |
|-------|---------|----------|
| 论证跳跃 | 补充推理步骤，构建论证结构图 | `prompt-chain-design`（机制3：思维框架构建） |
| 前后矛盾 | 用反向诊断矩阵定位矛盾点 | `prompt-chain-design`（机制5：质量控制） |
| 结构混乱 | 用CIRS模型重新组织内容结构 | `prompt-chain-design`（CIRS四环节） |
| 因果不清 | 用SPECTRA分解因果关系链 | `prompt-chain-design`（SPECTRA模型） |

### 知识链补强

当诊断出知识链偏弱时：

| 弱信号 | 补强方法 | 调用Skill |
|-------|---------|----------|
| 信息空洞 | 激活领域知识，补充数据和案例 | `prompt-engineering-basics`（知识激活策略） |
| 概念错误 | 用TFM聚焦核心概念，交叉验证 | `ai-content-quality`（TFM主题聚焦+七特检测） |
| 视角单一 | 用CMM多视角分析补充 | `creative-prompt-techniques`（CMM跨域映射） |
| 浮于表面 | 用知识链深度挖掘策略 | `prompt-engineering-basics`（五大调教策略） |

### 创意链补强

当诊断出创意链偏弱时：

| 弱信号 | 补强方法 | 调用Skill |
|-------|---------|----------|
| 内容平庸 | 用IDEA框架发散生成新想法 | `creative-prompt-techniques`（IDEA发散） |
| 缺乏新意 | 用EHS极端假设打破思维定式 | `creative-prompt-techniques`（EHS极端假设） |
| 重复常见观点 | 用BRIDGE跨界寻找新角度 | `creative-prompt-techniques`（BRIDGE跨界） |
| 没有差异化 | 用CGS概念嫁接创造独特方案 | `creative-prompt-techniques`（CGS概念嫁接） |

## 三、8维度评估框架

补强完成后，用 `prompt-chain-design` 中的8维度评估框架做全面评估：

| 维度 | 所属链条 | 评估问题 |
|------|---------|---------|
| 论证严密性 | 逻辑链 | 结论是否有充分论据支撑？ |
| 结构连贯性 | 逻辑链 | 各部分之间过渡是否自然？ |
| 知识准确性 | 知识链 | 引用的数据和概念是否准确？ |
| 知识深度 | 知识链 | 是否触及问题本质？ |
| 知识广度 | 知识链 | 是否整合了多个领域的知识？ |
| 原创性 | 创意链 | 是否提出了新颖的观点？ |
| 实用性 | 创意+逻辑 | 方案是否可落地执行？ |
| 表达感染力 | 创意+知识 | 内容是否吸引人？ |

**均衡标准**：8个维度的得分差距不超过2分（如最高5分最低3分）。如果某维度得分明显低于其他，继续针对性补强。

## 四、编排工作流

```
┌─────────────────────────────────────────────────────────┐
│                    三链平衡编排工作流                       │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  1. 接收输出（AI生成的内容 / 任何待评估的文本）             │
│         ↓                                               │
│  2. 诊断：扫描9个弱信号 → 判断哪条链偏弱                   │
│         ↓                                               │
│  3. 选路：根据偏弱链条 → 映射到对应Skill                   │
│         ↓                                               │
│  4. 补强：调用对应Skill的特定方法 → 针对性修改              │
│         ↓                                               │
│  5. 验证：8维度评估 → 检查三链是否均衡                     │
│         ↓                                               │
│  6. 输出：均衡达标 → 输出最终内容                          │
│           均衡未达标 → 回到步骤3继续补强                    │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

## 五、使用场景

### 场景1：AI输出"差点什么"但说不清哪里不对
→ 用三链诊断模型扫描，定位短板，精准补强

### 场景2：重要内容发布前的全面质量检查
→ 用8维度评估框架做全面评估，确保三链均衡

### 场景3：多Skill协作时的质量保障
→ 在多个Skill的输出整合后，用三链编排做最终质量把关

### 场景4：提示语效果不理想时的诊断
→ 结合 `prompt-chain-design` 的反向诊断矩阵，从"输出效果"反推"输入问题"

## 调用关系

- **调用**：`prompt-chain-design`（逻辑链补强）、`prompt-engineering-basics`（知识链补强）、`creative-prompt-techniques`（创意链补强）、`ai-content-quality`（质量检测）
- **被调用**：任何需要质量保障的Skill执行流程
