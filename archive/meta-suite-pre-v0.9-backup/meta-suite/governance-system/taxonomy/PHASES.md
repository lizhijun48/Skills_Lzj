# 六阶段过程定义（Phases）— 双轨共用

> 替代原 D/S/E/V/I 五层模型。
> 基于 PMP + NPDP + 一级建造师 三标准融合 · 产品+项目双轨模型。
> 六阶段是双轨共用的过程骨架，产品轨（PT）和项目轨（JT）各自在此基础上展开。
> 详见 [STANDARDS_FRAMEWORK.md](../STANDARDS_FRAMEWORK.md) §二 双轨模型
> 更新：2026-06-06

---

## 过程总览

```
P1 识别 ──→ P2 论证 ──→ P3 规划 ──→ P4 执行 ──→ P5 控制 ──→ P6 收尾
  ↑                                                              │
  └──────────────── 经验反馈闭环 ←──────────────────────────────────┘

                    CX 专业知识域（贯穿层，按需调用）
```

---

## P1 识别（Frame / 立项识别）

**存在的唯一理由：** 把"我有个想法/遇到个问题"变成"已定义的机会/问题 + 假设清单"。

**核心问题：** 要解决什么问题？值不值得继续投入？

**标准出处：**
- PMP：Initiating 过程组（制定项目章程、识别干系人）
- NPDP：Discovery 阶段（机会识别、概念初筛）+ Strategy（创新战略对齐）
- 一建：项目前期策划（立项建议书、合规预评估）

**常见 Skill 槽位：**
- P1-a 机会识别：问题界定、机会评估、假设树
- P1-b 用户洞察：用户画像、JTBD 分析、客户访谈设计、用户分群
- P1-c 市场机会：竞品初筛、滩头市场识别、ICP 定义
- P1-d 战略对齐：战略一致性检查、创新章程审查

**致命错误：** 还没验证问题就跳到 P3 写方案 → "解决方案前置"

---

## P2 论证（Justify / 可行性论证）

**存在的唯一理由：** 把"可能值得做"变成"有数据支撑的 Go/No-Go 决策"。

**核心问题：** 能不能做？值不值得做？选哪个方案？

**标准出处：**
- PMP：Planning 前端（范围定义、商业论证、风险评估）
- NPDP：Concept Evaluation + Business Analysis（概念评估、NPV/IRR/回收期）
- 一建：建设工程经济（投资估算、财务分析、技术方案比选）

**常见 Skill 槽位：**
- P2-a 经济评价：ROI/NPV/IRR 分析、成本效益分析、投资估算
- P2-b 方案比选：多方案决策矩阵、SWOT/PESTLE/五力分析
- P2-c 价值论证：商业模式画布（BMC/Lean/Startup）、价值主张设计
- P2-d 合规预审：法规约束评估、合规风险初筛

**致命错误：** 用直觉代替数据 — 至少需要一个可量化的论证维度

---

## P3 规划（Plan / 方案设计）

**存在的唯一理由：** 把"决定做了"变成"具体的做什么、怎么做、用什么资源、什么时候完"。

**核心问题：** 范围是什么？优先级怎么排？资源怎么分配？风险怎么应对？

**标准出处：**
- PMP：Planning 过程组（24 个过程：范围/进度/成本/质量/资源/沟通/风险/采购/干系人管理计划）
- NPDP：Development Planning（开发计划、资源配置、技术评审计划）
- 一建：施工组织设计 + 招投标策划 + 合同策划

**常见 Skill 槽位：**
- P3-a 范围定义：PRD、Backlog 条目（US/JS/WWA）、WBS
- P3-b 优先级排序：RICE/ICE/MoSCoW/Kano 框架、优先级矩阵
- P3-c 进度资源：Sprint 计划、OKR、路线图
- P3-d 风险规划：风险登记册、Pre-mortem、应对策略
- P3-e 干系人：干系人映射、沟通计划
- P3-f 采购合同：招投标策划、合同条款规划

**致命错误：** 规划跳过 P2 论证 — 还没证明值得做就开始排计划

---

## P4 执行（Execute / 实施交付）

**存在的唯一理由：** 把计划变成可交付成果，确保质量和边界。

**核心问题：** 怎么按标准做出来？交付物质量如何保证？

**标准出处：**
- PMP：Executing 过程组（10 个过程：指导管理项目工作、管理质量、获取资源、管理沟通/采购/干系人参与）
- NPDP：Development + Testing/Validation（产品开发、测试验证）
- 一建：施工管理实务 + 质量管理 + 安全管理

**常见 Skill 槽位：**
- P4-a 文档交付：PRD 细化、技术方案、标书生成、法律文档
- P4-b 产品交付：原型开发指引、测试方案、试产指导
- P4-c 工程交付：施工组织方案、技术交底、安全检查
- P4-d 工具执行：系统控制、数据处理、自动化任务

**致命错误：** 执行阶段替上游做决策 — 如果发现问题，必须触发变更回到 P2/P3

---

## P5 控制（Control / 监控纠偏）

**存在的唯一理由：** 确保执行不偏离计划，偏离了能及时纠正。

**核心问题：** 做得怎么样？偏了多少？怎么纠？

**标准出处：**
- PMP：Monitoring & Controlling 过程组（12 个过程：整体变更控制、范围/进度/成本/质量控制、风险监控）
- NPDP：Post-Launch Review + Metrics（上市后评审、KPI 仪表盘）
- 一建：进度控制 + 成本控制 + 质量控制 + 安全管理

**常见 Skill 槽位：**
- P5-a 实验验证：A/B 测试分析、队列分析、统计显著性判断
- P5-b 指标监控：北极星指标、指标树、看板设计、漏斗分析
- P5-c 偏差分析：挣值分析（EVM）、进度偏差、成本偏差
- P5-d 变更控制：变更评审、影响分析、变更决策

**致命错误：** 只报告问题不给纠偏方案 — 控制的价值在于"怎么纠"

---

## P6 收尾与演进（Close / 收尾复盘）

**存在的唯一理由：** 把做完的事情变成组织资产，让下一个项目做得更好。

**核心问题：** 学到了什么？什么该沉淀？下一步怎么走？

**标准出处：**
- PMP：Closing 过程组（结束项目或阶段）
- NPDP：Life Cycle Management + Portfolio Review（产品生命周期评审、组合再平衡）
- 一建：竣工验收 + 保修 + 结算

**常见 Skill 槽位：**
- P6-a 复盘引导：Sprint 回顾、项目复盘、经验教训提取
- P6-b 资产归档：文档整理、知识蒸馏、方法论沉淀
- P6-c 生命周期：产品退市评估、组合再平衡、持续改进

**致命错误：** 项目做完就散 — 不做复盘等于浪费组织学习机会

---

## CX 专业知识域（Cross-cutting / 贯穿层）

**定位：** 不绑定特定阶段，而是在任何阶段按需调用的专业知识库。

| 编号 | 知识域 | 标准出处 | 使用场景 |
|:---:|--------|---------|---------|
| CX-1 | 法律法规与合规 | 一建·法规 + NPDP·IP | 任何阶段涉及合规判断时调用 |
| CX-2 | 工程经济 | 一建·经济 + PMP·Cost | 任何阶段涉及财务分析时调用 |
| CX-3 | 市场研究 | NPDP·Market Research | P1/P2 阶段频繁调用 |
| CX-4 | 产品战略与组合 | NPDP·Strategy + Portfolio | P1/P2 阶段调用 |
| CX-5 | 组织与团队 | PMP·Resource + Stakeholder | P1/P3 阶段调用 |
| CX-6 | 度量与数据 | PMP·Metrics + NPDP·Tools | P5 阶段频繁调用 |
| CX-7 | 行业领域知识 | 一建·专业实务 + 各行业 | 任何阶段需要行业专业知识时 |
| CX-8 | Agent 与工具方法 | 独立（Agent Skills 元能力） | 系统运维、Skill 创建、Agent 编排 |

---

## 阶段间流转规则

1. **正常流向：** P1 → P2 → P3 → P4 → P5 → P6（顺序推进）
2. **允许跳阶段：** 用户自带上游结论可跳过（如已有 P2 论证可直接进 P3）
3. **允许回退：** P4/P5 发现问题可触发变更回到 P1/P2/P3（必须走变更控制流程）
4. **CX 随时可用：** 专业知识域不参与阶段流转，任何阶段按需调用
5. **不强制完整链路：** 用户的单次请求可能只涉及一个阶段，不强制走全流程
