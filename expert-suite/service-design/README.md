# 服务设计专家天团 - SkillHub 发布包

## 发布包定位

本发布包将「服务设计专家天团」拆分为 10 个可独立安装、可协作编排的 SkillHub 技能。适用于服务设计、客户洞察、增长策略、指标体系、ROI、证据审计、理论萃取和交付 QA 等咨询型任务。

## 推荐安装方式

- 如只需要单一专家能力，可安装对应 `fwsjtt-*` 技能。
- 如任务涉及多专家协同，优先安装并调用 `fwsjtt-expert-team` 作为总控入口。

## 技能清单

- `fwsjtt-chief-consultant`：帮助用户澄清复杂任务的北极星目标、拆解问题结构、制定专家协作路径，并防止任务发散或跳阶段。当用户要求“调用服务设计专家团”但任务目标、边界或交付物尚不清晰时，可先调用本技能完成目标澄清与专家协作路径设计。
- `fwsjtt-customer-discovery-expert`：帮助用户从客户事实、访谈证据、JTBD 和假设验证出发识别真实需求，避免把内部判断或销售话术当作客户事实。
- `fwsjtt-delivery-qa-reviewer`：审查报告、方案或咨询输出是否结论先行、结构清晰、证据边界明确、行动可执行，并触发返工建议。
- `fwsjtt-evidence-auditor`：审查资料、观点和结论的来源强度，标注 L0-L4 证据等级，阻止伪权威、伪引用和未经验证的确定性表达。
- `fwsjtt-expert-team`：服务设计专家团的统一入口与 FWSJTT 专家团总控调度中心。用于识别任务北极星目标，分诊到不同专家技能，协调多专家评审、冲突消解、结论综合与交付物 QA，形成可执行的咨询级输出。当用户提到“调用服务设计专家团”“启用服务设计专家团”“服务设计专家团介入”“请服务设计专家团队评估”“用专家团处理这个问题”，或提出需要多专家协同的复杂服务设计、服务优化、客户体验、增长策略、指标体系、ROI 评估、证据审计与交付 QA 任务时，应优先调用本技能。
- `fwsjtt-metrics-architect`：设计北极星指标、指标树、领先/滞后指标、测量口径和验证计划，确保指标能服务业务决策。
- `fwsjtt-roi-strategist`：根据输入数据完整度判断 ROI、成本收益、回本周期和商业价值能否量化，并在数据不足时输出假设、区间或测算框架而非伪精确数字。
- `fwsjtt-service-designer`：围绕用户旅程、触点、前后台流程、服务蓝图和关键时刻诊断服务体验问题，避免停留在表层建议。
- `fwsjtt-strategy-growth-advisor`：帮助用户诊断战略问题、增长瓶颈、竞争定位和关键取舍，避免泛泛而谈的增长建议。
- `fwsjtt-theory-distiller`：从专家、经典书目和高价值理论中提炼可操作的方法、工作流、QA 规则和测试场景，转化为技能模块输入。

## SkillHub 发布适配说明

本优化版已完成：

- 清理 macOS 噪音文件与压缩包冗余目录。
- 保留并校验每个技能的 `SKILL.md` 注册入口。
- 如发现缺少 YAML front matter，将自动补齐 `name` 与 `description`。
- 统一增强每个技能的 `README.md`，补充适用场景、不适用场景、快速开始、输出结构、安装依赖和验证方式。
- 为每个技能补充 `tests/boundary-and-routing-test.md` 和 `examples/example-prompts.md`。
- 为 references 目录补充 `references/index.md`，便于审核与维护。

## 发布前人工复核建议

- 若 SkillHub 面向外部或跨组织发布，请人工复核 `references/` 中是否包含内部项目名、内部版本过程、客户信息或不可外发内容。
- 若发布平台要求额外字段（如 version、author、tags、license），可在各技能 `SKILL.md` YAML front matter 中补充。
