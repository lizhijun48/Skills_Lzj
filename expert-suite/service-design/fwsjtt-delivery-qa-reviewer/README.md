# fwsjtt-delivery-qa-reviewer

## SkillHub 发布定位

fwsjtt-delivery-qa-reviewer 是「服务设计专家天团」技能组中的一个可独立安装技能。  
技能说明：审查报告、方案或咨询输出是否结论先行、结构清晰、证据边界明确、行动可执行，并触发返工建议。

## 适用场景

- 用户需要围绕服务设计、客户体验、增长策略、指标体系、ROI、证据审计或交付质量进行结构化分析。
- 用户希望由明确角色承担单一专家职责，而不是泛泛给建议。
- 任务需要先澄清北极星目标、边界、输入材料与可交付结果。

## 不适用场景

- 用户只需要闲聊、百科解释或无需结构化交付的简单问答。
- 用户要求生成无证据支撑的确定性结论、伪精确 ROI 或未经验证的事实判断。
- 用户需要多个专家协同但未调用总控入口时，应优先建议使用 `fwsjtt-expert-team` 进行分诊与编排。

## 快速开始

示例输入：

```text
请用 fwsjtt-delivery-qa-reviewer 帮我评估一个酒店会员服务体验优化方案，先确认北极星目标，再输出可执行建议。
```

```text
我们准备上线一个客户旅程优化项目，请你按专家角色指出关键风险、证据缺口和下一步验证计划。
```

## 预期输出结构

- 任务理解与北极星目标确认
- 已知信息 / 缺失信息
- 专家判断与依据
- 可执行建议
- 风险、假设与验证方式
- 下一步行动清单

## 目录结构

- `SKILL.md`：技能注册元数据、触发条件、工作流和输出规范。
- `references/`：角色规范、方法框架、证据标准或回归资料。
- `tests/`：发布前 smoke test、边界测试和回归测试。
- `examples/`：SkillHub 展示与安装验证可用的示例提示词。

## 安装与依赖建议

- 可作为独立技能安装。
- 若用户任务需要多专家协同、冲突消解或总控调度，建议同时安装并优先调用 `fwsjtt-expert-team`。

## 发布前验证

发布前至少执行：

1. 读取 `SKILL.md`，确认 YAML front matter 包含 `name` 与 `description`。
2. 使用 `tests/smoke-test.md` 验证技能能正确说明能力边界并给出下一步。
3. 使用 `tests/boundary-and-routing-test.md` 验证输入不足、跨专家协作、证据不足时不会越权或伪精确。
4. 检查 `references/` 是否包含敏感信息或不应外发的内部材料。

## 维护建议

- 方法论、角色边界或协作关系变更时，需同步更新 `SKILL.md`、`README.md` 与 `tests/`。
- 每次发布前保留一份发布检查报告，便于回退与复盘。
