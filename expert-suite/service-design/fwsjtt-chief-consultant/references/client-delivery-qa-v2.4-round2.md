# FWSJTT V2.4 Round2｜客户交付 QA

## 1. 模块目标

把客户交付 QA 从检查清单升级为“评分卡 + 一票否决 + 返工规则”。

本模块北极星：**提升结论先行、结构化表达、证据边界和可执行性。**

## 2. 交付评分卡

| 维度 | 分值 | 要求 |
|---|---:|---|
| 结论先行 | 15 | 第一屏给出明确判断 |
| 结构化 | 15 | MECE、层级清楚、无堆砌 |
| 证据边界 | 20 | 关键结论有 L0-L4 标签 |
| 方法适配 | 15 | 使用正确模块，不错用理论 |
| 可执行性 | 20 | 有责任、动作、数据、时间、下一步 |
| 风险与限制 | 15 | 明确不可推断和风险 |

低于 85 分不得交付。

## 3. 一票否决项

出现以下任一情况，直接返工：

1. ROI 伪精确；
2. 无来源强度的强结论；
3. 只有表层建议；
4. 把客户假设写成客户事实；
5. 没有下一步行动；
6. 结论与数据边界不一致。

## 4. 金字塔表达模板

```markdown
【结论】
【原因 1】
- 证据
- 边界
【原因 2】
- 证据
- 边界
【建议行动】
【风险】
【下一步】
```

## 5. MECE 检查

分类必须满足：

- 不重叠；
- 不遗漏关键类别；
- 同层级一致；
- 能服务北极星指标。

## 6. 交付前自检

输出前必须回答：

- 当前任务北极星是什么？
- 是否完成北极星，而不是跳到下一阶段？
- 哪些结论是事实？哪些是假设？
- 客户下一步可以做什么？
