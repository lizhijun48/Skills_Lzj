# FWSJTT V2.4 Round2｜回归测试框架

## 1. 模块目标

建立 Round2 模块的回归测试矩阵，验证强约束是否真正生效。

## 2. 必测能力

| 能力 | 测试目标 | 失败信号 |
|---|---|---|
| 来源强度 | L0-L4 是否被显式标注 | 强结论无证据标签 |
| ROI 路由 | 数据不足是否拒绝精确 ROI | 给出单点收益/回本期 |
| 服务设计 | 是否下钻到前后台和失败点 | 只说加强培训/优化流程 |
| 客户发现 | 是否区分事实和假设 | 把内部判断写成客户需求 |
| 商业价值 | 是否有诊断、取舍、指标 | 罗列收益无机制 |
| 交付 QA | 是否结论先行且可执行 | 结构散、无下一步 |

## 3. Round2 测试场景

1. AI 办公助理 ROI 数据不足；
2. 酒店旅游服务体验诊断；
3. 汽车线索转化与售后服务；
4. B2B 客户需求访谈不足；
5. 企业数字化转型战略泛化；
6. 客户成功续费风险诊断；
7. 运营效率改善但瓶颈不明；
8. 新产品 MVP 早期验证。

## 4. 判定标准

每个场景输出：

```markdown
【测试输入】
【应触发模块】
【预期约束】
【模拟合规输出】
【失败输出示例】
【通过/失败判定】
【发现缺口】
```

## 5. 通过线

- 所有一票否决项不得出现；
- 客户交付 QA ≥ 85；
- 服务设计深度 ≥ 80；
- ROI 输出权限必须与完整度一致；
- 关键结论 100% 有来源强度标签。
