# FWSJTT V2.4 Round2｜客户需求发现方法模块

## 1. 模块目标

新增客户需求发现模块，把 JTBD、The Mom Test、Value Proposition Design、Continuous Discovery 转化为 FWSJTT 的需求诊断工作流。

本模块北极星：**阻止把主观想象写成客户需求，优先使用客户事实、行为证据和可验证假设。**

## 2. 客户事实优先规则

需求判断必须区分：

| 类型 | 说明 | 输出权限 |
|---|---|---|
| 客户事实 | 客户真实行为、购买、投诉、流失、访谈原话 | 可作为需求线索 |
| 客户表述 | 客户说想要什么 | 只能作为待验证需求 |
| 内部判断 | 销售、运营、管理层认为客户需要 | 只能作为假设 |
| 模型推理 | AI 根据上下文推测 | 只能作为问题清单 |

## 3. JTBD 转化模板

```markdown
当我处在【情境】
我想要【进步/任务】
以便实现【结果】
当前替代方案是【替代品/流程】
阻碍是【约束/焦虑/惯性】
证据是【行为/访谈/数据】
```

## 4. The Mom Test 访谈约束

禁止问：

- 你会买吗？
- 你喜欢这个方案吗？
- 如果我们做了你会不会用？

优先问：

- 上一次遇到这个问题是什么时候？
- 当时怎么解决？
- 花了多少钱/时间/人力？
- 为什么现有方案不够好？
- 谁参与了决策？

## 5. 机会树与持续发现

输出客户需求时，应形成：

```text
业务结果
→ 客户机会
→ 解决方案假设
→ 实验
→ 学习指标
```

## 6. 价值主张匹配

每个方案必须匹配：

- 客户任务；
- 痛点；
- 收益；
- 产品/服务能力；
- 缓解痛点机制；
- 创造收益机制。

## 7. 回归测试触发

若输出中出现“客户需要”“用户更希望”“客户一定会”，但无客户事实或行为证据，必须判定为失败。
