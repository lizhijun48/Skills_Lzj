# 专家视角共享决策内核（perspective-kernel）

> 版本：v1.1 | 建立：2026-08-31 | v1.1：经刘润《底层逻辑》交叉检验，补强第1/2/5/6步的操作化检验，并附方法论来源（见文末）
> 定位：所有"视角类"专家技能的**不变底层逻辑**。视角层可以千变万化，本内核保持唯一。
> 引用方：S-006 高格局思维视角、S-007 周鸿祎思维视角，及未来新增的一切视角技能
> 关系：本文件不是独立技能，不被用户直接调用；它是视角技能执行时必须遵守的决策骨架
> 理论锚点：刘润《底层逻辑》序言公式——**底层逻辑 + 环境变量 = 方法论**。本内核即"不变的底层逻辑"，视角层四件套即"环境变量"。

## 1. 内核层与视角层的边界

| 层 | 内容 | 可变性 |
|----|------|--------|
| 内核层（本文件） | 6步决策程序 | **不变**。任何视角技能不得修改、删减或重排 |
| 视角层（各视角技能） | 透镜词汇、心智模型、启发式/检验清单的具体内容、案例库、角色扮演语气 | **可替换**。每个视角一套 |

新增一个视角技能时，只允许替换视角层四件套：
1. **透镜词汇**（该视角的偏好用词，如"免费/用户/颠覆"或"终局/尺度/边界"）
2. **检验清单内容**（8决策启发式 + 10验证测试的具体条目）
3. **案例库**（该视角人物/领域的真实案例）
4. **表达DNA**（第一人称角色设定的语气风格）

## 2. 六步决策内核（不变）

无论哪个视角，面对任何问题，决策推理必须依次经过：

### 第一步：本质定位——识别核心矛盾
剥离表面问题，找到背后的主要矛盾。
- **本质在关系/结构，不在人/事**：不要停在"是谁的问题""哪件事的问题"。同一批人放进不同结构，行为完全不同（如食堂考核从"保证质量"改为"后厨先吃"，问题即消失）。追问：是哪条**利益/激励/反馈结构**在决定这个表象？
- **三层追问法定位深度**：这个结论停留在哪一层——改**结果**（出了事再补救）？改**原因**（追责、堵漏洞）？还是改**模型**（重构结构本身，让问题不可能发生）？必须追到能改模型的那一层，才算找到本质。
- 检验问题：这个问题真正卡住的是什么？表面诉求和真实矛盾是否一致？如果把人和事件全部替换，这个结构还会产生同样的问题吗？

### 第二步：常变分离——区分不可变与可变
把约束条件分为两类：不可改变的（环境、禀赋、行业规律）接纳它；可改变的（方法、路径、投入）集中力量。
- **定常量要看系统不看孤点**：把要素拆开单个看是"个位思维"，看要素之间的联结和整体结构才是"千位思维"。齿轮可以换，传动结构往往是那个不可变的常量。
- 检验问题：哪些是必须接受的"常量"？哪些是可以创造的"变量"？

### 第三步：终局定义——具体描绘期望的终态
不是"做得更好"，而是"最终长什么样"。终局必须具体到可以辨认。
- 检验问题：做成之后的世界/状态，具体是什么样？

### 第四步：终局倒推——以终为始回推路径
从终局状态反向推导今天应该做什么。路径由终局决定，不由现状惯性决定。
- 检验问题：要达到那个终局，倒推回来，今天唯一必须做的动作是什么？

### 第五步：杠杆聚焦 + 取舍显化
找到"牵一发而动全身"的单一杠杆点，集中力量；同时**明确说出放弃了什么**。没有显化取舍的战略不是战略。
- **杠杆有层级，高级优先**：同样是"一两拨千斤"，撬动点分三级——改**结果**（事后补救，靠流程）< 改**原因**（追责堵漏，靠制度）< 改**模型**（重构系统，靠治理）。选杠杆点时先尝试在更高层级找；只有高层级撬不动时才降级。
- 检验问题：杠杆点是什么？它作用在结果层、原因层还是模型层？为此明确放弃了什么？

### 第六步：清单验证 + 概率检验
把结论送进该视角自己的检验清单（8启发式 + 10验证测试）跑一遍，通不过的结论降级为"待验证假设"；再用概率思维做最后一道检查。
- **期望值表述**：结论不要用"确定能/一定不能"表述，而用"概率 × 支付"的期望值表述。小概率高支付与大概率低支付是两个不同的决策，不是同一个"赌不赌"的问题。
- **幸存者偏差检查**：证据来自"活下来的样本"还是全部样本？看得见的弹孔不代表致命处，**没弹孔的地方才是**。主动问：我依据的案例里，沉默的失败者在哪里？
- 检验问题：哪些检验项没通过？对应需要补什么证据或实验？结论换算成期望值后还成立吗？证据链有没有幸存者偏差？

## 3. 跨视角比较协议

当用户要求多角度分析同一问题时，输出必须包含三层：

1. **逐视角陈述**：每个视角独立回答"在这个角度下，是什么情况"——使用该视角的透镜词汇和案例，但推理步骤严格遵循第2节的6步内核
2. **内核层对照表**：把各视角的结论拆回6步内核逐项对照，标出——
   - 各视角在**哪一步**产生了分歧（例如：终局定义不同 / 对"常量"的判断不同 / 杠杆点选择不同）
   - 各视角在哪些步骤上结论一致（这是更可信的部分）
3. **取舍显化**：说明采纳某视角结论意味着放弃什么，由用户决策

**分歧仲裁规则**：视角之间结论冲突时，不比较"谁的声音大"，而是回到内核层定位分歧步骤——
- 若终局定义不同 → 先让用户确认想要哪个终局
- 若常变判断不同 → 核对事实，常量判断错误的视角让步
- 若杠杆点不同 → 比较两个杠杆点的验证成本，低成本先验证

## 4. 与服务设计专家团（X-001~X-011）的关系

专家团有自己的一套不变逻辑（北极星目标 → 证据等级限定输出权限 → 可执行建议 → QA复核），服务于**交付物生产**；本内核服务于**思维视角类分析**。两者层次不同，不互相覆盖：
- 用户要"想清楚一个问题" → 用视角技能 + 本内核
- 用户要"产出一份可交付的专业结论" → 用服务设计专家团
- 两者可以串联：先用视角技能定方向（本内核），再用专家团出交付（团队逻辑）
