## 2. 三个增强方案（实施记录：C ✅ / B ✅ / A 全面落地 ✅）

> 实施顺序由用户指定为 C→B→A（2026-08-31）。注册表变更记录见 `SKILL-ID-REGISTRY.md` v1.5.5。

### 方案A：评分卡期望值化 → **已在三套评分卡全面落地**
1. ✅ 每个维度的 1–5 分改为**概率区间锚定**（复用 pm-risk PIM 的 >70%/51–70%/31–50%/11–30%/≤10% 五级语言-数字锚，这是全库唯一正面样板）→ 落点：`pd-go-nogo` Step 3 / `pm-project-opportunity` 阶段零 / `product-solution-evaluator` 8.1
2. ✅ 总分旁增列**期望支付**：`期望值 = Σ(维度概率 × 该维金额化支付)`，至少对"市场/财务"两维要求填金额量纲 → 落点：各 SKILL 的期望支付规则 + 报告模板；规则＝合计期望支付 ≤0 强制降级
3. ✅ 一票否决与封顶规则统一改写为**乘法零因子**表达：`总分 = (Σ 加权) × Π(通过_i ? 1 : 0)`——保留算术直观，同时显式承认"加法可补偿是错的" → 落点：各 SKILL 公式 + Veto 引导句 + 对应 references 模板
4. ✅ 每次立项/复盘后**回写先验**（推广 pm-bid 的贝叶斯K回写模式）：`本次置信度 → 下次同类项目基础成功率修正表` → 落点：各 SKILL 新增 Step X/Step 6 先验回写章节，含逐维度回写表与"≥5 样本后替换默认概率锚"累积规则
5. ✅ **推广完成**：`pm-project-opportunity` 8维、`product-solution-evaluator` 6维两张评分卡**已同步改造**，三套评分卡现统一概率锚定语义（注册表 v1.5.5）

### 方案B：通用交易结构分析器 → **已落地**
文件：`pd-suite/pd-product-strategy/references/transaction-structure-analyzer.md`（把合同类型矩阵 + BMC + Salience 三合一）

2. ✅ 逐边三问：**对手方为什么愿意？他有什么替代选项（BATNA）？风险沿合同/分成怎么流？**
3. ✅ 输出"交易结构图"（节点=角色，边=钱/货/数据/风险流向）——补上"没有一张因果/流向图"的系统思维缺口
4. ✅ 挂接位：`pd-product-strategy` 参考资料表、`pm-procurement-quality` A4 合同类型表（交叉指向）、`pd-go-nogo` 期望支付规则（对手方 BATNA 优于本交易时 V 须打折）
