# 阅读操作系统 v1.0

## 定义

一套完整的个人知识管理流程，覆盖从"书籍内容获取 → 目标收敛 → 读者反馈收集 → 知识点映射 → 深度拆解 → 资产化输出 → 技能治理与融入"的全链路。

**核心价值**：让书进入用户的真问题，产出可迭代的内部资产，并将知识转化为可复用的技能。不是"多读/速读/总结"，而是"把书变成判断/文档/决策/流程/技能"。

---

## 适用场景

- 用户拥有一座"负债型书架"（500+ 本未读），感到焦虑但不知从何下手
- 用户希望围绕一个明确的 90 天目标，系统性地阅读和产出
- 用户需要将阅读成果转化为可复用的工作资产（文档/决策/规范）和可执行的技能
- 用户想建立长期的、可持续的个人知识管理体系
- 用户希望将阅读中的感悟/共鸣/争议转化为技能建立的建议

---

## 不适用场景

- 纯消遣阅读（小说/随笔/诗歌），不需要系统化管理
- 用户没有明确的阅读数据源（无法获取书架信息）
- 用户只需要单次快速摘要（直接调用普通总结功能即可）
- 用户无法说清"我当前最重要目标是什么"——先退回问目标，不硬拆

---

## 核心调度逻辑

```
用户进入系统
  │
  ├─ 有书架数据？ ──→ Step 1：书架体检（调用子技能：reading-bookshelf-health）
  │                        │
  │                        └─→ 输出：三轴定位 + 收敛书单
  │                              │
  │                              └─→ 用户确认收敛书单
  │                                    │
  └─ 无书架数据？ ──→ Step 2：目标锚定（手动输入）
        │
        └─→ 用户提供角色 + 90 天目标
              │
              ↓
        Step 3：选择第一本书
              │
              ├─ 调用子技能：reading-role-path（角色适配）
              │    │
              │    └─→ 输出：三层路径 + 阅读优先级
              │          │
              │          └─→ 用户按路径阅读
              │                │
              │                └─→ Step 4：调用子技能：reading-book-deconstruction（深度拆书）
              │                      │
              │                      ├─ Step 0：书籍内容获取（强制）
              │                      │    │
              │                      │    └─→ 有内容：继续；无内容：选择框架性拆书
              │                      │
              │                      ├─ Step 1：单书定位
              │                      │    │
              │                      │    └─→ 输出：在知识体系中的位置 + 优先级
              │                      │
              │                      ├─ Step 1.5：读者反馈收集（新增）
              │                      │    │
              │                      │    └─→ 输出：读者反馈表 + 反馈与知识点对齐分析
              │                      │
              │                      ├─ Step 2：知识点映射
              │                      │    │
              │                      │    └─→ 输出：知识点-目标对齐表
              │                      │
              │                      ├─ Step 3：三个追问
              │                      │    │
              │                      │    └─→ 输出：三个追问答案
              │                      │
              │                      ├─ Step 4：资产化输出 + 技能建立建议
              │                      │    │
              │                      │    └─→ 输出：资产化产出 + 技能建立建议报告
              │                      │
              │                      └─ Step 5：技能治理与融入（新增）
              │                           │
              │                           └─→ 输出：技能融入报告
              │                                 │
              │                                 └─→ 存入个人知识库 + 技能图谱
              │                                       │
              └─→ 返回 Step 3，选择下一本书
                    │
                    └─→ 读完收敛书单后，回到 Step 1 做新一轮体检
```

## 输入要求

| 必填 | 说明 |
|------|------|
| 用户当前角色 | 产品负责人/售前/行业方案专家/研发/运营/其他 |
| 用户当前 90 天最重要目标 | 1 句话，越具体越好 |
| 书架数据（可选） | 若有则启动完整流程；若无则从 Step 2 开始 |
| 书籍内容（可选） | PDF/图片/文字/读书笔记/划线/感想 |
| 读者反馈（可选） | 共鸣/争议/应用意图 |

---

## 子技能间的数据传递

- **B → C**：B 输出的收敛书单作为 C 的输入之一，C 据此为每本书标注"对你当前角色的优先级"
- **C → A**：C 输出的三层路径作为 A 的 Step 2 输入，A 在执行拆解时自动按路径聚焦
- **A（Step 1.5）→ A（Step 2）**：读者反馈作为知识点映射的重要输入，优先映射有反馈的知识点
- **A（Step 4）→ A（Step 5）**：技能建立建议作为技能治理的输入，优先治理读者最需要的技能
- **A（Step 5）→ 技能图谱**：治理后的技能融入现有技能图谱，更新依赖关系
- **A → 知识库**：A 输出的资产化产物（决策备忘录/规范草案/Checklist）存入用户指定的知识库目录

## 人工确认点

- [ ] Step 1 结束后：用户是否认可三轴定位和收敛书单
- [ ] Step 3 每次选书前：用户是否确认当前优先级
- [ ] Step 4（拆书）每一步结束后：用户是否确认可以继续
  - [ ] Step 0：书籍内容获取是否完成？
  - [ ] Step 1：单书定位是否认可？
  - [ ] Step 1.5：读者反馈是否收集完整？
  - [ ] Step 2：知识点映射是否贴合用户目标？
  - [ ] Step 4：资产化产出格式，用户选哪一种？
  - [ ] Step 4：技能建立建议，用户是否认可？
  - [ ] Step 5：技能治理结果，用户是否认可？
- [ ] Step 4 每次产出后：用户是否确认资产化产物可用，是否需要修改

## 安全边界

- 不替用户做终极取舍（"这本书该不该删"）——只给数据和建议
- 不强制定期体检频率——由用户自行设定，系统只做提醒
- 不假设用户必须全职投入阅读——尊重用户的时间预算
- 不替用户决定"要建立什么技能"——给建议，用户自己拍板
- 不假设用户提供的书籍内容/反馈是完整的——主动询问是否有补充

## 版本迭代规则

- v0.1：三个子技能各自独立可用，总调度逻辑为手动引导（用户按步骤操作）
- v0.2：实现子技能间的自动数据传递（B 的输出自动进入 C 的输入）
- v0.3：按角色模板库扩充（产品/研发/运营/销售/HR…各自三层追问微调）
- v1.0：**当前版本**：增加 Step 0（书籍内容获取）+ Step 1.5（读者反馈收集）+ Step 4 优化（技能建立建议）+ Step 5（技能治理与融入）
- v1.1：增加知识库自动归档和检索功能
- v1.2：增加季度阅读资产报告自动生成
- v1.3：支持多人协作（团队共读场景）

## 踩坑点记录

- 用户在 Step 1 看到收敛书单时容易产生"舍不得删"的情绪——需要给出"降级资料库"的中间态选项
- 用户在 Step 3 选书时容易陷入"选择瘫痪"（30 本也不知道先读哪本）——系统应按"第一层优先"排序
- 用户在 Step 4 产出资产时容易滑回"写摘要"的老路——系统应强制要求选择产出类型
- 用户可能在运行中途更换角色或目标——系统应支持"中断当前流程，重新锚定目标后继续"
- 用户常说"帮我总结这本书"——要反问：你要的是总结，还是拆成资产？多数时候他要的是后者，但嘴上说的是前者
- 读者反馈收集容易被忽略——要主动询问，不要等用户主动说
- 技能建立建议容易"假大空"——要基于用户的实际角色和目标，给出可执行的建立路径
