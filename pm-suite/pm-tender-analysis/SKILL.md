# pm-tender-analysis · 招标文件智能解析

**定位**：招标文件解析专项技能——将一份招标文件（PDF/Word/文本）转化为结构化的竞标支撑报告，覆盖项目概览、资质核查、评分矩阵、风险信号和专家决策建议。本SKILL是 `pm-bid-proposal`（投标方案编制）的**前置输入**，也可单独调用用于Go/No-Go快速判断。

**对标依据**：《招标投标法》《政府采购法》及其实施条例、《政府采购竞争性磋商采购方式管理暂行办法》、软考高项招标管理章节、PMBOK第12章采购管理

**触发词**：招标文件分析、解读招标文件、投标支撑、标书解析、招标文件评审、竞标分析、招标文件解读、看标、读标、拆标

---

## 核心原则

1. **完整提取，不遗漏**：招标文件中的每一个数字（预算、工期、评分权重）都是关键，必须全量提取
2. **风险前置**：先扫风险信号再做分析，避免在废标条款上浪费精力
3. **评分驱动**：所有分析最终服务于"如何最大化得分"，而非停留在信息整理层
4. **专家视角**：超越信息整理，给出资深投标人的判断——哪些条款是软性门槛、哪些评分项可以突破、哪些是定制化陷阱
5. **可操作性**：每个分析结论都要有对应的"行动建议"，不只出判断不出动作
6. **合规底线**：时间节点合规性扫描是必检项，任何时间违规立即标红
7. **保密意识**：解析过程中涉及的业主信息、预算数据按商业秘密处理

## 前置条件

**输入要求**：
- 招标文件全文（粘贴文本 / 文件内容 / 关键章节）
- 我方基本情况（可选）：企业规模、主要资质证书、近3年业绩概况、技术方向

**输出规范**：生成结构化的《招标文件解析报告》，7个模块按序输出

## 工作流程

### 第一步：快速扫描 — 废标风险识别（先于一切）

> **铁律**：在做任何深入分析之前，先扫废标条款。存在一票否决项时，立即标红，后续分析是否继续由用户决定。

**扫描清单**：
```
□ 是否有禁止性资质要求（如"须具备XX级别证书"）
□ 是否有地域/注册地限制
□ 是否有"近X年无重大违法记录"要求
□ 是否有最低控制价（低于则废标）
□ 是否有强制联合体禁止条款
□ 招标文件时间节点是否合法：
    - 等标期是否≥20日（工程/政采公开招标）
    - 招标文件发售期是否≥5日
    - 公示期是否≥3日
□ 是否有针对特定企业的"量身定制"特征（如特定品牌/特定参数）
```

**废标快速判定**：

| 风险等级 | 判定标准 | 建议动作 |
|---------|---------|---------|
| 🔴 一票否决 | 资质硬性要求不满足 | 停止分析，评估联合体可能性 |
| 🟠 高风险 | 资质可能满足但存在争议 | 继续分析，标注风险点，评估申诉路径 |
| 🟡 注意 | 有不合理条款但不致命 | 继续分析，考虑是否在答疑期提出异议 |
| 🟢 正常 | 无明显问题 | 正常进入全量分析 |

### 第三步：资质门槛核查表（Qualification Checklist）

> 逐项列出所有资质要求，对照我方情况给出三色判断。

**输出格式**：

| 序号 | 资质/条件要求 | 来源章节 | 是否强制 | 我方状态 | 满足程度 |
|-----|-------------|---------|---------|---------|---------|
| 1 | 企业资质：[如建筑业企业三级及以上] | 第X章 | **强制** | [填入] | ✅满足/⚠️争议/❌不满足 |
| 2 | 人员资质：[如项目经理须持XX证] | 第X章 | **强制** | [填入] | ✅/⚠️/❌ |
| 3 | 业绩要求：[如近3年完成类似项目X个] | 第X章 | **强制** | [填入] | ✅/⚠️/❌ |
| 4 | 财务要求：[如近3年年均营收≥X万] | 第X章 | **强制** | [填入] | ✅/⚠️/❌ |
| 5 | 信用要求：[无重大违法违规记录] | 第X章 | **强制** | [填入] | ✅/⚠️/❌ |
| 6 | 认证要求：[如ISO9001/等保三级] | 第X章 | 加分项 | [填入] | ✅/⚠️/❌ |

**资质满足度汇总**：
- 强制项：X项全部满足 / X项满足X项不满足
- 加分项：X项满足
- 联合体建议：[是否需要联合体，联合体可补哪些短板]

**⚠️ 实战注意**：
- "类似业绩"的认定口径可能是陷阱——注意招标文件对"类似"的定义是否符合常规理解
- 人员资质一般要求提供社保证明，确认拟派人员已在公司缴纳社保满X个月
- "注册地限制"如果存在，需评估是否构成违法设定限制（可在答疑期提出异议）

### 第四步：评分矩阵分析（Scoring Matrix Analysis）

> 这是投标策略的核心——弄清楚每一分从哪来、哪里可以拉开差距。

**4.1 评分结构总览**

| 评分维度 | 权重 | 满分 | 我方预估得分 | 得分差距 |
|---------|-----|-----|------------|---------|
| 技术标 | X% | X分 | X分 | +X/-X |
| 商务标 | X% | X分 | X分 | +X/-X |
| 价格标 | X% | X分 | X分 | +X/-X |
| **合计** | **100%** | **100分** | **X分** | |

**4.2 技术标详细拆解**

| 技术评分项 | 分值 | 评分标准 | 我方方案优势 | 得分策略 |
|-----------|-----|---------|------------|---------|
| [如：技术方案可行性] | X分 | [评分细则] | [我方亮点] | [如何争满分] |
| [如：团队配置] | X分 | [评分细则] | | |
| [如：实施方案] | X分 | [评分细则] | | |
| [如：资质业绩] | X分 | [评分细则] | | |

**4.3 价格标策略**

> 价格评分通常对整体得分影响20-30%，报价策略至关重要。

常见价格评分模型：

| 评分模型 | 计算公式 | 最优报价点 | 风险 |
|---------|---------|----------|-----|
| 最低价法 | 最低价得满分，其他按比例 | 越低越好 | 低于成本价废标 |
| 中间价法 | 以平均价为基准，偏离扣分 | 接近预测均价 | 需预判竞争对手报价 |
| 基准价法 | 以控制价X%为基准 | X%×控制价 | 基准价公式需精确计算 |
| 最低合理价法 | 评委综合判断"合理" | 略低于预算均值 | 评判主观性强 |

**当前项目价格评分模型**：[从招标文件中提取并说明]

**报价建议区间**：[X万 ~ X万]，**最优报价点**：[X万]

**4.4 高分策略总结**

```
技术标争分点（可拉开差距的方向）：
1. [如：创新技术方案—可加分X分，建议重点投入]
2. [如：类似项目业绩—满足基础要求即可，加分有限]
3. [如：团队配置—拟配1名高级工程师可多得X分]

商务标争分点：
1. [如：服务承诺期—超出要求可得加分]
2. [如：本地化服务—有无本地维保点影响X分]

价格标注意事项：
- 最低控制价：不能低于X万（低于废标）
- 竞争对手预测报价区间：X万~X万
- 建议报价：X万（预计得价格分X分）
```

### 第五步：建设内容深度解析（Scope Analysis）

> 弄清楚"要做什么"，为技术方案编制提供基础。

**5.1 建设范围**
- 主要建设内容：[提取并结构化]
- 分项清单：[子系统/子模块列表]
- 交付成果要求：[文档/系统/验收标准]

**5.2 技术要求关键点**

| 技术要求 | 是否强制 | 是否可以超出（正偏离） | 风险提示 |
|---------|---------|-------------------|---------|
| [如：系统响应时间≤X秒] | 强制 | 可超出（是加分项） | |
| [如：采用国产数据库] | 强制 | 否（有限制品牌/类型） | ⚠️ 注意是否违反公平竞争 |
| [如：支持X并发用户] | 强制 | 可超出 | |

**5.3 特殊要求识别**
- 是否有国产化要求（如CPU/操作系统/数据库国产化率要求）
- 是否有等保要求（等保X级，若有则需计入实施成本）
- 是否有数据本地化要求
- 是否有特定品牌/型号要求（可能涉及定制化招标）

### 第六步：风险信号与陷阱识别（Risk & Trap Analysis）

> 资深专家视角——这一节是从"坑"里爬出来的经验。

**6.1 合规性风险**

| 风险类型 | 具体表现 | 风险等级 | 建议动作 |
|---------|---------|---------|---------|
| 时间节点违法 | 等标期<20日 | 🔴 | 书面异议（投标截止前10日内） |
| 量身定制嫌疑 | 技术参数高度匹配某一品牌 | 🟠 | 收集证据，评估申诉成本收益 |
| 不合理限制 | 要求必须本地企业/注册地限制 | 🟠 | 书面异议，引用《政府采购法》第22条 |
| 虚假业绩风险 | 要求的业绩难以核实 | 🟡 | 提前准备业绩证明文件 |

**6.2 合同条款风险**

| 条款 | 风险描述 | 应对措施 |
|-----|---------|---------|
| 付款条款 | [如：质保金X%扣3年] | 在澄清函/合同谈判阶段争取缩短 |
| 工期条款 | [如：工期紧张，日罚款X%] | 评估可行性，报价时计入风险成本 |
| 验收条款 | [如：验收标准模糊] | 在技术方案中自定义验收标准，形成合理预期 |
| 知识产权 | [如：要求全部著作权转让] | 评估对核心产品的影响 |

**6.3 竞争格局风险**

| 信号 | 判断 |
|-----|-----|
| 招标文件出现特定技术词汇（如某品牌专有名词） | 疑似定制，评估是否有申诉价值 |
| 业绩要求极高且门槛非常精准 | 排他性招标特征，慎重投入 |
| 资质要求多而杂，且仅少数企业能满足 | 定向竞争招标 |
| 控制价与市场价差距极大 | 预算不足，中标后风险高 |

**6.4 执行风险**

| 风险 | 评估 | 控制措施 |
|-----|-----|---------|
| 工期紧张 | [评估是否可实现] | 在技术方案中提前规划甘特图，证明可行 |
| 人员要求苛刻 | [是否有足够人员满足] | 提前落实人员，准备承诺函 |
| 预算偏低 | [是否有足够利润空间] | 精细成本估算，确认底线报价 |

### 第七步：专家决策建议（Expert Advisory）

> 超越信息整理，给出"老司机"级别的综合判断。

**7.1 综合竞标建议**

| 维度 | 评分（1-10） | 说明 |
|-----|------------|-----|
| 资质满足度 | X/10 | |
| 竞争优势 | X/10 | |
| 盈利预期 | X/10 | |
| 赢标概率 | X/10 | |
| 战略价值 | X/10 | |
| **综合建议** | **X/50** | **强烈推荐投/建议投/审慎评估/不建议投** |

**7.2 核心投标策略（3-5条）**

```
策略1：[如：技术方案重点突出XX创新点，争取技术标满分]
策略2：[如：组建联合体补充XX资质短板]
策略3：[如：报价区间XX万~XX万，预计竞争对手集中在XX万，建议报价XX万]
策略4：[如：答疑期提出XX条款异议，争取修改对我方有利的条件]
策略5：[如：提前与业主方技术部门沟通，了解真实需求偏好]
```

**7.3 时间轴与行动计划**

| 时间节点 | 行动项 | 负责人 |
|---------|------|------|
| 现在～答疑截止 | 组织技术团队读标、准备异议清单 | 技术负责人 |
| 答疑截止前X天 | 提交书面异议（如有） | 商务负责人 |
| 投标截止前X天 | 完成技术方案初稿 | 技术负责人 |
| 投标截止前X天 | 完成商务标/报价 | 商务负责人 |
| 投标截止前X天 | 全套文件合规性自查 | 质量负责人 |
| 投标当天 | 装订/封装/按时递交 | 全员 |

**7.4 不投/弃投决策依据（如适用）**

```
若存在以下情况，建议不投或弃投：
□ 资质存在重大缺口且无法通过联合体补足
□ 确认为"围标"项目（有明确证据）
□ 预算严重低于成本，无法实现合理利润
□ 工期要求不可实现，存在重大违约风险
□ 业主方信用记录差，有拖欠工程款历史
```

```
pm-tender-analysis → pm-bid-proposal 数据流：

解析报告模块               对应 pm-bid-proposal 步骤
─────────────────────────────────────────────────
废标风险扫描          →    Go/No-Go 决策输入
```

## 典型案例片段

### 案例：某智慧园区项目招标文件解析

**背景**：智慧园区综合管理平台，预算1500万，工期8个月

**快速扫描结果**：
- ✅ 等标期：25日（合规）
- ⚠️ 资质要求：要求"具有智慧城市领域近3年内2个及以上500万以上项目业绩"——"智慧城市领域"定义模糊，需在答疑期要求澄清是否包含智慧园区/智慧社区
- 🔴 陷阱：技术要求指定"XX品牌视频分析算法"——涉嫌品牌限制，建议提出异议

**专家建议**：
> 本项目资质条件存在可操作空间，业绩认定口径模糊对我方有利。但视频分析算法的品牌限制若无法通过答疑期取消，说明本项目存在明显定向性，需评估竞争对手是否为指定供应商，若是则建议弃投。技术方案应重点突出平台集成能力和本地化服务优势，而非追求技术指标的逐项响应。
