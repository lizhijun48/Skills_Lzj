# 质量保证与过程改进

## 角色定位

资深项目经理（PMP）兼一级建造师角色，专注于政府/国企项目的质量保证和过程改进。

核心任务：建立项目质量管理体系，执行质量审计确保过程合规，应用QC七大工具进行质量控制，管理质量成本，推动持续改进。每一步对标 PMBOK 第8章、软考高项第15章，同时融入一建实务中政府项目的质量管理经验（等保合规、隐蔽工程验收、第三方测试）。

> **与pm-procurement-quality的关系**：`pm-procurement-quality`是规划阶段的SKILL，负责"质量规划+采购管理"（制定质量标准、选择供应商）；本SKILL是执行/监控阶段的SKILL，负责"质量保证+质量控制+过程改进"（执行质量活动、检测偏差、持续改进）。规划阶段用`pm-procurement-quality`，执行阶段用本SKILL。

---\n\n## 工作流程（5 步）

### 第一步：质量保证体系建立

#### 1.1 项目质量体系架构

```
项目质量管理体系
├── 质量方针（对齐公司质量方针）
├── 质量目标（可量化、可追踪）
├── 组织架构
│   ├── QA经理（过程审计、质量体系维护）
│   ├── QC工程师（检测、测量、记录）
│   └── 测试经理（测试策略、测试执行）
├── 过程资产
│   ├── 质量检查清单
│   ├── 审计检查表
│   └── 缺陷分类标准
└── 度量体系
    ├── 过程度量（评审通过率/缺陷密度/返工率）
    └── 产品度量（功能覆盖率/性能达标率/安全合规率）
```

#### 1.2 QA vs QC vs 测试 的职责边界

| 角色 | 关注点 | 活动类型 | 时机 |
|------|--------|---------|------|
| **QA（质量保证）** | 过程是否合规 | 过程审计、检查、评审 | 贯穿全过程 |
| **QC（质量控制）** | 产品是否达标 | 测量、检测、验证 | 每个交付物 |
| **测试** | 功能是否正确 | 单元/集成/系统/验收测试 | 开发完成后 |

> **关键区别**：QA关注"过程对不对"（预防性），QC关注"结果好不好"（检测性），测试关注"功能行不行"（验证性）。

### 第二步：质量审计

#### 2.1 审计类型与频率

| 审计类型 | 频率 | 审计对象 | 输出 |
|---------|------|---------|------|
| **内部过程审计** | 每月/每Sprint | 项目过程合规性 | 审计报告+改进项 |
| **供应商质量审计** | 季度/里程碑 | 供应商交付质量 | 供应商评估报告 |
| **第三方合规审计** | 阶段性 | 等保/安全/法规合规 | 合规报告 |

#### 2.2 审计检查表模板

| 检查项 | 标准要求 | 实际情况 | 是否合规 | 不合规说明 |
|--------|---------|---------|---------|-----------|
| 需求评审是否执行 | 100%需求经过评审 | | ☐合规 ☐不合规 | |
| 代码评审覆盖率 | ≥80% | | ☐合规 ☐不合规 | |
| 测试用例评审 | 100%测试用例经过评审 | | ☐合规 ☐不合规 | |
| 变更是否走CCB | 100%变更经CCB审批 | | ☐合规 ☐不合规 | |
| 缺陷跟踪闭环率 | ≥95%缺陷已关闭 | | ☐合规 ☐不合规 | |
| 文档版本一致性 | 全部文档为最新版本 | | ☐合规 ☐不合规 | |

#### 2.3 政府项目特有审计

| 审计类型 | 法规依据 | 审计重点 | 不合规后果 |
|---------|---------|---------|-----------|
| **等保合规审计** | GB/T 22239 | 安全措施是否到位 | 不通过等保测评→无法上线 |
| **隐蔽工程验收** | 建设工程质量管理条例 | 管线/布线/接地 | 返工+工期延误 |
| **安全专项验收** | 安全生产法 | 安全设施"三同时" | 不通过→不予验收 |
| **软件合规性审计** | 招标文件/合同 | 功能完整性+数据安全 | 验收扣款 |

### 第三步：质量控制（QC七大工具实战）

#### 3.1 QC七大工具速查表

| 工具 | 用途 | 适用场景 | 政府项目实例 |
|------|------|---------|-------------|
| **因果图**（鱼骨图） | 找根因 | 缺陷原因分析 | 系统性能不达标→人机料法环 |
| **帕累托图** | 找主因 | 缺陷分类统计 | 80%缺陷来自20%模块 |
| **控制图** | 监控过程稳定性 | 重复性过程监控 | 代码缺陷密度趋势 |
| **检查表** | 数据收集 | 标准化记录 | 隐蔽工程检查表 |
| **直方图** | 分布分析 | 数据分布可视化 | 需求变更频率分布 |
| **散点图** | 相关性分析 | 两变量关系 | 代码复杂度vs缺陷数 |
| **分层图** | 数据分类 | 多维度对比 | 按模块/团队/阶段分层 |

#### 3.2 控制图实战规则

```
UCL (上限) ─────────────────────────────
           │    ╱╲    ╱╲
   CL (中心线) ──╱──╲╱──╲──╱──
           │╱            ╲
LCL (下限) ─────────────────────────────
```

**±3σ规则**：
- 点在控制线内 → 过程稳定（正常波动）
- 点超出控制线 → 过程失控（特殊原因）
- 7点连续上升/下降 → 趋势预警
- 7点在中心线同侧 → 偏移预警

#### 3.3 帕累托分析步骤

1. 收集缺陷数据（按类型/模块/阶段分类）
2. 计算各类频数和累计百分比
3. 绘制帕累托图（降序排列+累计曲线）
4. 识别80/20分界线（前20%类别贡献80%问题）
5. 针对关键少数制定改进措施

### 第四步：质量成本管理（COQ）

#### 4.1 质量成本四分类

| 类别 | 定义 | 典型项目 | 占比目标 |
|------|------|---------|---------|
| **预防成本** | 预防缺陷发生 | 培训、评审、QA活动、过程改进 | 15-25% |
| **鉴定成本** | 检测是否合规 | 测试、审计、检查、评审 | 20-30% |
| **内部故障成本** | 交付前发现缺陷 | 返工、回归测试、缺陷修复 | 25-35% |
| **外部故障成本** | 交付后发现缺陷 | 现场修复、投诉处理、合同罚款 | 10-20% |

#### 4.2 COQ优化策略

| 阶段 | 策略 | 预期效果 |
|------|------|---------|
| 项目前期 | 增加预防成本（评审、培训） | 减少故障成本30-50% |
| 项目中期 | 加强鉴定成本（测试、审计） | 尽早发现问题 |
| 项目后期 | 控制内部故障（快速修复） | 防止转化为外部故障 |
| 交付后 | 控制外部故障（快速响应） | 减少合同罚款和信誉损失 |

#### 4.3 政府项目COQ特殊考量

| 考量 | 说明 | 影响 |
|------|------|------|
| 等保合规 | 安全不合规=无法上线 | 预防成本必须包含安全评审 |
| 隐蔽工程 | 管线/布线必须100%检验 | 鉴定成本中隐蔽工程检查不可省 |
| 验收扣款 | 功能不完整=扣款 | 外部故障成本可能极高 |
| 审计追责 | 质量事故可能追责 | 外部故障成本=法律风险 |

### 第五步：持续改进

#### 5.1 PDCA循环

```
    ┌─── Plan（计划）───┐
    │  识别改进机会       │
    │  制定改进计划       │
    │  设定改进目标       │
    │                    ↓
    │  Act（行动）    Do（执行）│
    │  标准化成功做法   执行改进计划   │
    │  纳入过程资产     收集改进数据   │
    │                    ↑
    │  Check（检查）─────┘
    │  评估改进效果
    │  对比改进目标
    └── 确定下一步 ──────┘
```

#### 5.2 持续改进方法

| 方法 | 适用场景 | 周期 | 输出 |
|------|---------|------|------|
| **PDCA** | 通用过程改进 | 每Sprint/每月 | 改进措施+效果验证 |
| **Kaizen** | 小步持续改进 | 每周 | 微改进+累积效果 |
| **六西格玛DMAIC** | 重大质量问题 | 专项 | Define→Measure→Analyze→Improve→Control |
| **根本原因分析** | 重大缺陷/事故 | 触发时 | 5-Why分析+纠正措施 |

#### 5.3 质量改进度量

| 度量项 | 计算方法 | 目标值 | 监控频率 |
|--------|---------|--------|---------|
| 缺陷密度 | 缺陷数/千行代码 | ≤5 | 每Sprint |
| 缺陷修复率 | 已修复/总缺陷 | ≥95% | 每周 |
| 评审效率 | 发现缺陷数/评审人时 | ≥2 | 每次评审 |
| 返工率 | 返工工时/总工时 | ≤10% | 每月 |
| 测试覆盖率 | 已测功能/总功能 | ≥90% | 每Sprint |
| 等保合规率 | 合规项/总检查项 | 100% | 阶段性 |

## 使用示例

### 示例1：政府信息化项目质量审计

```
项目：XX市政务大数据平台
金额：3500万
触发：用户说"帮我做质量审计"

执行：
1. 建立质量体系 → 定义质量目标+QA组织+度量体系
2. 执行过程审计 → 6项检查，发现2项不合规：
   - 代码评审覆盖率60%（目标80%）→ 改进项
   - 变更CCB审批率85%（目标100%）→ 改进项
3. QC活动 → 帕累托分析发现80%缺陷集中在数据集成模块
4. COQ分析 → 内部故障成本占比40%（偏高），需增加预防成本
5. 改进措施 → PDCA：增加代码评审频率+数据集成模块专项测试

效果：下一个Sprint缺陷密度从8/千行降至4/千行
```

---

## 核心原则

1. **预防优于检测**：增加预防成本，减少故障成本，ROI最高
2. **QA关注过程，QC关注结果**：过程对了，结果自然对
3. **数据驱动改进**：不用"我觉得"，用度量指标说事
4. **控制图判定稳定性**：±3σ规则，超限即行动
5. **80/20法则优先**：帕累托图先解决关键少数
6. **等保合规不可妥协**：安全审计不通过=项目失败
7. **质量成本看总账**：预防+鉴定是投资，故障是浪费
8. **PDCA不停转**：每个Sprint都是改进循环
9. **自动化测试是质量底线**：单元测试覆盖率≥80%+集成测试+E2E测试构成质量门禁，人工测试仅覆盖自动化无法触达的场景
