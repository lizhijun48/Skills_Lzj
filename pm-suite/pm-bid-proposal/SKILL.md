# 招投标方案编制

## Metadata

- **Name**: pm-bid-proposal
- **Track**: JT（项目轨）
- **Phase**: P1（识别）+ P2（论证）+ P3（规划）+ P4（执行）+ P5（控制）
- **Crosscut**: CX-2（工程经济）、CX-5（组织与团队）
- **Standard Source**: PMP — Bid Management; 一建 — 招投标管理; 发改委55号令
- **Triggers**: 招投标, 投标, 招标, bid, bidding, tender, 标书, 标书撰写, 招标文件解析, 投标方案, 投标文件生成, 该不该投, 投标风险, 联合体投标

## 角色定位

资深项目经理（PMP）兼一级建造师（房建+机电）角色，专注于政府/国企项目的投标方案编制。

核心任务：从投标决策（该不该投）到方案编制（怎么投好）全流程覆盖，将招标文件转化为可中标的**技术方案 + 商务标 + 报价策略 + 述标方案**，每一步均对标《招标投标法》《政府采购法》及发改委55号令。

## 工作流程（8 步）

### 第零步：投标/弃标决策（Go/No-Go）

**ITTO 元数据**：
- **Input（输入）**：招标文件（完整）、公司资质/业绩/财务数据、竞争对手情报（如有）、预算约束、时间约束
- **Tools/Techniques（工具/技术）**：决策矩阵（5维度）、一票否决项检查表、战略价值评估模型
- **Output（输出）**：投标/弃标决策记录（含各维度评分、决策依据、后续行动建议）
- **Acceptance Criteria（验收标准）**：
  - [ ] 5个维度（资质匹配、胜率预估、投入产出比、战略价值、机会成本）均有评分
  - [ ] 一票否决项已逐项检查（硬性资质、法律障碍、投标成本）
  - [ ] 决策结论明确（Go/Conditional Go/Defer/No-Go）
  - [ ] 后续行动建议具体（如"寻找联合体伙伴"或"放弃并记录原因"）

**定位**：在投入大量资源编制投标方案之前，先判断"该不该投"。

**决策维度**：

| 维度 | 核心问题 | 评估指标 |
|------|---------|---------|
| ① 资质匹配 | 我方是否满足硬性门槛？ | 逐项对照资质、业绩、财务、认证要求 |
| ② 胜率预估 | 综合来看中标概率多高？ | 技术匹配度、商务优势、客户关系基础 |
| ③ 投入产出比 | 投标成本 vs 预期收益？ | 投标人力/资金投入、预期合同额、毛利率 |
| ④ 战略价值 | 即使亏本也值得投吗？ | 市场准入、标杆案例、后续项目机会 |
| ⑤ 机会成本 | 投这个标会占用什么资源？ | 是否影响其他更高价值项目、核心人员是否可调配 |

**决策矩阵**：

| 维度综合评分 | 决策 | 行动 |
|------------|------|------|
| 资质全部满足 + 胜率 ≥ 40% + 投入产出合理 | **Go** | 全力投入投标方案编制 |
| 资质部分不满足但可通过联合体补 + 胜率 30%-40% | **Conditional Go** | 寻找联合体伙伴，补齐短板后投入 |
| 资质满足但胜率 < 30% + 无战略价值 | **Defer** | 暂缓，关注后续同类项目 |
| 资质不满足且无法联合体补 | **No-Go** | 放弃，记录原因归档 |

**投标委员会线下决策触发规则**：

| 触发条件 | 必须组织线下会议 | 会议输出 |
|---------|----------------|---------|
| 决策为 Conditional Go（需联合体） | ✅ | 联合体伙伴选择决议 + 分工方案 |
| 项目金额 ≥ 1000万 | ✅ | 投标决策纪要 + 资源承诺 |
| 战略级项目（市场准入/标杆案例） | ✅ | 投标决策纪要 + 特殊资源调配 |
| 决策存在分歧（不同维度评分矛盾） | ✅ | 最终决策决议（记入会议纪要）|
| 常规项目（金额 < 500万，Go明确） | ❌ | 线上确认即可 |

> 📝 **决议录入规则**：会议结束后，必须将"最终决策结论"和"后续行动项"以纪要形式归档。严禁"线上甩锅"——复杂项目的决策必须有书面纪要作为依据。

**一票否决项**（任一触发即No-Go）：
- 硬性资质不满足且无法通过联合体解决
- 存在法律障碍（如：被列入失信被执行人、行政处罚期内）
- 投标成本超过预期合同额的5%且无战略补偿价值

**输出**：投标/弃标决策记录（含各维度评分和决策依据）

**弃标管理闭环**（当决策为 No-Go 或 Defer 时强制执行）：

| 步骤 | 动作 | 输出 |
|------|------|------|
| 1. 形成弃标说明 | 写明"为什么不做"：资质缺口/技术不可行/风险不可控/投入产出不合理 | `references/弃标说明模板.md`（新增）|
| 2. 线下会议纪要 | **严禁线上甩锅**：组织投标委员会线下会议，形成决议纪要 | 会议纪要（归档）|
| 3. 必须留痕 | 弃标说明 + 会议纪要一并归档，避免后续扯皮 | 归档记录 |
| 4. 定期复审 | 若项目为 Defer（暂缓），设置 30 天后自动提醒重新评估 | 待办提醒 |

> ⚠️ **严禁"死扛"**：一旦在 Go/No-Go 阶段发现技术无法实现或风险不可控，立刻启动弃标流程。盲目投标不仅浪费资源，还会损害公司信誉。

### 第一步：招标文件解读（含多模态视觉理解）

**ITTO 元数据**：
- **Input（输入）**：招标文件（完整，支持文本/PDF/扫描件/工程图纸/现场照片）、招标公告、补遗/澄清文件
- **Tools/Techniques（工具/技术）**：结构化拆解模板（三类条款）、评分标准拆解公式、时间节点合规核查表、**多模态视觉理解（OCR + 表格结构识别 + 图纸解析）**
- **Output（输出）**：招标文件解读报告（含硬性门槛清单、评分标准拆解、关键条款识别、时间节点合规核查、**扫描件/图纸解析结果**）
- **Acceptance Criteria（验收标准）**：
  - [ ] 硬性门槛（5项）逐项核查并标注满足状态
  - [ ] 评分标准拆解完整（技术分/商务分/价格分 + 各分项子项）
  - [ ] 关键条款识别完整（付款条件、工期要求、技术偏离表、废标条款）
  - [ ] 时间节点合规核查完整（招标文件发售期、等标期、中标公示期）
  - [ ] 所有风险提示均引用招标文件原文位置/条款
  - [ ] **多模态输入已处理**：扫描件OCR文字识别完整、工程图纸/工程量清单截图表格结构已还原为可编辑格式

**1.0 多模态视觉理解（新增能力）**

当用户上传非文本文件（扫描件、工程图纸、现场照片、模糊截图）时，自动启用视觉理解能力：

| 输入类型 | 处理方式 | 输出格式 | 适用场景 |
|---------|---------|---------|---------|
| 扫描版招标文件（PDF/图片） | OCR文字识别 + 版面分析 | 结构化 Markdown（保留原章节结构） | 招标文件为扫描件，无法复制文字 |
| 工程量清单截图（模糊/拍照） | OCR + 表格结构识别（行列检测） | `references/工程量清单_标准格式.md`（标准表格） | 用户只有手机拍照的清单截图 |
| 工程图纸（平面图/系统图） | 图像识别 + 关键参数提取（面积/层数/系统组成） | 项目关键参数摘要表 | 招标图纸为图片格式，无法直接解析 |
| 现场照片（踏勘照片） | 图像内容识别 + 施工条件判断 | 现场条件摘要（空间/电力/网络/环境约束） | 投标准备阶段的现场踏勘 |

**处理流程**：
```
Step 1: 接收文件 → 判断文件类型（文本/扫描件/图纸/照片）
Step 2: 文本 → 直接结构化拆解
        扫描件 → OCR识别 → 版面还原 → 结构化拆解
        图纸/照片 → 视觉理解 → 关键参数提取 → 标准化输出
Step 3: 输出统一格式的招标文件解读报告
```

> ⚠️ **OCR 精度说明**：识别结果需人工复核关键数字（金额、面积、工期），AI 识别错误率约 2%-5%，关键数据必须以招标文件原始文字版为准。

对招标文件进行结构化拆解，重点关注三类条款：

**1.1 硬性门槛（一票否决项）**

| 检查项 | 招标要求 | 我方状态 |
|--------|---------|---------|
| 企业资质 | 如：电子与智能化一级 | ✅/❌/⚠️需联合体 |
| 项目经理资质 | 如：一建（机电） | ✅/❌ |
| 同类业绩 | 如：近3年1000万+项目≥2个 | ✅/❌ |
| 财务要求 | 如：营收≥5000万/年 | ✅/❌ |
| 认证要求 | 如：ISO9001、CMMI3 | ✅/❌ |

**任一项不满足且无法通过联合体解决 → 建议放弃投标。**

**1.2 评分标准拆解**

→ 详细评标方法及评分公式见 `references/评标方法详解.md`

```
总分 = 技术分（XX%）+ 商务分（XX%）+ 价格分（XX%）

技术分拆解：
- 技术方案（XX分）：完整性、先进性、可落地性
- 项目团队（XX分）：项目经理资质、核心人员配置
- 企业业绩（XX分）：同类项目数量、规模
- 售后服务（XX分）：响应时间、驻场承诺、质保期
```

**1.3 关键条款识别**

- 付款条件：预付款比例、里程碑节点、质保金比例
- 工期要求：是否合理？有无罚款条款？
- 技术偏离表：哪些条款可以正偏离？
- 废标条款：哪些情况直接废标？（对照 `references/招标投标法规依据.md` 关键红线；常见废标原因详见 `references/常见废标原因清单.md`）

**1.4 时间节点合规核查**

拿到招标文件后，必须立即核查以下时间节点是否符合法定要求，发现违规立即向招标方提出异议（投标截止前10日内提出方为有效）：

| 核查项 | 法定要求 | 招标文件写的 | 是否合规 |
|--------|---------|-----------|---------|
| 招标文件发售期 | ≥5日 | | ✅/❌ |
| 等标期（依法必须招标工程） | ≥20日 | | ✅/❌ |
| 等标期（政采货物/服务公开招标） | ≥20日 | | ✅/❌ |
| 中标候选人公示期 | ≥3日 | | ✅/❌ |

> ⚠️ "工作需要、时间紧急"不构成缩短等标期的合法理由。时间合规性判断三步法及各类型等标期完整下限（竞争性谈判≥3工作日、磋商≥10日、公路投资≥45工作日等），详见 `references/招标投标法规依据.md` 中"招投标时间约束标准库"章节。

### 第二步：竞争分析

**ITTO 元数据**：
- **Input（输入）**：招标文件（评分标准）、已知竞争对手信息、我方优劣势分析、历史中标数据（如有）
- **Tools/Techniques（工具/技术）**：对手画像模板、胜负手分析模型、报价博弈矩阵
- **Output（输出）**：竞争分析报告（含对手画像、胜负手分析、报价模拟）
- **Acceptance Criteria（验收标准）**：

### 第五步：报价策略（含蒙特卡洛模拟）

**ITTO 元数据**：
- **Input（输入）**：成本底线（硬件+软件+实施+管理费+税费+风险预留）、目标毛利、竞争对手报价预估、招标控制价、**历史中标数据（过去50次同类项目）**

- **Output（输出）**：报价策略报告（含成本底线、目标毛利、报价区间、对抗性模拟结果、**中标概率分布曲线**）
- **Acceptance Criteria（验收标准）**：
  - [ ] 成本底线已完整计算（含软件FPA估算）
  - [ ] 报价区间已确定（最高价=预算×0.95，最低价=成本底线×(1+最低毛利率)）
  - [ ] 价格分模拟已完成（预测对手报价→模拟评分→找到最优出价点）
  - [ ] **蒙特卡洛模拟已完成**：基于历史数据生成中标概率分布曲线，预测对手可能的狙击价位

**5.1 四步决策**

→ 详细报价公式、博弈模型和定价策略见 `references/报价决策公式与模型.md`

```
第一步：确定成本底线
  硬件成本 + 软件成本 + 实施成本 + 管理费 + 税费 + 风险预留 = 总成本

  **软件成本估算**：
  软件项目使用功能点分析（FPA）或类比估算确定开发成本，参照 `pm-project-opportunity` 技能的 `references/软件项目估算方法.md`：
  ├── 人力成本 = 功能点数 × 生产率（人月）× 人月单价
  ├── 第三方 License/订阅（数据库、中间件、API 服务）
  ├── 云资源成本（IaaS/PaaS/SaaS，按年报价）
  └── 安全合规成本（等保测评、渗透测试、证书费用）

第二步：确定目标毛利
  ToG项目通常 15%-30%（考虑：竞争激烈度、后续机会、战略价值）

第三步：确定报价区间
  最高价 = 预算上限 × 0.95
  最低价 = 成本底线 × (1 + 最低可接受毛利率)
  目标价 = (最高价 + 最低价) / 2 × 调整系数（K）

第四步：对抗性报价模拟
  预测对手报价 → 模拟评分 → 找到最优出价点
```

**5.2 价格分模拟（示例）**

```
假设公式：价格分 = 基准价/报价 × 满分（基准价为有效报价均值）

我方 1800万 vs 对手A 2100万 vs 对手B 1550万
→ 基准价 = 1817万
→ 我方价格分 = 1817/1800 × 30 = 30.28
→ 对手A价格分 = 1817/2100 × 30 = 25.96
→ 对手B价格分 = 1817/1550 × 30 = 35.17

结论：若技术分能拉开与B的差距，1800万是合理报价
```

**5.3 蒙特卡洛模拟（调用 tools-monte-carlo）**

> 将报价策略从"合规助手"升级为"博弈军师"：用概率分布替代确定性计算，预测对手可能的狙击价位。

**原理解读**：基于过去 N 次同类项目的中标数据，通过随机抽样模拟 thousands 次投标场景，输出中标概率分布曲线。

**本步骤不再展开蒙特卡洛细节，改为调用通用工具**：

```
→ 调用 tools-monte-carlo skill，传入以下参数：

variables:
  - name: 我方报价下浮率
    distribution: normal
    params: {mu: 6.2%, sigma: 1.8%}
    bounds: [3%, 12%]

  - name: 对手A报价下浮率
    distribution: normal
    params: {mu: 8.1%, sigma: 2.2%}
    bounds: [3%, 15%]

  - name: 对手B报价下浮率
    distribution: normal
    params: {mu: 4.5%, sigma: 1.1%}
    bounds: [3%, 10%]

  - name: 控制价下浮率
    distribution: uniform
    params: {low: 3%, high: 10%}

objective_function:
  我方得分 = 技术分_我方 + 商务分_我方 + 价格分(我方报价, 所有报价)
  是否中标 = (我方得分 == MAX(所有方得分))

trials: 10000
confidence_level: 0.95
output_format: [chart, table]
```

**tools-monte-carlo 输出内容（直接用于本报告）**：

| 输出项 | 用途 |
|---------|------|
| 中标概率分布曲线图（PNG/SVG）| 找到最优下浮率区间 |
| 统计分析表（P10/P50/P90）| 报告正文引用 |
| 敏感性分析图 | 识别最关键变量（通常是控制价下浮率）|
| 解读文本 | 直接呈现给用户 |

**解读要点（由本 skill 根据 tools-monte-carlo 输出填写）**：

- 最优下浮率区间：______%（中标概率 ≥ 70%）
- 对手A狙击价位预测：下浮 ______%
- 对手B保守报价区间：下浮 ______%
- 风险提示：若对手A极端压价（下浮>10%），我方中标概率降至 ______%

> 📊 **图表生成说明**：tools-monte-carlo 会调用多模态图表能力，生成三张图：
> 1. 概率密度分布图（PDF）— X轴=我方下浮率，Y轴=中标概率密度
> 2. 累积概率曲线图（CDF）— 回答"下浮X%时，中标概率多少？"
> 3. 敏感性分析图（Tornado样式）— 识别对中标概率影响最大的变量

**5.4 博弈系数 K 的贝叶斯更新（调用 tools-bayesian-update）**

> 报价博弈系数 `K` 的历史数据积累后，通过贝叶斯更新实现动态进化。本步骤不再展开计算公式，改为调用通用工具。

```
→ 调用 tools-bayesian-update skill，传入以下参数：

prior_params:
  mu_old: 1.00      # K 的先验均值（中性）
  sigma_old: 0.10    # 先验标准差（初始不确定）

observations:
  - K_used: 1.00, 是否中标: 是
  - K_used: 0.95, 是否中标: 否
  - K_used: 1.05, 是否中标: 是
  - K_used: 1.02, 是否中标: 是
  - K_used: 0.98, 是否中标: 否

likelihood_model: normal   # K 近似服从正态分布
prior_type: normal

→ 预期输出（来自 tools-bayesian-update）：
  - 后验 μ_new, σ_new
  - K 的推荐区间（μ ± 1σ）
  - 下次投标的 K 使用建议
```

**tools-bayesian-update 输出解读（由本 skill 填写到报告中）**：

| 项目 | 内容 |
|------|------|
| 后验 K 均值 | ______（通常向"历史中标时使用的 K 均值"靠拢） |
| 后验 K 置信区间 | [______, ______]（μ ± 1σ） |
| 下次建议 K 值 | ______（取 μ，或根据项目类型微调） |
| 模型可信度 | σ < 0.05 → 高；σ ≥ 0.05 → 需更多数据 |

**6.3 POC/Demo 演示策略（软件项目）**

软件项目投标中，技术演示是核心胜负手。述标阶段的 Demo 质量往往直接决定技术分高低。

**POC 决策矩阵**：

| 条件 | 是否做 POC | 说明 |
|------|----------|------|
| 技术分占比 ≥ 50% + 有可演示的现成产品 | **强烈建议** | 演示实际产品效果远超PPT |
| 技术分占比 30%-50% + 关键功能可快速搭建 | **选择性做** | 优先做核心功能点的Demo |
| 技术分占比 < 30% 或纯硬件集成项目 | 不做 | 投入产出比不高 |

**Demo 搭建流程**（由工程师寇豆码执行）：

1. **需求筛选**（PM）：从招标需求中选出3-5个最适合演示的功能点
   - 标准：视觉冲击力强 + 技术难度适中 + 2周内可搭建
2. **原型搭建**（工程师）：
   - 使用公司现有产品/平台作为底座
   - Mock 数据填充（最接近真实场景）
   - 确保离线可运行（防止现场网络问题）
3. **演示脚本设计**（PM + 述标人）：
   - 演示顺序：问题场景 → 解决方案展示 → 效果对比
   - 每个演示点控制在2-3分钟
   - 准备"好->更好"演进路径（先展示基本功能，再展示差异化能力）
4. **演示风险管控**：
   - 准备本地离线版本（防止网络不通）
   - 准备录屏视频作为备用（防止Demo崩溃）
   - 带2套设备（防止硬件故障）
   - 准备快速跳过流程（评委问题太多时的应对）

**演示分检查清单**（述标前24小时确认）：

- [ ] Demo 系统已在述标设备上完整部署并测试
- [ ] 离线版本已验证可正常运行

- [ ] 备用设备已准备（笔记本/平板）

**定位**：识别投标全流程中的风险点，制定预案，防止"投标出错"和"中标后出事"。

**7.1 投标阶段风险清单**

| 风险类别 | 具体风险 | 后果 | 预防措施 | 应急方案 |
|---------|---------|------|---------|---------|
| **废标风险** | 投标文件不完整（缺页、漏签、漏章） | 直接废标 | 编制投标文件清单，逐项打勾；独立复核人制度 | 投标截止前24小时完成终审 |
| **废标风险** | 报价超过招标控制价 | 直接废标 | 报价前核算控制价，留5%安全边际 | 发现超价立即调整分项报价 |
| **废标风险** | 未按要求密封/递交 | 直接废标 | 按招标文件要求逐项检查封装 | 投标截止前2小时送达现场 |
| **资质风险** | 联合体资质不满足 | 资格审查不通过 | 联合体协议签订前逐项核对资质 | 提前准备备选联合体伙伴 |
| **资金风险** | 投标保证金未按时到账 | 废标 | 提前3个工作日办理保证金 | 准备银行保函替代现金 |
| **资金风险** | 保证金退还条件苛刻 | 资金占用 | 投标前确认退还条件 | 优先选择银行保函形式 |
| **法律风险** | 串通投标 | 取消资格+罚款+刑事 | 绝对红线，投标过程独立封闭 | — |
| **法律风险** | 业绩材料虚假 | 取消资格+列入黑名单 | 所有业绩必须真实可查 | — |
| **联合体风险** | 联合体方违约导致投标失败 | 投标无效 | 联合体协议明确违约责任 | 联合体协议中加入违约金条款 |
| **联合体风险** | 联合体方中标后不履约 | 连带赔偿责任 | 联合体协议明确分工和责任 | 联合体协议中加入履约保证金 |

**7.2 中标后风险清单**

| 风险类别 | 具体风险 | 后果 | 预防措施 |
|---------|---------|------|---------|
| **合同风险** | 招标文件条款与合同条款不一致 | 履约争议 | 投标前审查合同草案，标注风险条款 |
| **合同风险** | 预付款比例过低导致资金链紧张 | 项目执行困难 | 报价中计入资金成本；投标前评估现金流 |
| **履约风险** | 中标后无法按期交付 | 违约金+信用损失 | 投标前评估交付能力，不承诺做不到的工期 |
| **质保风险** | 质保期过长（如5年） | 长期维护成本 | 报价中计入质保期维护成本 |

**7.3 投标风险自查清单（投标递交前必须逐项确认）**

- [ ] 所有硬性资质要求逐项满足
- [ ] 投标文件每页盖章/签字完整
- [ ] 报价未超过招标控制价
- [ ] 投标保证金已按时足额到账
- [ ] 业绩材料真实可查（业主、金额、时间均可核实）
- [ ] 联合体协议已签署且明确分工
- [ ] 投标文件密封符合招标文件要求
- [ ] 递交时间预留充足余量（至少提前2小时）

### 第八步：联合体投标

**ITTO 元数据**：
- **Input（输入）**：招标文件（资质要求）、我方资质缺口、潜在联合体伙伴清单、联合体协议草案
- **Tools/Techniques（工具/技术）**：联合体适用判断矩阵、伙伴选择评分模型（5维度）、联合体协议核心条款模板（7条）、联合体投标检查清单（7项）
- **Output（输出）**：联合体投标方案（含伙伴选择建议、协议条款、分工界面、检查清单）
- **Acceptance Criteria（验收标准）**：
  - [ ] 联合体适用判断已完成（是否需要联合体）
  - [ ] 伙伴选择评分已完成（5维度加权评分）
  - [ ] 联合体协议核心条款已填写（7条）
  - [ ] 联合体投标检查清单已确认（7项）

**定位**：当单一投标人无法满足招标资质要求时，通过联合其他企业组成联合体进行投标。

**8.1 联合体适用判断**

| 触发条件 | 是否需要联合体 |
|---------|-------------|
| 某一硬性资质不满足（如无电子与智能化一级资质） | **需要** |
| 技术能力覆盖不足（如AIoT项目我方缺AI能力） | **建议** |
| 业绩数量/规模不足 | **建议** |
| 本地化服务要求（外地公司需要本地服务团队） | **可选** |
| 全部资质和业绩独立满足 | 不需要 |

**8.2 联合体伙伴选择标准**

| 评估维度 | 权重 | 评估要点 |
|---------|------|---------|
| 资质互补性 | 30% | 是否能补齐我方缺失的硬性资质？ |
| 技术互补性 | 25% | 是否能补齐我方技术短板？ |
| 信誉风险 | 20% | 是否有投标不良记录？是否有履约纠纷？ |
| 配合度 | 15% | 过往合作经验？沟通效率？ |
| 报价竞争力 | 10% | 联合体报价是否会抬高总价？ |

**8.3 联合体协议核心条款**

1. **牵头方约定**：明确谁为牵头单位，负责投标文件的编制和递交
2. **分工界面**：技术方案分工（各承担哪些建设内容）、商务责任划分
3. **投标保证金**：各方承担的投标保证金比例
4. **中标后履约**：合同签订主体、项目实施分工、质保责任划分
5. **收益分配**：合同金额在各成员间的分配比例
6. **违约责任**：任一方违约导致投标失败的赔偿责任
7. **连带责任**：根据《招标投标法》第31条，联合体各方就中标项目向招标人承担**连带责任**

**8.4 联合体投标检查清单**

- [ ] 联合体各方资质满足招标文件要求（逐项核对）
- [ ] 联合体协议已签署（加盖各方公章）
- [ ] 联合体协议中分工明确，边界清晰
- [ ] 牵头方已获得其他各方的授权委托书
- [ ] 联合体协议中包含连带责任条款
- [ ] 各方业绩材料已准备并在有效期内
- [ ] 联合体各方的投标保证金出资比例已确认

## 投标项目执行计划（里程碑管理）

> **定位**：在 Go/No-Go 决策通过后、正式进入方案编制前，制定项目级的执行计划与里程碑节点。确保标书编制、审核、封装全流程有序进行，避免"最后一刻赶工"导致质量事故。

### 计划制定规则

**输入**：投标截止时间（截标时间）+ 当前时间 + 项目复杂度（金额/战略级别）

**里程碑倒推公式**：

```
截标时间（T）= 招标文件规定的投标截止日期和时间

T-3天：技术标初稿 + 商务标初稿完成
T-2天：报价策略定稿 + 标书整合完成
T-1天：四级审核完成 + 定稿签字盖章
T-0天（截标当天）：
  - 电子标：提前2小时完成上传，预留平台故障应急时间
  - 线下标：提前2小时送达开标现场，预留交通意外缓冲

特殊规则：
  - 金额 ≥ 500万 或 战略级项目：T-1天须完成分管领导审核（四级审核完整触发）
  - 电子标：T-0天上午完成上传（避免下午平台拥堵）
  - 需现场述标：T-0天上午抵达现场城市（避免航班延误风险）
```

### 项目启动检查清单

| 检查项 | 责任人 | 完成标志 |
|--------|--------|---------|
| 组建投标项目组（项目经理+技术负责人+商务专员+排版员） | 销售/商务主管 | 项目群已建立，成员角色明确 |
| 招标文件已上传至共享目录 | 项目经理 | 文件可全员访问 |
| 截标时间已录入项目日历（含提前提醒） | 项目经理 | 日历提醒已设置 |
| 标前答疑问题清单已整理并提交 | 技术负责人 | 答疑函已发出 |
| 联合体协议（如需）已启动签署流程 | 商务专员 | 协议草案已草拟 |

### 动态审核层级规则

标书审核不是"一刀切"，根据项目复杂度动态调整审核深度：

| 项目类型 | 审核层级 | 触发条件 |
|---------|---------|---------|
| 常规项目（金额 < 500万，非战略级） | 三级审核 | 自审 → 二审（主管）→ 三审（部门经理）|
| 重大项目（金额 ≥ 500万 或 战略级） | **四级审核** | 三级审核 + 分管领导审核 |
| 紧急项目（等标期 < 15天） | 三级审核 + 并行 | 自审与二审并行，三审不跳过 |
| 联合体投标项目 | 四级审核 | 联合体各方分别审核各自负责部分，再统一整合审核 |

> 📝 **分管领导审核触发阈值**：金额阈值可在 `references/投标审核规则配置.md` 中根据公司实际情况调整。战略级项目的判断标准：市场准入项目 / 标杆案例项目 / 后续项目机会 ≥ 3个。

### 标书封装与递交 SOP

| 步骤 | 动作 | 风控要点 |
|------|------|---------|
| 1. 打印 | **最后打印报价单**（防泄密：报价在打印前最后一刻确定） | 打印后立即封存，仅限授权人员接触 |
| 2. 装订 | 胶装，封面用招标规定颜色/材质 | 检查页码连续性，避免缺页 |
| 3. 签字盖章 | 逐页小签 + 骑缝章 + 法人章 | 对照招标文件要求逐项检查（每页章/签字位置） |
| 4. 密封 | 按招标文件要求封装（正本/副本数量、密封袋要求） | 封条盖骑缝章，密封袋外标注项目名称 |
| 5. 电子标上传 | 生成加密文件，在截标前2小时完成上传 | 上传后下载回执，确认平台已接收 |
| 6. 线下递交 | 提前2小时送达，保留送达凭证 | 交通路线备选方案已准备 |

## 使用示例

```

     对手A：本地公司，技术弱但关系硬，预计报价1100万。

输出：
0. 投标决策 → Go（资质全满足，胜率45%，投入产出合理）

2. 项目类型 → AIoT平台，加载模板二 AIoT架构
3. 胜负手：技术方案碾压A、案例多于B但价格居中

9. 中标后交接：投标承诺→软件团队（架构师/工程师/QA）移交清单已生成
10. 中标概率：中等偏高（55%）
```

## 中标后衔接

投标中标后，项目进入交付阶段。投标方案的承诺构成项目交付的基线：

| 投标产出 | 交付阶段的用途 | 消费方 |
|---------|--------------|---------|
| 投标技术方案 | 项目执行的基准方案（范围基线） | 架构师 + PM |
| 投标报价 | 项目成本基线的起点 | 主理人 |
| 投标风险预案 | 交付阶段风险管理的输入 | QA工程师 |
| 述标承诺 | 客户期望管理的基础 | PM |
| POC/Demo原型 | 代码基线，避免从零开发 | 工程师 |
| 运维SLA承诺 | 运维监控基线 | SRE |

> **衔接规则**：中标后须按"与软件开发团队的协作接口"章节的检查清单，将全套投标文件移交软件团队，进行合同交底，确保投标承诺→交付基线的无缝衔接。

## 禁止内容铁律

> 本规则为**绝对红线**，投标文件（含技术方案、商务标、报价文件）中**严格禁止**出现以下内容：

| 禁止内容 | 说明 | 后果 |
|---------|------|------|
| 中标概率预测 | 如"中标概率55%"、"预计中标可能性较高" | 视为串通投标或内部评分，直接废标 |
| 匹配度自评 | 如"匹配度90%"、"完全符合招标要求" | 被视为虚假响应，取消资格 |
| 竞争对手分析 | 如"对手A技术较弱"、"我方比B公司优势明显" | 被视为不正当竞争，取消资格 |
| AI 生成标注 | 如"由AI生成"、"AI辅助撰写" | 被视为非人工撰写，不符合招标文件要求 |
| 内部策略词 | 如"高分响应"、"满分策略"、"必得满分" | 暴露内部评分策略，被视为串通投标 |
| 样例标书残留 | 其他项目名称、地点、特定产品型号、工期或报价 | 被视为抄袭，直接废标 |

**检查清单**（投标文件输出前必须逐项确认）：

- [ ] 全文不含"中标概率"、"匹配度"、"得分预测"等自评内容
- [ ] 全文不含竞争对手名称或对比分析
- [ ] 全文不含"AI"、"人工智能生成"等标注
- [ ] 全文不含"高分"、"满分"、"必得"等内部策略词

- [ ] 项目名称、编号、采购人、地点、服务期限和关键数字全文统一

## 核心原则

1. **先决策再投入**：投标前先过Go/No-Go决策，避免在不可投标项目上浪费资源
2. **资质第一**：投标前逐项核对资质门槛，一项不满足且无法联合体解决即建议放弃
3. **废标条款是绝对红线**：对照 `references/招标投标法规依据.md` 关键红线逐项检查
4. **技术方案须具体**：每个功能模块说明"解决什么问题"，不泛泛而谈；软件项目加载对应架构模板
5. **报价须有依据**：从立项阶段的初设概算和详细设计工程量清单出发；软件项目使用功能点/类比估算
6. **风险须有预案**：投标前识别废标风险、资金风险、法律风险，制定预防和应急措施
7. **软件项目须差异化**：技术方案加载架构模板，售后服务使用软件运维模板，述标配合POC/Demo策略
8. **交接须标准化**：中标后按软件团队协作接口，确保投标成果可被架构师/工程师/QA直接消费
9. **若招标文件信息不完整**：先输出可做的部分，标注缺失项

## 第十一步：投标复盘与学习闭环（动态反馈闭环 — 进阶能力）

> **定位**：将每次投标的"中标/未中标结果"转化为"下一次投标的竞争优势"。这是本 Skill 从"规则引擎"升级为"自我进化系统"的核心机制。

### 11.1 复盘触发时机

| 触发时机 | 必须执行动作 | 输出 |
|---------|---------|------|
| **中标** | 执行 11.2（中标复盘）→ 11.4（模型更新）| 中标复盘报告 + 模型更新记录 |

### 11.2 中标复盘流程

**目标**：提炼"为什么赢了"，将成功要素固化到对手画像模型和报价博弈系数中。

**Step 1：回溯投标时的关键决策**

| 决策项 | 投标时判断 | 实际结果 | 偏差分析 |
|---------|---------|---------|---------|
| 竞争分析（第二步） | 对手A预估报价1100万，胜率45% | 对手A实际报价1080万，我方胜出 | ✅ 预估准确 |
| 报价策略（第五步） | 推荐报价1180万，下浮6.5% | 实际报价1180万，价格分28.5 | ✅ 报价合理 |
| 技术方案亮点 | 3个差异化亮点（AI预测维护等） | 技术分全场最高 | ✅ 亮点命中评委偏好 |
| 胜负手判断 | 技术方案碾压A，价格居中压制B | 实际：技术分领先第二名12分 | ✅ 判断正确 |

**Step 2：对手画像模型更新**

```
对手A画像更新（基于本次投标数据）：
  - 报价偏好：下浮率 8.1%（本次8.0%）→ 更新为偏激进（μ=8.0%, σ=1.8%）
  - 技术短板：AI算法能力弱（本次技术方案得分落后12分）→ 标记"AI能力弱"
  - 关系优势：业主倾向明显（但技术分差距过大未起效）→ 标记"关系强硬但技术弱势时可被翻盘"
  - 下次相遇策略：技术方案必须拉开10分以上差距，价格可适当激进（下浮7%-9%）

对手B画像更新：
  - 报价偏好：下浮率 4.5%（本次4.8%）→ 偏保守（μ=4.6%, σ=1.0%）
  - 技术特点：标准化方案，无差异化亮点 → 标记"技术方案可预测"
  - 下次相遇策略：价格压制有效（我方价格分高于B 5.2分），可继续压制
```

**Step 3：报价博弈系数 K 更新**

```
K_new = K_old × 修正系数

本次结果：中标，价格分28.5（全场第2），技术分全场最高
→ 判断：报价策略合理，无需大幅调整

修正系数计算：
  - 对手A报价激进（下浮8.0%）但未中标 → A的激进策略在本类项目中效果有限
  - 我方下浮6.5%，价格分第2 → 报价策略有效
  → 修正系数 = 1.0（保持不变）

特殊调整：
  - 若下次再遇对手A：K += 0.05（A激进，我方适当跟进）
  - 若下次再遇对手B：K -= 0.03（B保守，我方可适当压制）
```

**Step 4：成功要素沉淀**

- [ ] 本次技术方案的**优秀章节**已提取，存入 `references/优秀章节库.md`
- [ ] 本次**差异化亮点**已记录，存入 `references/亮点模板库.md`
- [ ] 本次**述标PPT**的高效表达已记录，存入 `references/述标策略库.md`
- [ ] 本次**Demo演示**的评委反馈已记录，更新 `references/Demo最佳实践.md`

### 11.3 未中标复盘流程

**目标**：分析"为什么输了"，找到可改进的痛点，更新对手画像和报价模型。

**Step 1：未中标原因分析（五维度）**

| 维度 | 我方得分 | 第一名得分 | 差距 | 根本原因 |
|---------|---------|---------|------|---------|
| 技术分 | 78.5 | 85.2 | -6.7 | 方案亮点不够突出，架构图不够清晰 |
| 商务分 | 18.0 | 19.5 | -1.5 | 业绩案例数量够但相关性弱 |
| 价格分 | 30.2 | 28.8 | +1.4 | 价格分占优，但未能弥补技术分差距 |
| **总分** | **126.7** | **133.5** | **-6.8** | — |

**Step 2：关键失误回溯**

| 失误项 | 投标时判断 | 实际结果 | 改进方向 |
|---------|---------|---------|---------|
| 对手A报价预判 | 预估1100万（下浮8%） | 实际1050万（下浮10%） | ❌ 低估了A的激进程度 → 下次A的报价分布 σ 调大 |
| 技术方案定位 | 强调"先进性"（AI算法） | 评委更看重"可落地性" | ❌ 技术方案偏离业主真实需求 → 需加强招标文件解读中的"业主偏好识别" |
| 述标策略 | Demo演示占比40% | 评委更关注"类似案例" | ❌ Demo投入过高但未得分 → 述标时间分配需调整 |

**Step 3：对手画像模型更新（基于失败数据）**

```
对手A画像更新（基于本次投标数据）：
  - 报价偏好：下浮率 10.0%（本次10.0%）→ 极激进（μ=9.2%, σ=2.5%）
  - 技术特点：标准化方案但可落地性强（本次技术分85.2，全场最高）
    → 之前标记"技术弱"有误，需修正为"技术方案可落地性强"
  - 下次相遇策略：
    - 价格战无法打赢A（A可下浮10%以上）→ 避免价格战
    - 必须在技术上升级：增加"可落地性"证明（试点案例、运行数据）
    - 若预算允许：寻找联合体伙伴补齐短板
```

**Step 4：报价博弈系数 K 更新**

```
K_new = K_old × 修正系数

本次结果：未中标，价格分30.2（全场第1），但技术分落后6.7分
→ 判断：报价过于保守（追求价格分），但技术分差距过大

修正系数计算：
  - 对手A下浮10%仍中标 → 说明本项目价格分权重低（30%），技术分才是决胜点
  - 我方价格分第1，但总分落后 → 报价策略误判（不应过度关注价格分）
  → 修正系数 = 0.95（降低K，下次报价可适当提高，把精力放在技术方案上）

特殊调整：
  - 若项目价格分权重 < 35%：K -= 0.05~0.10（不必过度压价）
  - 若对手A/B均采用激进报价（下浮>8%）：评估我方成本底线，能跟则跟，不能跟则放弃
```

### 11.4 模型自动更新机制（调用 tools-bayesian-update）

> 每次复盘完成后，自动触发以下更新（均通过调用 `tools-bayesian-update` 实现，不再内嵌计算公式）：

**A. 对手画像模型更新**（调用 `tools-bayesian-update`）

| 更新项 | 数据来源 | 更新频率 |
|---------|---------|---------|
| 对手报价分布（μ, σ） | 每次投标的实际报价 | 每次复盘后即时更新 |
| 对手技术特点标签 | 技术评分拆解 + 评委反馈 | 每次复盘后即时更新 |
| 对手最优应对策略 | 历史交锋记录（胜/负） | 累计3次交锋后更新策略 |
| 对手关系优势评估 | 中标结果 + 业主背景调研 | 每次复盘后即时更新 |

```
→ 调用 tools-bayesian-update：

prior_params:
  mu_old: [从历史对手画像库读取上次 μ]
  sigma_old: [从历史对手画像库读取上次 σ]

observations:
  - [本次对手实际报价下浮率]
  - [若有多次观测，一并传入]

likelihood_model: normal
prior_type: normal
```

→ 预期输出：后验 μ_new, σ_new → **写回 `references/对手画像库.md`**

→ 调用 tools-bayesian-update：
