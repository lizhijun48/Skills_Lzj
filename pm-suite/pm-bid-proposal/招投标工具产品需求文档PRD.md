# 招投标工具产品需求文档（PRD）

## 1. 项目背景与目标

### 1.1 项目背景
在企业招投标业务中，流程节点繁多且涉及跨部门协作。传统的招投标管理往往依赖人工流转，存在信息获取分散、审批流僵化、报价策略缺乏数据支撑、以及弃标等异常流程缺乏闭环管理等问题。为提升业务效率并规避合规风险，需构建一套贴合实际业务场景的招投标管理工具。

### 1.2 项目目标
- **流程标准化与自动化**：将线下复杂的招投标全生命周期（从需求确认到总结归档）进行线上化、结构化沉淀。
- **决策数据化**：通过动态审批路由和报价辅助测算，降低人为决策风险，避免形式主义。
- **人机协同**：在关键业务节点（如信息录入、线下会议决议）保留人工干预，确保系统工具与真实业务场景无缝衔接。

## 2. 用户角色与权限

基于招投标业务的跨部门协作特性，系统需支持以下核心角色：

- **销售/商务部**：负责项目线索录入、招标文件上传、商务标编制、报价测算及二次报价策略录入。
- **售前/技术部**：负责技术标编制、可行性分析、标前答疑及产品配置。
- **部门主管/经理**：负责标书初审与二审，把控基础合规性与内容质量。
- **分管领导**：负责重大或高金额项目的终审把关（动态触发）。
- **投标委员会成员**：参与线下定标会议，对最终报价与投标策略进行综合决策。
- **系统管理员**：负责审批阈值配置、资质库维护及系统基础数据管理。

## 3. 核心业务流程图描述

系统核心业务流程分为两条主线，并在关键节点进行交汇：

### 3.1 招投标全生命周期主线
1. **项目获取**：销售通过指定网站获取项目信息，人工下载招标文件并上传系统。
2. **需求与报名**：确认标书需求，完成线上/线下投标报名。
3. **资质与标书制作**：调用资质库，进行标前分析，制定计划表。
4. **多级审核**：执行“制作人员自审 -> 主管二审 -> 部门经理三审”流程；若满足阈值条件，自动触发“分管领导审批”。
5. **封标与上传**：审核通过后进行封标及标书上传。
6. **结果跟进与总结**：记录我司及友商开标信息，无论中标、未中标或弃标，均需完成复盘总结。
7. **归档与费用追踪**：完成电子/纸质存档，追踪保证金及服务费。

### 3.2 标书制作协作与定标主线
1. **双轨并行**：商务部编制商务标；技术部进行可行性分析、标前答疑及技术标编制。
2. **弃标分支**：技术部进行可行性分析时，若判定不可行，触发“弃标线下沟通会议”，上传会议纪要后闭环。
3. **方案整合**：双轨完成后，进行标书集结与检视。
4. **投标委员会审核**：摒弃线上多人会签，改为线下沟通会议综合决策，上传会议决议后流程继续。
5. **定标与二次报价**：根据会议决议及项目推进信息，确定最终价格并完成二次报价，进入装订签封环节。

## 4. 功能需求详解

### 4.1 立项解析模块（信息录入）
- **文件解析引擎**：支持销售上传PDF/Word格式的招标文件，系统自动提取项目名称、编号、截止时间、保证金等关键字段，生成结构化表单。
- **人工确认机制**：解析结果需经销售人员核对修改后方可正式立项，确保数据准确性。
- **非爬虫策略**：系统不提供全网自动抓取功能，仅作为人工下载后的解析与归档工具。

### 4.2 动态审批流模块
- **条件路由引擎**：在投标文件审核节点，系统根据“项目合同级别”和“预估金额”两个变量进行判断。
- **动态触发规则**：当单一条件满足预设阈值时，审批流自动增加“分管领导审批”节点；否则，部门经理三审通过后直接流转至下一环节。
- **阈值配置**：管理员可在后台灵活调整触发分管领导的金额与级别阈值。

### 4.3 报价辅助与二次报价模块
- **报价测算工具**：提供内部成本、预期利润、历史报价等维度的测算模型，辅助销售制定初始报价。
- **二次报价管理**：支持在投标截止前根据最新信息进行最终价格调整。
- **策略留痕**：无论实际价格变动还是策略响应，二次报价环节必须强制填写“调价理由/操作说明”，确保决策可追溯。

### 4.4 弃标闭环管理模块
- **强制记录**：当项目状态变更为“弃标”时，系统拦截直接结束流程的操作。
- **线下会议联动**：提示用户组织线下沟通会议说明弃标原因。
- **决议上传**：必须上传“弃标决策会议纪要”附件，方可将项目归档至“投标总结”模块，形成管理闭环。

### 4.5 投标委员会决议录入模块
- **线下会议支持**：取消线上串行审批，系统仅作为线下沟通会议的记录载体。
- **决议录入**：指定专人（如商务总监）在系统中录入委员会最终决议，并上传签字版会议纪要。
- **流程解锁**：系统校验“会议纪要”附件上传成功后，才允许流程流转至“标书确定价格核定”及后续环节。

## 5. 非功能性需求

- **安全性**：招投标文件属于企业核心机密，系统需具备严格的权限隔离机制；所有报价、决议等敏感操作需留存不可篡改的审计日志。
- **兼容性**：文件解析引擎需兼容市面上主流的PDF、Word格式，对扫描件需具备一定的OCR识别能力。
- **灵活性**：审批阈值、弃标必填字段等规则需支持后台热配置，无需修改代码即可适应业务调整。
- **易用性**：界面设计应遵循“表单极简、流程可视化”原则，降低一线销售与技术人员的系统学习成本。
