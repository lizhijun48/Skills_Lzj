# 报价决策公式与模型

> 本文件为 `pm-bid-proposal` 的参考资源，系统梳理招投标报价决策中的核心公式、定价模型和博弈策略，帮助投标人员从"拍脑袋报价"升级为"数据驱动定价"。

---

## 一、报价决策框架

```
报价 = 成本底线 + 目标利润 + 竞争调整 + 风险预留

其中：
- 成本底线：绝对不可突破的下限（亏本线）
- 目标利润：基于公司战略和项目价值的期望利润
- 竞争调整：基于对手预期报价的动态调整
- 风险预留：不确定性缓冲（通常3%-8%）
```

---

## 二、成本核算模型

### 2.1 全成本核算法

```
总成本 = 直接成本 + 间接成本 + 风险预留

直接成本：
  硬件成本 = 设备采购价 + 运输保险 + 安装调试
  软件成本 = 许可费 + 定制开发费 + 集成费
  实施成本 = 人工费（人月×单价）+ 差旅费 + 培训费
  
间接成本：
  管理费 = 直接成本 × 管理费率（通常8%-15%）
  税费 = （直接成本 + 管理费 + 利润）× 综合税率

风险预留：
  风险预留 = 总成本 × 风险系数（3%-8%）
```

### 2.2 人月成本估算

```
单人月成本 = 月工资 × 负荷系数

负荷系数 = 1 + (社保公积金比例 + 福利比例 + 办公分摊比例)
         ≈ 1.5 ~ 2.0（即月成本的1.5-2倍）

项目人工总成本 = Σ(各角色人月数 × 该角色单人月成本)
```

### 2.3 成本核算表模板

| 费用项 | 金额（万元） | 占比 | 备注 |
|--------|------------|------|------|
| 硬件设备 | | | 含运输保险安装 |
| 软件许可 | | | 含定制开发和集成 |
| 实施人力 | | | PM+架构+开发+测试+部署 |
| 差旅培训 | | | 按项目地点估算 |
| 管理费 | | | 直接成本×管理费率 |
| 风险预留 | | | 总成本×风险系数 |
| **成本合计** | | **100%** | **报价不得低于此数** |

## 三、定价模型

### 3.1 成本加成定价法

```
报价 = 总成本 × (1 + 目标毛利率)

适用场景：
- 预算充裕的ToG项目
- 竞争不充分的市场
- 战略性项目（利润不是首要考量）

毛利率参考：
- ToG信息化项目：15%-30%
- ToG安防项目：10%-25%
- 运维服务：20%-35%
- 纯软件项目：30%-50%
```

### 3.2 竞争导向定价法

```
报价 = 预估对手平均报价 × 竞争系数

竞争系数确定：
- 技术优势明显：1.0 - 1.05（略高于平均，技术分弥补）
- 技术势均力敌：0.95 - 1.0（略低于平均，争取价格分）
- 技术处于劣势：0.90 - 0.95（明显低于平均，靠价格分拉回）
- 战略性亏损：0.85 - 0.90（亏本也要拿下的项目）

适用场景：
- 竞争充分的市场
- 有可靠的对手报价信息
- 价格分权重较高的项目
```

### 3.3 价值导向定价法

```
报价 = 客户感知价值 × 价值系数

客户感知价值 = 预算上限 × 我方价值占比

我方价值占比取决于：
- 方案独特性（独家技术/专利）
- 服务质量（响应速度/驻场承诺）
- 品牌溢价（行业标杆/头部企业）
- 客户关系（长期合作/信任基础）

适用场景：
- 客户对我方有明确偏好
- 我方有不可替代的技术/服务优势
- 述标阶段可展示差异化价值
```

### 3.4 博弈论定价法（对抗性模拟）

```
步骤1：预估每个对手的报价区间
  对手A：[估计最低价, 估计最高价]
  对手B：[估计最低价, 估计最高价]
  ...

步骤2：根据评分公式，模拟不同报价下的得分
  我方报价X → 技术分T + 商务分B + 价格分P(X) = 总分S(X)
  对手A报价Y_A → 总分S_A(Y_A)
  对手B报价Y_B → 总分S_B(Y_B)

步骤3：找到我方总分最大化的报价点
  max S(X) subject to X > 成本底线

步骤4：敏感性分析
  对手报价变动±10%时，我方最优报价如何变化？
```

## 四、价格分模拟公式

### 4.1 基准价法模拟

```python
# 基准价法价格分计算（最常见的评分模型）

def calc_price_score(my_bid, all_bids, full_score, benchmark_method='mean'):
    """
    my_bid: 我方报价
    all_bids: 所有有效报价列表（含我方）
    full_score: 价格分满分
    benchmark_method: 基准价计算方法
    """
    
    # 计算基准价
    if benchmark_method == 'mean':
        benchmark = sum(all_bids) / len(all_bids)
    elif benchmark_method == 'trimmed_mean':
        sorted_bids = sorted(all_bids)
        trimmed = sorted_bids[1:-1]  # 去掉最高最低
        benchmark = sum(trimmed) / len(trimmed)
    elif benchmark_method == 'weighted':
        # 去掉最高最低后的加权平均
        sorted_bids = sorted(all_bids)
        trimmed = sorted_bids[1:-1]
        benchmark = sum(trimmed) / len(trimmed)
    
    # 计算价格分
    deviation = abs(my_bid - benchmark) / benchmark
    score = full_score * (1 - deviation)
    
    return max(0, score)  # 不低于0分

# 示例
all_bids = [1800, 2100, 1550]  # 我方1800, 对手A 2100, 对手B 1550
my_score = calc_price_score(1800, all_bids, 30, 'mean')
# 基准价 = (1800+2100+1550)/3 = 1816.67
# 我方价格分 = 30 × (1 - |1800-1816.67|/1816.67) = 29.72
```

### 4.2 最低价法模拟

```python
def calc_lowest_price_score(my_bid, all_bids, full_score):
    """
    最低价法：最低有效报价得满分，其他按比例折算
    """
    min_bid = min(all_bids)
    score = full_score * min_bid / my_bid
    return score

# 示例
# 最低报价1550
# 我方1800: 30 × 1550/1800 = 25.83
# 对手A 2100: 30 × 1550/2100 = 22.14
# 对手B 1550: 30 × 1550/1550 = 30.00
```

### 4.3 最优报价搜索

```python
def find_optimal_bid(cost_floor, budget_cap, all_competitor_bids, 
                     my_tech_score, comp_tech_scores, 
                     price_weight, tech_weight, full_score,
                     benchmark_method='mean'):
    """
    在成本底线和预算上限之间搜索使我方总分最大化的报价
    """
    best_bid = cost_floor
    best_total = 0
    
    # 以1万元为步长搜索
    for bid in range(int(cost_floor), int(budget_cap), 10):
        all_bids = [bid] + all_competitor_bids
        
        # 计算我方价格分
        my_price_score = calc_price_score(bid, all_bids, full_score, benchmark_method)
        
        # 计算对手价格分
        comp_price_scores = []
        for cb in all_competitor_bids:
            all_bids_temp = [bid] + all_competitor_bids
            cs = calc_price_score(cb, all_bids_temp, full_score, benchmark_method)
            comp_price_scores.append(cs)
        
        # 计算总分
        my_total = my_tech_score + my_price_score
        max_comp_total = max(ts + ps for ts, ps in zip(comp_tech_scores, comp_price_scores))
        
        # 最大化我方总分 - 最高对手总分的差值
        margin = my_total - max_comp_total
        
        if margin > best_total:
            best_total = margin
            best_bid = bid
    
    return best_bid
```

## 五、报价调整策略

### 5.1 不平衡报价法

```
原则：在总价不变的前提下，调整分项报价
- 早期完成的分项：适当提高报价（提前回收资金）
- 后期完成的分项：适当降低报价
- 预计工程量增加的分项：适当提高单价
- 预计工程量减少的分项：适当降低单价

注意：
- 调整幅度不宜过大（通常±10%以内）
- 过度不平衡可能被评标委员会质疑
- 招标文件若禁止不平衡报价则不可使用
```

### 5.2 报价分项策略

| 分项 | 策略 | 原因 |
|------|------|------|
| 硬件设备 | 按采购成本+合理利润 | 价格透明，偏离容易暴露 |
| 软件开发 | 适当高报 | 价值难以量化，差异化空间大 |
| 系统集成 | 核心利润区 | 技术含量高，对手难以对标 |
| 实施部署 | 按人月估算 | 相对标准，但可调整人月数 |
| 运维服务 | 适当低报 | 建立长期合作基础，后续可续约 |
| 培训 | 适当低报 | 成本低，客户感知好 |

### 5.3 降价策略（磋商/谈判阶段）

```
首次报价 = 目标价 × (1 + 谈判空间)

谈判空间：
- 竞争性磋商：10%-20%
- 竞争性谈判：5%-15%
- 议标/单一来源：3%-10%

降价原则：
- 每次降价不超过上一轮的50%（递减式让步）
- 降价须给出理由（优化方案、规模效应、战略合作）
- 绝不低于成本底线
```

## 七、报价决策速查表

| 场景 | 推荐策略 | 报价定位 |
|------|---------|---------|
| 技术强+竞争少 | 价值导向定价 | 偏高（接近预算上限） |
| 技术强+竞争多 | 竞争导向定价 | 中等偏高 |
| 技术弱+竞争少 | 成本加成定价 | 中等 |
| 技术弱+竞争多 | 博弈论定价 | 中等偏低（靠价格分） |
| 战略项目 | 成本底线+微利 | 接近成本价 |
| 运维续约 | 锁定客户+后续增值 | 硬件微利/服务长线 |
| 首次进入市场 | 市场准入定价 | 低于常规10%-15% |

## 八、报价红线

> 以下任何一条触犯，报价决策应立即叫停：

- ❌ 报价低于成本（法律禁止+实际亏损）
- ❌ 报价超过招标控制价（直接废标）
- ❌ 低于成本价竞标（《反不正当竞争法》风险）
- ❌ 串通报价（《招标投标法》刑事责任）
- ❌ 未经授权的折扣/让利（公司决策流程外的报价）
