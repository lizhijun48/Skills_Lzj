# 用户访谈提纲模板

> 适用于政府/国企信息化项目需求调研阶段，对标PMBOK第5章收集需求工具与技术

---

## 一、访谈前准备

| 项目 | 内容 |
|------|------|
| 访谈对象 | 姓名/职务/部门/联系方式 |
| 访谈目的 | 明确本次访谈要获取哪类需求（政策/业务/功能/非功能/验收） |
| 前置阅读 | 可研报告相关章节、该部门业务流程文档 |
| 访谈时长 | 建议45-60分钟/人，领导30分钟 |
| 记录方式 | 双人制：1人提问+1人记录，全程录音（须提前获同意） |

---

## 二、领导层访谈提纲（30分钟）

### 2.1 战略与愿景

1. 本项目在您部门整体工作中的定位是什么？期望解决什么核心问题？
2. 项目建成后的理想状态是怎样的？有什么量化目标？
3. 上级领导对本项目有什么特别指示或要求？（标注`[领导要求]`）
4. 与其他在建/规划项目有什么关联或协同要求？

### 2.2 约束与红线

5. 预算方面有什么硬性约束？（标注`[预算红线]`）
6. 工期方面有什么不可变更的节点？（如领导视察、会议、审计等）
7. 有什么部门之间的敏感关系需要特别注意？

### 2.3 决策机制

8. 本项目的业主方决策链是怎样的？最终决策人是谁？
9. 需求变更的审批流程是什么？

---

## 三、业务部门访谈提纲（60分钟）

### 3.1 现状与痛点

1. 目前这个业务是怎么做的？请描述完整流程
2. 现有系统/手工操作中最困扰您的3个问题是什么？
3. 这些痛点发生的频率和影响程度如何？（高/中/低）
4. 之前是否尝试过解决？效果如何？

### 3.2 业务需求

5. 新系统最核心必须实现的3个功能是什么？（标注优先级）
6. 您期望的日常工作流是怎样的？请按步骤描述
7. 与其他部门的数据交互需求有哪些？
8. 有什么行业/部门规范必须遵守？

### 3.3 非功能需求

9. 系统使用场景：办公电脑/移动端/大屏？并发用户数大约多少？
10. 数据安全等级要求？哪些数据涉及隐私或敏感信息？
11. 对系统响应速度有什么期望？能否容忍短暂不可用？
12. 系统需要7×24运行吗？有无计划维护窗口？

### 3.4 验收期望

13. 您会怎么判断系统是否满足需求？有什么可量化的标准？
14. 最小可用版本需要包含哪些功能才能上线？
15. 试运行期间需要多长时间才能确认系统可用？

---

## 四、技术部门访谈提纲（45分钟）

1. 现有IT基础设施情况（服务器/网络/数据库/中间件）？
2. 已有系统清单及接口方式（API/数据库/文件/消息队列）？
3. 数据迁移需求？数据量和数据质量情况？
4. 等保级别要求？有无安全合规的特殊要求？
5. 运维团队配置情况？技术栈偏好？
6. 与其他系统的集成要求和技术约束？

---

## 五、访谈纪要模板

| 项目 | 内容 |
|------|------|
| 访谈日期 | |
| 访谈对象 | 姓名/职务/部门 |
| 访谈人 | |
| 需求分类 | □政策 □业务 □功能 □非功能 □验收 |
| 原始需求记录 | （逐条记录，保留用户原话） |
| 需求来源标注 | `[领导要求]` / `[业务需要]` / `[合规必须]` / `[隐性需求]` |
| 待确认事项 | （需要二次确认的内容） |
| 被访者签字 | ____________ 日期：______ |

**政府项目特殊要求**：
- 访谈纪要须在24小时内输出并请被访者签字确认
- 区分"领导意志"和"业务真实需求"是核心能力
- 跨部门协调需求须单独标注并确认协调机制
- 记录"隐性需求"——用户未明说但经验判断必须的
