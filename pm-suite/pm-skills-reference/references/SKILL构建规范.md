# SKILL 库构建规范 v2.0

> 提炼自 pm-project-opportunity（v2.0）和 pm-bid-proposal（v2.0）的构建过程。
> 所有后续 PM 工作流 SKILL 必须严格遵循本规范。

---

## 一、文件结构标准

```
~/.workbuddy/skills/<skill-name>/
├── SKILL.md              ← 主文件（200-400行，不超过500行）
└── references/           ← 详细提纲、法规原文、模板文件
    ├── xxx编制提纲.md      ← 详细提纲类
    ├── xxx法规依据.md      ← 法规条文原文
    ├── xxx模板.md          ← 模板/框架文件
    └── xxx方法论详解.md    ← 方法论深度解读
```

**渐进式加载原则**：
- SKILL.md 只包含核心工作流和关键要求
- 详细提纲/模板/法规原文 → references/
- 编制某阶段时**才按需加载**对应的 references 文件
- 主文件中用 `→` 箭头指向 references 文件路径

## 三、九大构建约束

### 约束1：法规对标原则
- 所有输出结论必须标注法规/标准来源
- 法规引用格式：`（文件简称第X条）`
- 禁止无依据的编撰和推测
- 法规引用包括但不限于：
  - 法律：《招标投标法》《政府采购法》《政府投资条例》
  - 部门规章：发改委55号令、7号令
  - 国家标准：GB/T系列
  - 行业规范：住建部编制深度规定
  - 知识体系：PMP/软考高项/NPDP/一建实务

### 约束2：交叉引用原则
- 每个 SKILL 必须明确与上下游 SKILL 的衔接关系
- 上游 SKILL：输入从哪里来（前置条件）
- 下游 SKILL：输出到哪里去（后置衔接）
- 用表格列明"前置文件→用途"和"产出→消费方"

### 约束3：角色定位原则
- 每个 SKILL 必须声明角色身份（PMP/一建/NPDP/软考高项）
- 角色身份决定视角和权威性来源
- 涉及多角色协作时，定义标准协作接口

### 约束4：渐进式加载原则
- SKILL.md 主文件控制在 200-400 行
- 详细内容（提纲、法规原文、长篇模板）→ references/
- 主文件中用 `→` 符号标注 references 路径
- 禁止将超过50行的提纲/表格嵌入主文件

### 约束5：量化标准化原则
- 所有评估/决策必须有量化标准（评分表、阈值、公式）
- 不可只用"高/中/低"等模糊描述
- 精度标注：标注每个数字的精度级别（±30%/±10%/±5%）
- 不可将低精度数字伪装为精确数据

### 约束6：红线规则原则
- 涉及合规/资质/安全时，必须列出硬红线
- 红线标注法规来源
- 分级管理：重大/一般/轻微
- 触发条件必须明确可判断

### 约束7：输入输出标准化
- 必填输入 vs 选填输入 明确区分
- 输出结构用表格列出，标注每项的内容范围
- 提供使用示例（具体输入→输出）

### 约束8：触发词标准化
- description 字段的触发词必须直接可用
- 触发词使用中文业务用语
- 每个功能场景至少配2-3个触发词变体
- 触发词列表在文件末尾单独列出

### 约束9：团队协作接口标准化
- 涉及软件开发团队协作时，定义标准数据流
- 用表格列明"产出物 → 消费角色 → 消费方式"
- 交接检查清单用checkbox格式
- 角色名使用标准化称谓（PM:许清楚, 架构师:高见远, 工程师:寇豆码, QA:严过关, 主理人:齐活林）

## 四、构建工作流

```
第1步：明确领域
  → 确定归属 PMP 五大过程组的哪个

第2步：确定对标标准
  → PMP 对应章节 + 软考高项 + 一建实务 + 国标

第3步：定义输入输出
  → 必填/选填输入 + 输出物清单

第4步：设计工作流
  → N步流程 + 每步子步骤 + 法规标注

第5步：建立交叉引用
  → 上游 SKILL + 下游 SKILL + 数据流

第6步：提炼 references
  → 超过50行的提纲/模板/法规 → references/

第7步：编写使用示例
  → 基于用户真实项目经验的示例

第8步：检查九大约束
  → 逐条对照，确保不遗漏
```

- [ ] SKILL.md 主文件 ≤ 400 行
- [ ] 所有法规引用标注了具体条款
- [ ] 与上下游 SKILL 的衔接已定义
- [ ] 输入/输出用标准化表格
- [ ] 至少1个使用示例
- [ ] 触发词覆盖所有功能场景
- [ ] 角色定位明确
- [ ] agent_created: true 标记存在
- [ ] 硬红线标注法规来源
- [ ] references/ 文件路径正确
- [ ] 量化标准（非模糊描述）
- [ ] 交接检查清单完整
