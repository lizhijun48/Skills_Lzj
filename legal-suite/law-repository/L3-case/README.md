# L3 案例引用层

> 定位：law-repository 的 **L3 层**。存放**指导案例 / 公报案例 / 典型案例**的裁判要旨与引用锚点。
> 治理身份：与 L1/L2 同属 data 基础设施，不占技能编号，纳入 GOV_SkillGovernance v3.6 管辖（QG4 数据溯源）。
>
> 用户需求 #1（2026-08-26 复盘结论）：法律法规库应包含【原文、司法解释、领域解读、案例引用】——本层承载「案例引用」。

## 用途

行业技能做场景化论证时，引用「案例要旨 + 案号 + 来源」增强说服力；并反向登记该案例所援引的法条（→ L1 原文层），落实双向闭环。

## 文件命名

`<案由>_案例_<案号或代号>.md`

示例：
- `建设工程施工合同_案例_指导案例X号.md`
- `买卖合同_案例_（202X）最高法民终X号.md`

## 文件头规范（强制）

```yaml
---
案由: 建设工程施工合同
案例标识: 指导案例X号 / 公报案例(202X) / (202X)最高法民终X号
裁判要旨: <一句话归纳>
关联原文: ../laws/<法律名>_<版本>.md   # 本案援引的核心法条（可多个，;分隔）
层级: L3-案例引用
快照日期: 2026-09-01
状态: 待补(联网恢复后入库)   # 待补(联网恢复后入库) / 新鲜 / 待核(180天)
---
```

## 内容规范

- 仅存「裁判要旨 + 案号 + 来源 + 关联法条」，不存完整判决书（冗长内容归 sources/ 或外部库）。
- 必须挂「关联原文」回指 L1，形成 案例 → 原文 的正向溯源。
- 反向：案例所揭示的「新裁判口径 / 库缺失法条」→ 登记 law-manifest.md「待补」区，推动 L1 补库。

## 当前状态（2026-09-01）

- 本层为**空骨架**，待联网恢复后按业务需要填充（如 contract-review 引用的最高法指导案例、pm-bid 引用的招投标争议案例）。
- 不阻塞：现有技能蒸馏数据独立使用，库补全后建立正式引用。
