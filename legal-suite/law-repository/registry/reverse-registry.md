# reverse-registry — 反向登记（蒸馏数据 → 库原文）

> 用途：记录「各行业技能蒸馏数据」引用了 law-repository 中哪些原文，建立**反向可追溯**链路。
> 这是用户需求 #2 闭环的落地文件：「蒸馏数据来源从法规库获取原文，再蒸馏+更新；出现新要求反向推动法规库更新」。
>
> - **正向（蒸馏）**：技能引用库原文时标注 `来源：law-repository/laws/<文件>(快照日期)`（L2/L3 同理）。
> - **反向（缺口登记）**：本表登记「哪个技能的哪块蒸馏数据」←「依赖库内哪部法」，库更新时据此级联通知受影响技能。

## 登记格式

| 依赖法规(库内文件) | 引用技能 | 引用位置(模块/文件) | 引用性质 | 登记日期 |
|---|---|---|---|---|
| `<laws/文件名>` | `<技能名>` | `<模块或 references 文件>` | 原文引用 / 解读引用 / 案例引用 | 2026-09-01 |

## 维护规则

1. 每次「技能引用库原文」或「库新增原文被技能引用」→ 同步更新本表。
2. 库某法修订/废止 → 查本表找下游技能 → 在技能引用处加「⚠️ 上游已更新」标记（见 README 更新规程第5条）。
3. 技能发现库缺某法 → 在 law-manifest.md「待补」登记 → 人工补库 → 回填本表。
