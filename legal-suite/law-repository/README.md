# law-repository — 中央法规库（法律内容基础设施）

> 定位：legal-suite 的**单一事实来源**（Single Source of Truth）。只存法条原文快照与版本元数据，**不存解读、不存案例、不存场景化内容**（那些归 L1/L2/L3 各技能层）。
> 治理身份：**不占技能编号**（同 perspective-kernel / business-underlying-logic 模式），作为数据基础设施挂在 legal-suite 下，纳入 GOV_SkillGovernance v3.6 管辖（QG4 数据溯源 / QG6 变更管理）。

## 目录结构

```
legal-suite/law-repository/
├── README.md          ← 本文件（定位 + 更新规程）
├── law-manifest.md    ← 法规清单（已入库 / 待补 / 待核），唯一盘点入口
├── laws/              ← 法条原文快照（一部法一个 .md，文件名含版本戳）
│   └── <法律名称>_<版本>.md
└── sources/           ← 原始来源归档（PDF 等），保溯源
```

## 文件头规范（强制）

每个 laws/ 下的 .md 必须带 YAML frontmatter：

```yaml
---
法律名称: 中华人民共和国招标投标法
层级: 法律            # 法律 / 行政法规 / 部门规章 / 司法解释 / 地方性法规
现行版本: 2017修订
版本说明: <通过/修订/施行的时间与会议信息，缺失则标"待核实">
施行日期: 2017-12-28   # 缺失标"待核实"
快照日期: 2026-08-31   # 本文件入库/核对日期
来源: <发布机构 + 文档形态>
来源文件: ../sources/<原始文件名>   # 无原件可指时标"无原件（在线来源）"
状态: 新鲜            # 新鲜 / 待核(180天) / 待核(版本待核实) / 已废止
规模: 6章 68条
---
```

**不杜撰原则**：版本信息（文号/年份/施行日期）缺失时一律标「待核实」，禁止编造。文本内容保持提取原样（含少量 reflow 合并瑕疵），不做语义改写。

## 更新规程（六条）

1. **仅人工触发**：不自动抓取。任何更新由用户在真实会话中下令（"更新X法"），或 AI 检出下游引用失效时提请用户触发。
2. **三粒度**：
   - 单法更新：核对一部法的现行版本，更新快照与 frontmatter
   - 分片更新：核对某个领域（如招投标领域全部4部）
   - 全量审计：对照 law-manifest.md 逐条核对（建议每季度一次）
3. **180天阈值**：快照日期距今超过180天 → 状态改「待核(180天)」，提示优先级链上的下游技能注意。
4. **git 一更新一 commit**：每次更新独立 commit，commit message 含法规名+版本变化（旧版→新版），可回滚。
5. **级联标记**：某法原文变更（修订/废止）→ 在 law-manifest.md 该法条目的「下游引用」列登记受影响技能 → 受影响技能自己的引用处加「⚠️ 上游已更新」标记。反向同理：行业技能发现场景缺口（缺某法/某司法解释）→ 在 manifest「待补」区登记 → 人工补充入库。
6. **优先级链**：官方网站原文（人大网/中国政府网）> 官方汇编PDF（政府交易平台发布）> 权威转载（律所/平台全文）。每级须在 frontmatter「来源」中如实记录级别。

## 数据流（与三层技能架构的关系）

```
[本库 laws/] --蒸馏(引用原文+溯源标注)--> L2 专业技能 / L3 行业技能
      ^                                            |
      └──── 反向登记场景缺口（manifest 待补区）←────┘
```

- **正向（蒸馏）**：行业技能引用库内原文做场景化解读时，必须标注「法条来源：law-repository/laws/<文件名>（快照日期）」。
- **反向（缺口登记）**：技能使用中发现库内缺某法/某司法解释 → manifest 登记 → 人工入库 → 技能引用补齐。

## 已知限制（2026-08-31 建库时点）

- flk.npc.gov.cn（国家法律法规数据库）API 已改版，旧端点失效（返回 SPA HTML / 405），在线核验通道暂不可用 → 需联网核验的项目均标「待核」或「待补」。
- 现有 4 部入库文件来自机器提取（pypdf + 页面切片），段落 reflow 存在少量章标题与首条合并现象（如"第六章附则第六十五条…"），**不影响检索与引用，后续优化**。
