# ip-protection · 知识产权保护技能

> **核心定位**：回答"IP权益如何保护"——识别IP类型、审查归属条款、预警侵权风险、制定保护策略。
> **法规依据**：《专利法》《商标法》《著作权法》《反不正当竞争法》《网络安全法》

---

## 适用场景

| 场景 | IP类型 | 保护重点 |
|------|---------|---------|
| 软件开发 | 著作权（代码）+ 专利（算法） | 开源协议合规、背景IP保护 |
| 产品开发 | 专利（技术方案）+ 外观设计 | 专利申请策略、侵权规避 |
| 技术合作 | 背景IP + 新增IP | IP归属条款、许可范围 |
| 品牌建设 | 商标 + 域名 | 商标注册、侵权监控 |
| 开源项目 | 开源协议选择 | 协议兼容性、商业使用合规 |

---

## 核心工作流程

### Step 1：识别IP类型与归属

**IP类型矩阵**：

| IP类型 | 保护对象 | 保护期限 | 授权条件 |
|---------|---------|---------|---------|
| **专利** | 技术方案（发明/实用新型/外观设计） | 20年/10年/15年 | 新颖性/创造性/实用性 |
| **商标** | 商品/服务标识（文字/图形/组合） | 10年（可续展） | 显著性/非冲突性 |
| **著作权** | 原创作品（软件/文档/设计） | 作者终生+50年 | 原创性（自动保护） |
| **商业秘密** | 技术/经营信息（非公开） | 无期限（需保密） | 保密措施+商业价值 |
| **集成电路布图设计** | 芯片拓扑结构 | 10年 | 独创性 |

**IP归属规则**：

```
背景IP（Background IP） → 归各自所有
                ↓
                合作中可使用（需明确许可范围）

新增IP（Foreground IP） → 约定归属
                ↓
                常见模式：
                - 归开发方（委托方付费使用）
                - 归委托方（开发方保留署名权）
                - 共同所有（需明确实施/许可权利）
```

---

### Step 2：IP条款审查（合同审查场景）

**强制审查项**：

| # | 审查项 | 风险信号 | 建议修改 |
|---|---------|---------|---------|
| 1 | **背景IP归属** | 未明确背景IP归属 | 补充"各方背景IP归各自所有，仅授予项目必需的使用许可" |
| 2 | **新增IP归属** | 未约定新增IP归属 | 明确"新增IP归X方所有，另一方享有X权利" |
| 3 | **IP许可范围** | 许可范围过大/过小 | 明确"许可范围：地域/期限/独占性/可分许可" |
| 4 | **开源协议合规** | 使用GPL代码未披露 | 替换为MIT/Apache 2.0等商业友好协议 |
| 5 | **保密义务** | 未明确保密信息范围 | 定义"保密信息包括：技术方案/源代码/商业数据" |

**开源协议选择指南**：

| 协议 | 商业友好度 | 适用场景 | 风险提示 |
|------|-----------|---------|---------|
| **MIT** | ⭐⭐⭐⭐⭐ | 商业项目、SDK | 几乎无限制 |
| **Apache 2.0** | ⭐⭐⭐⭐⭐ | 商业项目、大厂背书 | 需保留版权声明 |
| **BSD** | ⭐⭐⭐⭐⭐ | 商业项目 | 需保留版权声明 |
| **LGPL** | ⭐⭐⭐ | 库/框架（动态链接） | 静态链接需开源 |
| **GPL v3** | ⭐ | 开源项目（强制开源） | **商业项目禁用**（传染性） |
| **AGPL** | ❌ | 网络服务（强制开源） | **商业项目禁用**（强传染性） |

### Step 3：IP侵权风险分析

**侵权风险信号**：

| IP类型 | 风险信号 | 规避策略 |
|---------|---------|---------|
| **专利** | 产品功能与竞品专利高度相似 | 做专利规避设计（绕开权利要求） |
| **商标** | 品牌名称与已注册商标近似 | 商标检索 + 更换品牌名称 |
| **著作权** | 使用第三方代码/图片/文档未授权 | 获得授权 OR 替换为自有内容 |
| **商业秘密** | 员工跳槽带走客户名单/技术方案 | 签署保密协议 + 竞业限制 |

**侵权应对流程**：

```
发现侵权信号
    ↓
1. 侵权分析（是否构成侵权？）
    ↓
2. 风险评估（侵权概率×赔偿金额）
    ↓
3. 应对策略：
    ├── 规避设计（改产品）
    ├── 获得许可（拿授权）
    ├── 无效宣告（打掉对方专利）
    └── 接受风险（商业决策）
```

---

### Step 4：IP保护策略制定

**保护策略矩阵**：

| 商业模式 | 推荐保护策略 | 成本预估 |
|---------|-------------|---------|
| **ToB软件** | 软件著作权登记 + 核心算法专利申请 + 商业秘密保护 | 1-3万/年 |
| **ToC产品** | 商标注册 + 外观设计专利 + 开源协议合规 | 5千-1万/年 |
| **技术平台** | 平台架构专利 + API接口著作权 + 数据保密 | 3-5万/年 |
| **品牌运营** | 商标注册（全类目） + 域名保护 + 侵权监控 | 1-2万/年 |

**保护优先级**：

```
高价值IP（核心专利/主商标） → 优先保护
    ↓
中等价值IP（辅助功能/子品牌） → 选择性保护
    ↓
低价值IP（过期技术/非核心内容） → 放弃保护 OR 开源
```

## 调用示例

**示例1：软件开发合同IP条款审查**
```
用户："这份开发合同，IP归属条款怎么改？"

AI调用 `ip-protection`：
1. 识别合同中的IP条款（第X条）
2. 分析当前条款风险（未明确背景IP归属）
3. 生成修改建议（背景IP归各自 + 新增IP归委托方）
4. 输出谈判要点 + 替代方案
```

**示例2：开源项目协议选择**
```
用户："我的开源项目想让商业公司也能用，选什么协议？"

AI调用 `ip-protection`：
1. 分析使用场景（商业友好）
2. 推荐协议（MIT OR Apache 2.0）
3. 对比协议差异（版权声明要求/专利授权）
4. 输出协议选择建议 + LICENSE模板
```

## 限制与例外

- ❌ **不适用于**：国际IP保护（需考虑PCT专利/马德里商标等）
- ❌ **不适用于**：IP诉讼代理（需执业律师）
- ✅ **适用于**：IP条款审查、侵权风险分析、保护策略制定、开源协议选择
