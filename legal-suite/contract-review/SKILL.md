# contract-review · 合同审查技能

> **核心定位**：回答"合同条款有没有坑"——系统化审查合同风险，确保合规且保护己方利益。
> **法规依据**：《招标投标法》《政府采购法》《民法典》合同编

---

## 适用场景

| 场景 | 合同类型 | 审查重点 |
|------|---------|---------|
| 政府采购 | 固定总价合同 | 合规检查、价格条款、验收标准 |
| 工程建设 | 建设工程施工合同 | 工期条款、质量标准、变更条款 |
| 软件开发 | 技术开发/服务合同 | 知识产权归属、验收标准、维护条款 |
| 服务采购 | 服务合同 | 服务标准、SLA、终止条款 |

---

## 核心工作流程

### Step 1：识别合同类型

```
合同类型选择矩阵：

| 需求特征 | 推荐合同类型 | 风险分配 |
|---------|-------------|---------|
| 需求明确、变更少 | 固定总价（FFP） | 卖方承担成本风险 |
| 需求不明、可能变更 | 成本补偿（CPAF/CPFF） | 买方承担成本风险 |
| 短期、灵活需求 | 工料合同（T&M） | 风险共担 |
```

**决策规则**：
- 政府项目 → 优先固定总价（财政评审要求）
- 信息化项目 → 固定总价 + 明确变更条款
- 研发项目 → 成本补偿 + 激励条款

---

### Step 2：合同审查清单

**强制审查项（Must-Check）**：

| # | 审查项 | 风险信号 | 建议修改 |
|---|---------|---------|---------|
| 1 | **价格条款** | 价格可调 + 无上限 | 增加"价格调整需双方书面确认+不超过X%" |
| 2 | **交付标准** | "满意为准"（主观） | 改为"符合GB/T XXXX标准+验收清单" |
| 3 | **付款条件** | 预付款>30% | 政府项目：预付款≤30%，验收后付尾款 |
| 4 | **违约责任** | 只有单方违约条款 | 补充双方对等违约责任 |
| 5 | **争议解决** | 无争议解决条款 | 增加"协商→调解→仲裁/诉讼"阶梯条款 |
| 6 | **知识产权** | 未明确IP归属 | 明确"背景IP归各自，新增IP归X方" |
| 7 | **保密条款** | 无保密期限 | 增加"保密义务持续至合同终止后X年" |
| 8 | **终止条款** | 无终止条件 | 明确"不可抗力+违约+双方协商"三种终止情形 |

---

### Step 3：合规检查（政府项目专用）

**强制合规项**：

| 合规项 | 法规依据 | 检查标准 |
|---------|---------|---------|
| 招标程序 | 《招标投标法》第3条 | 必须招标的项目是否经过招标 |
| 采购方式 | 《政府采购法》第26条 | 采购方式是否符合法定情形 |
| 合同内容 | 招投标文件 | 合同是否与中标内容一致（不得实质性偏离） |
| 价格评审 | 财政评审中心 | 价格是否通过财政评审（政府投资项目） |
| 验收标准 | GB/T 16260/ISO 25010 | 软件项目是否有明确质量标准 |

**合规风险信号**：
- ❌ 合同价格 > 中标价格（实质性偏离）
- ❌ 合同范围 > 招标范围（需重新招标）
- ❌ 付款方式违反政府采购规定（如预付>30%）

---

### Step 4：风险评级与谈判要点

**风险评级矩阵**：

| 风险等级 | 判定标准 | 处理方式 |
|---------|---------|---------|
| 🔴 **高风险** | 合规违法 OR 单方面承担主要风险 | 必须修改，否则拒签 |
| 🟡 **中风险** | 条款模糊 OR 风险分配不均 | 建议修改，谈判争取 |
| 🟢 **低风险** | 表述瑕疵 OR 次要条款 | 可接受，记录备案 |

**谈判要点模板**：

```
针对[风险条款]，我方建议：
1. 修改理由：[法规依据/风险分析]
2. 修改建议：[具体条款修改建议]
3. 替代方案：[如果对方不接受，替代方案是什么]
4. 底线：[我方最低接受条件]
```

## 输出模板

**合同审查报告**：

```
# 合同审查报告

## 一、合同基本信息
- 合同名称：
- 合同类型：
- 合同金额：
- 审查日期：

## 二、合规检查
- [ ] 招标程序合规
- [ ] 采购方式合规
- [ ] 合同内容无实质性偏离
- [ ] 价格通过财政评审（如适用）

## 三、风险条款清单
| 条款位置 | 风险描述 | 风险等级 | 修改建议 |
|---------|---------|---------|---------|
| 第X条 | ... | 🔴高 | ... |

## 四、谈判要点
1. [优先级1] ...
2. [优先级2] ...

## 五、审查结论
- ✅ 可以签署（低风险）
- ⚠️ 建议修改后签署（中风险）
- ❌ 必须修改后重新审查（高风险）
```

## 调用示例

**示例1：政府采购合同审查**
```
用户："帮我审查这份《XXX政府采购合同》，重点看合规和风险"

AI调用 `contract-review`：
1. 识别合同类型（固定总价）
2. 执行合规检查（招标投标法/政府采购法）
3. 生成风险条款清单
4. 输出审查报告 + 谈判要点
```

**示例2：软件开发合同审查**
```
用户："这份开发合同，IP归属条款怎么改？"

AI调用 `contract-review`：
1. 定位IP条款（第X条）
2. 分析当前条款风险（未明确背景IP归属）
3. 调用 `law-skills`（法律咨询）→ 获取IP法律依据
4. 输出修改建议 + 替代方案
```

## 限制与例外

- ❌ **不适用于**：国际合同（需考虑国际私法、CISG等）
- ❌ **不适用于**：证券、金融、保险等高度专业领域合同
- ✅ **适用于**：国内民商事合同，特别是政府/国企项目
