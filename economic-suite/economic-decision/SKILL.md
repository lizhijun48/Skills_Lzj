## 核心定位

**不是计算工具，而是"经济决策顾问"**。

- **输入**：模糊的业务需求（如："老板问我要不要重构老系统"）
- **输出**：综合决策报告（含场景识别、工具调用、风险分析、行动建议）

**核心价值**：
1. **场景识别**：用户不需要知道用什么工具，只需描述问题
2. **工具编排**：自动调用 `economic-suite/` 中的对应工具
3. **综合判断**：整合多个工具的输出，给出最终建议

---

## ITTO 合约

### Input（输入）

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `business_scenario` | String | ✅ | 业务场景描述（如："重构老系统"） |
| `project_data` | Object | ⭕ | 项目数据（若有） |
| `decision_type` | String | ❌ | "立项" / "比选" / "成本优化"，若不填则自动识别 |
| `risk_preference` | String | ❌ | "保守" / "进取"，默认"稳健" |

---

### Tools（工具与方法）

1. **场景识别框架**（映射框架）：
   - 是新项目（0-1）还是改扩建（1-N）？
   - 是独立决策还是互斥比选？
   - 是成本优化还是投资决策？

2. **工具调度逻辑**：
   - 识别场景后，**调用** `economic-suite/` 中的对应工具
   - 整合多个工具的输出

3. **综合报告生成**：
   - 按照"经济师.txt"中的 Step 4 报告结构输出

---

### Techniques（技巧与注意事项）

1. **增量思维优先**：
   - 改扩建项目：**必须**使用增量分析（有无对比法）
   - 严禁使用总量 NPV 决策改扩建项目

2. **全生命周期视角**：
   - 提醒用户列出：初始投资 + 运营成本 + 残值
   - 若缺失：基于行业基准保守估算并标注

3. **不确定性量化**：
   - 所有决策必须包含敏感性分析
   - 识别"死穴"变量（波动 ±10% 就导致 NPV 转负）

### Output（输出）

**标准输出格式**（参考"经济师.txt" Step 4）：

```markdown
## 经济决策报告

### 1. 核心结论（Executive Summary）
- **建议**：[通过 / 否决 / 有条件通过]
- **关键指标**：NPV = xxx万，IRR = xx%，动态回收期 = x.x年
- **一句话理由**：基于增量分析，该项目在基准收益率10%下，年均创造净价值xx万

### 2. 场景识别与数据清洗
- **问题类型**：[新项目 / 改扩建 / 多方案比选 / 成本优化]
- **数据来源**：[用户提供 / 行业基准估算]
- **关键假设**：[增量逻辑说明 / 折现率来源]

### 3. 经济测算详情
- **现金流表**（含增量逻辑说明）
- **核心指标计算过程**
- **敏感性分析**：龙卷风图（最敏感的3个变量）

### 4. 风险与临界
- **盈亏平衡点**：如"产能利用率需达到65%才能保本"
- **风险等级**：高/中/低
- **对冲建议**：如"签订长协锁定成本"

### 5. 行动建议
- 若通过：下一步的关键里程碑及资金释放条件
- 若否决：替代方案建议或需补充的数据清单
```

## 执行流程

### Step 1：场景识别（映射框架）

**执行逻辑**：
1. **定性问题**：
   - 是新项目（0-1）还是改扩建（1-N）？
   - 是独立决策还是互斥比选？
   - 是成本优化还是投资决策？

2. **定量数据清洗**：
   - 索要关键数据（现金流、折现率、寿命期）
   - 若缺失：基于行业基准进行保守估算并标注

3. **选择计算工具**：
   | 场景 | 调用工具 |
   |------|---------|
   | 新项目可行性 | `@economic-npv` + `@economic-irr` + `@economic-sensitivity` |
   | 改扩建项目 | `@economic-npv`（增量分析） |
   | 多方案比选 | `@economic-comparison` |
   | 成本优化 | `@economic-ve` |
   | 回本速度 | `@economic-payback` |

---

### Step 2：工具调度与计算

**执行逻辑**：
1. **调用工具**：
   - 根据 Step 1 识别的场景，调用对应工具
   - 传递标准化输入参数

2. **多工具协同**：
   - 若需要多个工具（如：NPV + 敏感性分析）
   - 按顺序调用，整合输出

3. **结果验证**：
   - 检查计算结果是否合理（如：NPV 是否为负但 IRR 很高）
   - 若异常：触发重新计算或提示用户检查数据

---

### Step 3：风险边界划定

**执行逻辑**：
1. **计算盈亏平衡点（BEP）**：
   - 如："产能利用率需达到65%才能保本"

2. **识别临界点**：
   - 如："若获客成本上涨15%，项目NPV归零"

3. **给出风险等级**：
   - 高/中/低
   - 附带对冲建议（如：签订长协锁定成本、设置价格联动机制）

---

### Step 4：输出决策报告

**执行逻辑**：
1. **按标准格式输出**（参考 Output 部分）
2. **明确决策建议**：通过/否决/有条件通过
3. **标注不确定性**：哪些数据是估算的，哪些是准确的

---

## 边界与异常处理

### 边界1：用户需求模糊

- **问题**：用户说"帮我分析一下"，但没有提供数据
- **处理**：
  1. 主动询问关键数据（初始投资、现金流、折现率）
  2. 若用户无法提供：基于行业基准保守估算，并明确标注"估算值"
  3. 给出**框架性建议**（如："若投资 <100万，建议做；若 >200万，需详细测算"）

---

### 边界2：计算结果矛盾

- **问题**：NPV > 0 但 IRR < 折现率（极少见但存在）
- **处理**：
  1. 信任 NPV（绝对财富增量）
  2. 标注："IRR < 折现率，但 NPV > 0，建议通过"
  3. 解释原因（如：后期现金流巨大，但前期 IRR 低）

---

### 边界3：多方案比选但寿命期不同

- **问题**：用户直接比较 NPV（这是错误的）
- **处理**：
  1. 提示用户："寿命期不同，不能直接比 NPV"
  2. 自动调用 `@economic-comparison`（年值法）
  3. 输出年均成本/收益比较

## 调用示例

### 示例1：重构老系统（改扩建项目）

**用户提问**：
> "老板问我要不要重构老系统，帮我分析一下经济性。"

**技能调用**：
```
调用 @economic-decision
输入：
  - business_scenario: "重构老系统"
  - project_data: {无项目损失: 200万/3年, 重构成本: 100万, 运维节省: 1人/年}
```

**输出**：
```markdown
## 经济决策报告

### 1. 核心结论
- **建议**：✅ 通过（重构）
- **关键指标**：增量 NPV = 65万，增量 IRR = 18%
- **一句话理由**：基于有无对比法，不重构未来3年损失200万；重构后，损失降为20万且运维人力减少1人。增量收益180万+人力节省，扣除重构成本100万，增量 NPV = 65万。

### 2. 场景识别
- **问题类型**：改扩建项目（1-N）
- **分析方法**：增量分析（有项目 - 无项目）
- **关键假设**：不重构，系统崩溃导致的订单损失 = 200万/3年

### 3. 经济测算
| 年份 | 无项目现金流 | 有项目现金流 | 增量现金流 |
|------|---------------|---------------|-------------|
| t=0  | 0             | -100（重构成本）| -100        |
| t=1  | -200          | -20            | +180         |
| t=2  | -200          | -20            | +180         |
| t=3  | -200          | -20            | +180         |

- **增量 NPV** = 65万（折现率10%）
- **增量 IRR** = 18%

### 4. 风险与临界
- **盈亏平衡点**：重构成本需 ≤ 165万，才可行
- **风险等级**：中（若重构成本超预算，可能不可行）
- **建议**：分阶段上线以控制风险

### 5. 行动建议
- ✅ 建议重构，但需分阶段上线
- ⚠️ 下一步：与IT部门确认重构成本，若 ≤ 165万则可立即启动
```
