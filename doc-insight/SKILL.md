# 资料深度解读（doc-insight）

## 一、定位

把**任意非结构化资料**变成**能支撑决策的要素矩阵**。

一句话区分本技能与"AI 总结"：

> 总结回答「**这份资料说了什么**」；本技能回答「**为了这个决定，哪些要素必须知道、它们在原文哪一处、彼此是否打架、所以我该做什么**」。

**核心产出**：`决策要素矩阵`（每行一个要素，必带原文出处）+ `决策简报`（红线→要素→矛盾→行动→待澄清）。

---

## 二、适用与不适用（先分流，再动手）

### 2.1 用本技能

| 资料类型 | 典型文件 |
|---|---|
| 立项前期 | 项目建议书、可研报告、初设方案、批复文件、评审意见 |
| 实施过程 | 监理月报/例会纪要（书面）、工程联系单、现场签证、隐蔽验收记录、变更台账 |
| 收尾阶段 | 验收资料、决算资料、审计意见、整改通知 |
| 政策法源 | 政策文件、行业规范、标准条文（**仅提取要求，不做权威解释**） |
| 商务与合作 | 合同附件、技术协议、SOW、尽调材料、供应商资质包 |
| 内部档案 | 历史项目档案、复盘材料、往来函件 |

### 2.2 不用本技能（转专用技能，避免"通用技能做专用活"）

| 你要做的事 | 该用谁 | 为什么不用我 |
|---|---|---|
| 解读**招标文件**、评标办法、废标条款 | `pm-tender-analysis` (JT-019) | 它有招标专属 7 模块与法规细节，比通用骨架细 |
| 从**访谈/会议/竞品录音转写**抽 PM 洞察 | `pd-user-research.insight-extraction` (PT-012 子能力) | 它专治口语转写的冗余与失真 |
| **合同法律审查**（效力、风险、责任分配） | `contract-review` (L-002) | 法律定性与条款攻防不是提取工作 |
| **法条权威解读**（这个条款到底怎么适用） | `law-skills` (L-001) / 法规库 (S-071) | 我明确不做法律解释，只提取要求 |
| **读书**、拆书、知识资产化 | `reading-os` (R-001) | 产出是知识资产，不是决策 |
| **结构化数据**（表格/CSV）统计与可视化 | `data-analyst` | 我吃文档，不吃数字 |

> **判据**：资料是**口语转写**→ PT-012；是**招标文件**→ JT-019；是**合同且要判断法律效力**→ L-002；其余**书面资料要提取决策要素**→ 本技能。

## 三、核心原则（五条，缺一即不合格）

1. **无靶不解读**。没搞清"这份资料要支撑什么决定"，不许开始提取——否则一定退化成通读摘要。靶子必须写成一句可判断真假的话。
2. **无出处不算提取**。每个要素必须能指到原文位置（页码/条款号/章节/段落）。指不到 = 那是你的推断，必须标注为推断或删除。
3. **只提决策相关**。与决策无关的整章直接略过，**不做通读摘要**，不追求"覆盖全文"。
4. **矛盾必须暴露**。两份资料冲突、与法规冲突、与我方现状冲突——列出来并指明"以谁为准、需要谁确认"，**禁止和稀泥式整合**。
5. **分清"资料说的"与"我判断的"**。原文事实用「明确」；需要解读、需要补证、多方口径不一的用「需澄清」，另列待澄清清单。

---

## 四、六步工作流

### 第 0 步 · 立靶（不可省）

先问一句话：**这份资料要支撑哪个具体决定？**

| 要素 | 要求 |
|---|---|
| 决策问题 | 写成一句可判断真假的话，例："这个变更该不该批""这笔付款能不能签""该不该按此方案进场" |
| 决策时点 | 什么时候必须出结论（决定提取的深度上限） |
| 决策人 | 谁拍板（决定需要哪些维度的详略） |
| 已知立场 | 我方当前倾向（用于识别"只找支持证据"的偏误） |

靶子写不出 → **停下来问**，不要硬解读。靶子模糊时只问一句："这份资料最终要你做什么决定？"

### 第 1 步 · 全量清点

1. 列资料清单：文件名 / 类型 / 版本或日期 / 页数或条款范围。
2. 标**版本冲突**：同一文件多个版本时，指定**唯一有效版本**并说明依据（批复日期/发文号/盖章版）。
3. 标**缺口**：按决策需要，缺哪份、缺了会导致哪个维度无法判断、后果是什么。

> 输出要求：缺口必须写成"**缺 X → 导致无法判断 Y → 后果 Z**"，不许只写"资料不全"。

### 第 2 步 · 扫红线（先于一切口径分析）

按七维中的**时间 / 义务 / 风险 / 凭证**先扫一票否决项：

- 时限类：答复期限、异议期、付款节点、报批时限、有效期
- 资格类：资质等级、注册地、业绩门槛、人员持证
- 禁令类：禁止分包、禁止转包、不得偏离的实质性条款
- 经济类：违约金比例、罚则、超概算红线、审计追责条款

命中红线 → **立即在简报顶部标红**，并明确"是否继续深入分析由决策人定"。红线未扫就做细分析 = 白做。

### 第 3 步 · 结构化提取（本技能的主体）

按**七类决策维度**逐维提取，维度细则见 `references/decision-dimensions.md`：

| 维度 | 问什么 |
|---|---|
| 时间 | 什么时候、多久内、以哪天为基准 |
| 金额 | 多少钱、怎么算、什么条件下付、能不能调 |
| 义务 | 谁必须做什么、在什么条件下、不做怎样 |
| 权限 | 谁批、谁签、授权到哪、超了怎么办 |
| 风险 | 罚则、违约、免责、兜底、责任转移 |
| 凭证 | 要交什么材料、几份、什么形式、认不认电子件 |
| 口径 | 定义、计量方式、验收标准、争议解释顺序 |

**每维两条硬规则**：
1. **抽样穷尽**：某维在资料中确实不存在时，写「本维无内容」并给出检索依据（查了哪些章节/关键词），**不许留空**。
2. **允许留白，不许编造**：资料没写的，进"待澄清清单"，**绝不按常识补齐**。

### 第 4 步 · 交叉校验

三类矛盾逐项检查，每条都要写"冲突双方 + 以谁为准 + 谁去确认"：

| 类型 | 检查什么 |
|---|---|
| **资料间** | 正文 vs 附件、前版 vs 后版、批复 vs 方案、合同 vs 技术协议 |
| **对外合规** | 与政策法规、行业强条、上级批复口径是否冲突（**只指出冲突，不做法律结论**） |
| **对我方** | 与我方资质/业绩/产能/现金流/既有承诺是否冲突 |

### 第 5 步 · 决策输出

按 `references/output-contract.md` 的固定结构输出六段，然后**必须跑**：

```bash
python scripts/check_brief.py <你写出的简报文件路径>
```

- 退出码 **0** = 结构与出处合规，可交付；
- 退出码 **1** = 有具体问题，按提示逐条修好后重跑；
- **不得在未跑检查器的情况下宣称简报已完成**；检查器不可用时（无 Python 环境）必须在交付说明里写明"结构自检未执行"。

## 五、输出结构（固定六段，列名不得改）

| 段 | 标题（逐字） | 内容 |
|---|---|---|
| 0 | `## 0. 决策靶子` | 决策问题 / 时点 / 决策人 / 已知立场 |
| 1 | `## 1. 资料清点` | 资料清单表 + 版本裁定 + 缺口（缺X→无法判断Y→后果Z） |
| 2 | `## 2. 红线清单` | 命中项置顶标红；无命中写"未发现一票否决项"并列出扫描依据 |
| 3 | `## 3. 决策要素矩阵` | 固定 7 列表，见下 |
| 4 | `## 4. 矛盾清单` | 资料间 / 对外合规 / 对我方，三类逐条 |
| 5 | `## 5. 决策简报` | 结论倾向 + 行动清单（动作/归口/完成判据/时限） + 待澄清清单 |

**决策要素矩阵表头（逐字，检查器按此校验）**：

```
| 编号 | 维度 | 要素 | 原文出处 | 确定性 | 影响判断 | 行动建议 |
```

| 列 | 合法值 / 要求 |
|---|---|
| 编号 | `D-01` 起顺序编号 |
| 维度 | 只能是：时间 / 金额 / 义务 / 权限 / 风险 / 凭证 / 口径 |
| 要素 | 一句话事实，不复述整段 |
| 原文出处 | **必填**，格式见下；不得写"见上文" |
| 确定性 | 只能是：明确 / 需澄清 |
| 影响判断 | 对本次决策的影响（支持 / 阻碍 / 中性 + 一句说明） |
| 行动建议 | 具体到"谁做什么"，不许写"建议关注" |

**原文出处合法格式**（检查器按此判）：

| 资料类型 | 写法 | 例 |
|---|---|---|
| 有页码的文档 | `p` + 页码 | `p12`、`p12-14` |
| 有条文号的合同/法规 | `第X条第Y款` | `第5条第2款` |
| 有章节的方案 | `§` + 章节号 | `§3.2` |
| 有表格 | `表` + 表号 | `表4-1` |
| 无上述结构的纪要/函件 | `日期+段落序` | `2026-03-12#2` |

## 六、常见坑（只有踩过的人知道）

| 坑 | 表现 | 正确做法 |
|---|---|---|
| **摘要化** | 输出"本文主要讲了……"，无矩阵 | 回到第 0 步补靶子；摘要不是本技能产物 |
| **出处造假** | 写"根据相关资料""详见附件" | 指不到就标「需澄清」，不许糊过去 |
| **版本混用** | 前版与批复混着提 | 第 1 步先裁定唯一有效版本，其余版本只作对比 |
| **红线后置** | 先做完整分析才发现废标项 | 第 2 步前置，红线命中先停 |
| **口径漂移** | 同一要素两次解读结论不同 | 逐条对照 `references/decision-dimensions.md` 的必提项 |
| **替我决策** | 直接写"应当批准" | 给结论倾向 + 判据 + 待澄清，拍板权归决策人 |
| **越界解释法律** | 直接断言"该条款无效" | 指出冲突并转 `contract-review`(L-002) |

## 八、边界

- **不替我拍板**：给要素、给判据、给倾向；决策权归人。
- **不编造出处与数字**：资料没写的不补，指不到的标「需澄清」。
- **不做法律结论**：只指出与法规/合同的冲突点，法律定性交 `contract-review`(L-002)。
- **不做通读摘要**：用户明确要"总结全文"时，说明本技能不做此事，并问是否需要按决策维度提取。
- **不做结构化数据统计**：表格/CSV 计算交 `data-analyst`。
- **保护敏感信息**：涉及标的、报价、业主预算等，按商业秘密处理，不外泄、不写入公开产物。
