# 概念测试评分表（Concept Testing Scorecard）

> 用途：在 MVP 开发前，对产品概念进行量化评分，决定是否推进到下一阶段。
> 适用场景：新产品立项、功能方向决策、GTM 前概念验证。

---

## 一、概念陈述板（填写模板）

在测试前，先准备好概念陈述（1页 PPT / 1段文字）：

```
【产品名称】
【目标用户】：[Persona 一句话]
【核心痛点】：[用户现在怎么解决，有什么不满]
【我们的方案】：[产品是什么，如何解决问题]
【核心利益点】：[用户能获得的最大好处，1-2条]
【与现有方案的区别】：[我们不一样的地方]
```

---

## 二、购买意向 5 级量表（标准问法）

向目标用户展示概念陈述后，问：

> 「如果有这样一款产品，您**购买的可能性有多大**？请用以下刻度表示：」

| 分值 | 标签 | 含义 |
|------|------|------|
| 5 | 非常可能购买 | 产品上市一定会买 |
| 4 | 可能购买 | 很可能会买 |
| 3 | 不确定 | 说不准 |
| 2 | 可能不买 | 不太会买 |
| 1 | 非常不可能购买 | 一定不会买 |

### Top-2 购买意向率计算

```
Top-2 购买意向率 = (选5的人数 + 选4的人数) / 总受访人数 × 100%
```

| Top-2 结果 | 判定 |
|------------|------|
| ≥ 60% | ✅ 强购买意向，推荐推进 |
| 40%-60% | ⚠️ 中等意向，需优化概念后重测 |
| < 40% | ❌ 弱意向，不推荐推进 |

## 三、概念筛选评分表（多维度）

当同时测试多个概念时，用此表打分筛选：

| 评分维度 | 权重 | 概念A(0-10分) | 概念B(0-10分) | 概念C(0-10分) |
|---------|------|----------------|----------------|----------------|
| 购买意向（Top-2） | 30% | | | |
| 独特性（与竞品差异） | 20% | | | |
| 可实现性（技术/成本） | 20% | | | |
| 战略契合度 | 15% | | | |
| 市场规模感知 | 15% | | | |
| **加权总分** | 100% | **=SUM** | **=SUM** | **=SUM** |

> 评分标准（0-10分）：
> - 9-10：非常强
> - 7-8：较强
> - 5-6：一般
> - 3-4：较弱
> - 0-2：非常弱

## 五、测试结果判定卡

| 指标 | 通过标准 | 实际值 | 判定 |
|------|---------|--------|------|
| Top-2 购买意向率 | ≥ 50% | ___% | ✅/❌ |
| 独特性评分均值 | ≥ 7/10 | ___/10 | ✅/❌ |
| 可实现对行性评分 | ≥ 6/10 | ___/10 | ✅/❌ |
| 提及「最担心」中有超过50%提到同一问题 | 否 | 是/否 | ✅/❌ |

**综合判定**：
- ✅ 全部通过 → 推荐推进到 MVP 阶段
- ⚠️ 部分通过 → 优化概念后重新测试
- ❌ 多数不通过 → 不推荐推进，回到需求挖掘阶段

---

## 六、与 MVP 测试的区别

| 维度 | 概念测试 | MVP 测试 |
|------|----------|----------|
| 阶段 | 产品开发前 | 产品开发后（或有原型） |
| 测试对象 | 概念陈述（文字/图片） | 可交互的产品/原型 |
| 样本量 | 小（30-50人） | 小→中（50-200人） |
| 核心问题 | 「你会买吗？」 | 「你用了，会持续用吗？」 |
| 决策输出 | Go/No-Go → MVP | Go/No-Go → 正式发布 |
