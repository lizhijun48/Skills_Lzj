# pd-portfolio-management · 产品组合管理

> **核心定位**：回答"有限资源投到哪里"——在多个产品/项目之间做出最优配置。

## 核心工作流程

### Step 1：产品组合盘点

**组合盘点清单**：

| 产品/项目 | 阶段 | 年收入 | 年投入 | 净贡献 | 战略对齐度 | 资源占用 |
|-----------|------|--------|--------|--------|-----------|----------|
| 产品A | 成长期 | | | | 高/中/低 | __人+__万 |
| 产品B | 成熟期 | | | | 高/中/低 | __人+__万 |
| 产品C(新) | 发现期 | 0 | | 负 | 高/中/低 | __人+__万 |

**实操规则**：
- 盘点范围包括：在售产品 + 在研产品 + 已批准待启动产品 + 评估中机会
- 净贡献=年收入-年投入（含人力成本）
- 战略对齐度=与pd-product-strategy的对齐检查结果

### Step 2：组合选择（4种方法）

**方法选择决策表**：

| 场景 | 推荐方法 | 原因 |
|------|----------|------|
| 候选≤10个，决策者3-5人 | 评分法 | 简单透明，易达成共识 |
| 需要量化财务回报 | 财务法 | ROI/NPV/IRR直接比较 |
| 多业务单元，各有战略重点 | 战略桶 | 按战略分配预算再选项目 |
| 候选>10个，需快速可视化 | 视觉法(气泡图) | 一图看全貌 |

#### 方法1：评分法（最常用）

```
评分维度（与pd-go-nogo的8维度对齐）：

维度           权重    产品A   产品B   产品C
─────────────────────────────────────────
战略对齐度      25%     4      3      5
市场吸引力      20%     5      3      4
财务回报        20%     4      5      2
技术可行性      15%     3      4      3
资源可用性      10%     3      4      2
风险可控性      10%     4      3      2
─────────────────────────────────────────
加权总分                3.95   3.65   3.30
排名                    1      2      3
```

**实操**：直接复用pd-go-nogo的8维度评分，额外加入"与现有组合的互补性"维度

#### 方法2：财务法

| 财务指标 | 产品A | 产品B | 产品C |
|----------|-------|-------|-------|
| NPV(净现值) | 500万 | 800万 | 200万 |
| IRR(内部收益率) | 35% | 25% | 15% |
| 投资回收期 | 1.5年 | 2年 | 3年 |
| EVA(经济增加值) | 300万 | 400万 | 50万 |

**决策规则**：NPV>0且IRR>资本成本率（通常15%）→ 财务可行

#### 方法3：战略桶

```
总预算：1000万

战略桶1：核心业务维护（30%=300万）
  └─ 产品A升级：200万  ☑入选
  └─ 产品B优化：100万  ☑入选

战略桶2：新市场拓展（40%=400万）
  └─ 产品C开发：300万  ☑入选
  └─ 产品D调研：100万  ☑入选

战略桶3：创新探索（20%=200万）
  └─ 产品E PoC：150万  ☑入选
  └─ 产品F概念验证：50万  ☑入选

战略桶4：技术储备（10%=100万）
  └─ 技术预研：100万  ☑入选
```

#### 方法4：视觉法（气泡图）

```
                    高
                    │  ●A
              回报  │      ●B
                    │
                    │          ●C
                    │  ●D
                    │
                    低──────────────
                      低    风险    高

气泡大小=投资规模    位置=风险-回报
A: 低风险高回报=首选   B: 中风险中回报=可选
C: 高风险中回报=谨慎   D: 低风险低回报=维持
```

### Step 3：组合平衡

**3维平衡检查**：

| 维度 | 平衡标准 | 不平衡信号 | 调整方向 |
|------|----------|-----------|----------|
| **风险-回报** | 60%低风险+40%高风险 | 全低风险=无增长；全高风险=生存危机 | 增加探索性项目或减少投机项目 |
| **长-短期** | 70%短期收益+30%长期布局 | 全短期=吃老本；全长期=现金流断裂 | 确保短期养长期 |
| **跨市场/技术** | 不超40%集中在单一市场/技术 | 单一依赖=系统性风险 | 分散到2-3个市场/技术 |

**波士顿矩阵快速定位**：

| 象限 | 特征 | 策略 | 资源分配 |
|------|------|------|----------|
| **明星** | 高增长+高份额 | 投入资源，保持增长 | 优先投入 |
| **现金牛** | 低增长+高份额 | 维持运营，抽取利润 | 维持投入 |
| **问题** | 高增长+低份额 | 选择性投入或放弃 | 谨慎投入 |
| **瘦狗** | 低增长+低份额 | 逐步退出 | 减少投入→退市 |

### Step 4：资源分配与管道管理

**资源分配原则**：
1. **核心业务优先**——确保现金牛/明星产品资源充足
2. **战略项目保障**——战略级新项目至少分配20%资源
3. **探索项目小额多投**——用最小资源验证最多假设
4. **预留15%弹性**——应对突发需求/机会

**管道管理模型**：

```
  机会池          评估中         开发中        上市/运营
  ┌────┐        ┌────┐        ┌────┐        ┌────┐
  │ ●● │──Go──→│ ●● │──启动──→│ ●● │──上线──→│ ●● │
  │ ●● │        │ ●● │        │ ●● │        │ ●● │
  │ ●  │        │    │        │    │        │    │
  └────┘        └────┘        └────┘        └────┘
   宽入口         筛选过滤       窄管道        持续运营

管道平衡目标：
- 机会池：5-8个（持续补充）
- 评估中：2-3个（快速决策）
- 开发中：2-3个（聚焦执行）
- 运营中：按产品线管理
```

**资源瓶颈识别**：

| 瓶颈类型 | 信号 | 解决方案 |
|----------|------|----------|
| 人力瓶颈 | 项目排队等开发 | 延迟低优先级项目/外部协作 |
| 资金瓶颈 | 好项目无法启动 | 分阶段投入/MVP验证 |
| 时间瓶颈 | 同期项目过多 | 错开启动时间/减少WIP |

### Step 5：组合评审

**评审节奏**：

| 评审类型 | 频率 | 参与者 | 输出 |
|----------|------|--------|------|
| 月度管道Review | 月度 | PM+研发负责人 | 管道状态更新 |
| 季度组合Review | 季度 | PM+管理层 | 优先级调整+资源再分配 |
| 年度战略Review | 年度 | PM+CEO+高管 | 组合战略方向确认 |

**季度组合Review议程**（60分钟）：
1. 现有组合健康度（10min）：3维平衡检查结果
2. 各产品进展与异常（15min）：红/黄/绿状态
3. 新机会评估结论（10min）：pd-go-nogo结果
4. 优先级调整讨论（15min）：升/降/保持/终止
5. 资源再分配决定（10min）：具体到人+预算

**终止决策（最难也最重要）**：

| 终止信号 | 具体表现 | 行动 |
|----------|----------|------|
| 市场变化 | 原有市场萎缩>30% | 启动退市评估 |
| 技术失败 | 核心技术3次迭代仍未验证 | 终止或换方向 |
| 战略偏移 | 公司战略调整，产品不再对齐 | 转让或终止 |
| 资源挤占 | 高优项目资源不足 | 降级或暂停低优项目 |
| 长期亏损 | 连续2年净贡献为负 | 退市流程 |

## 即用工具

### 工具1：优先级快速排序（成对比较法）

当评分法争议太大时，用成对比较强制排序：

```
产品列表：A, B, C, D

比较矩阵（每对比较，胜者得1分）：
      A    B    C    D
A     -    ?    ?    ?
B     ?    -    ?    ?
C     ?    ?    -    ?
D     ?    ?    ?    -

填写规则：A vs B，哪个更优先？如果A→A行B列=1
汇总得分排序即为优先级
```

## 踩坑预警

| # | 坑点 | 表现 | 规避 |
|---|------|------|------|
| 1 | **什么都想做** | 所有项目都是"高优先级" | 优先级必须有排序，不存在并列第一 |
| 2 | **不敢终止** | "再给3个月看看"×N次 | 设定明确的终止条件，到了就执行 |
| 3 | **资源幻觉** | 计划10个并行但团队只够5个 | WIP限制=团队容量×0.8（留弹性） |
| 4 | **平衡假象** | 表面平衡但核心维度缺失 | 3维平衡每季度必须量化检查 |
| 5 | **评审走过场** | Review变成汇报会 | 每次Review必须有至少1个"终止/降级"讨论 |

## 政企产品专项支持（ToG/ToB）

### ToG组合管理特殊考量

| 维度 | ToG差异 | 实操要点 |
|------|---------|----------|
| 财务法 | 政府项目回款周期长 | NPV计算用8-10%折现率（反映回款风险） |
| 战略桶 | "国产化替代"桶可能占40%+ | 单独设立"信创"战略桶 |
| 资源分配 | 实施团队>研发团队 | 人力分配7:3（实施:研发） |
| 评审节奏 | 与财政年度强绑定 | Q1定方向，Q3调整，Q4总结 |

### ToB组合管理特殊考量

| 维度 | ToB差异 | 实操要点 |
|------|---------|----------|
| 组合平衡 | KA定制vs标准产品冲突 | 20%资源给KA定制，80%给标准产品 |
| 终止决策 | 大客户依赖导致无法终止 | 终止前需有替代方案或过渡期 |
| 资源瓶颈 | 实施交付是最大瓶颈 | 组合决策需实施团队参与 |

## 核心原则

1. **组合≠项目列表**——组合是有策略的资源分配，不是所有项目的简单加总
2. **优先级必须有序**——"所有都重要"="所有都不重要"，必须排出1-2-3
3. **终止是一种能力**——敢终止比敢启动更考验产品经理
4. **平衡是动态的**——每季度重新检查3维平衡，不是一次搞定
5. **资源是硬约束**——在资源边界内做选择，不是先选再加资源
6. **评审必须有动作**——没有终止/降级讨论的Review=浪费所有人时间
