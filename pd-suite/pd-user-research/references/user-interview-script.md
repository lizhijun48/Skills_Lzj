# 用户访谈脚本模板（User Interview Script）

> 用途：标准化用户访谈流程，确保每次访谈都能获取有效信息。
> 适用场景：需求挖掘、概念测试、可用性测试、产品满意度调研。
> 对标：NPDP Ch4 + `pd-user-research` Step 2

---

## 一、访谈前准备清单

- [ ] 访谈目标明确（本次访谈要回答的 3 个核心问题）
- [ ] 受访者筛选标准（Persona 匹配度 ≥ 70%）
- [ ] 访谈脚本已准备（本模板）
- [ ] 录音/笔记工具 ready（需征得受访者同意）
- [ ] 时长控制：45-60 分钟（含 10 分钟缓冲）

---

## 二、标准访谈脚本（45 分钟版）

### 开场（5 分钟）

```
感谢您参加今天的访谈。我是 [姓名]，负责 [产品名称] 的产品设计。

本次访谈目的：[一句话说明，如"了解您平时如何管理任务"]

⚠️ 重要说明：
- 没有对错之分，您的真实感受最有价值
- 我们在测试产品，不是测试您
- 可以任何时候打断、补充、纠正

您的发言将被 [录音/笔记]，仅用于产品改进，不会对外泄露。
```

---

### 暖身问题（5 分钟）

```
Q1：请简单介绍一下您自己和您目前的工作/生活状态？

Q2：您平时用什么工具/方法来 [与目标相关的行为]？

Q3：最近一次 [目标行为] 是什么时候？能描述一下过程吗？
```

> **提问技巧**：多用「如何」「什么」「能举个例子吗」，少用「是不是」「对不对」

---

### 核心探索（25 分钟）

#### 探索1：现状与痛点

```
Q4：您现在是怎么 [完成某件事] 的？能演示一下吗？

Q5：在这个过程中，最让您头疼/浪费时间的是哪一步？

Q6：您尝试过哪些其他方法？为什么放弃了？
```

#### 探索2：需求挖掘（JTBD）

```
Q7：您雇用 [现有工具/方法] 来帮您完成什么「进步」？

Q8：如果可以许一个愿，您最希望 [某件事] 变成什么样？

Q9：有什么是您一直想做、但现有工具做不到的？
```

#### 探索3：概念测试（如有原型/概念陈述）

```
Q10：这是我们的想法 [展示概念]，您第一感觉是什么？

Q11：这解决了您的某个问题吗？哪个？

Q12：如果上市了，您会考虑用吗？为什么？
```

---

### 收尾（5 分钟）

```
Q13：如果可以改进一件事，您最希望改进什么？

Q14：您还有想分享但我们没问到的吗？

感谢您的时间！[如有礼品卡/优惠券，此时送出]
```

---

## 三、概念测试专用脚本（15 分钟快版）

> 适用场景：已有概念陈述板，需要快速验证

```
【展示概念陈述板，给受访者 1 分钟阅读】

Q1：您觉得这个产品是做什么的？（理解度检查）

Q2：这东西对您有用吗？什么场景下有用？（相关性）

Q3：如果有，您会买吗？（购买意向 1-5）

Q4：您觉得它和 [竞品] 最大的区别是什么？（差异化感知）

Q5：有什么让您担心的吗？（风险点挖掘）
```

---

## 四、可用性测试脚本（有原型时）

```
【任务卡，逐项完成】

任务1：[一句话描述任务，如"创建一个新项目并邀请同事加入"]
  - 成功/失败：
  - 用时：_____ 秒
  - 犹豫点：[记录鼠标停顿/反复点击的位置]

任务2：...
任务3：...

【任务完成后追问】
- 刚才哪个步骤最让你困惑？
- 如果给这个流程打分（1-10），你打几分？为什么？
```

## 五、访谈笔记模板（实时填写）

|------|---------------------|---------|---------|
| 00:05 | "[原话]" | [我的理解] | [是否需要追问] |
| 00:12 | | | |
| 00:23 | | | |

> **重要**：记录受访者原话，而非你的总结！原话更有说服力。

## 六、访谈后 1 小时内必做

- [ ] 整理录音/笔记，提取关键原话 3-5 条
- [ ] 更新 Persona（如有新发现）
- [ ] 更新 CJM（标注新的痛点）
- [ ] 将需求写入需求池（标注来源：访谈 R-XXX）
- [ ] 团队同步：向产品/研发/运营分享 3 个核心发现
