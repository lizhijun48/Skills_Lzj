# 交易结构分析器（Transaction Structure Analyzer）

> 版本：v1.0 | 建立：2026-08-31

## 0. 一句话定位

不看广告词、不看财报口径，把一家公司（或一个项目、一次合作）还原成**一张"谁和谁、拿什么换什么、风险沿哪条边流动"的结构图**——这张图就是它的商业模式本体。图上有结构性硬伤的方案，PPT 再漂亮也不做。

## 1. 四步分析法

### Step 1：列出全部利益相关者（含隐性方）

按 Salience 模型（权力×合法性×紧迫性）扫一遍，但**必须额外追问三类常被漏掉的隐性方**：
- **被补贴方**：谁在收钱却不提供对价？钱从哪条边流过来？
- **被替代方**：这个结构成立后，谁的生意没了？他会如何反击（监管、价格战、另起炉灶）？
- **沉默方**：数据、环境、终端用户等"不在桌上但承担后果"的角色。

### Step 2：每条交易回答三问

| 三问 | 回答要求 | 判据来源 |
|---|---|---|
| 对手方**为什么愿意**？ | 用对手方的利益单位表述（他的成本/收益/考核指标），禁止用"双赢/赋能"等空词 | 卷1 p067 |
| 他有什么**替代选项**（BATNA）？ | 写出他不做这单时的次优选择及价格；次优越差，我方议价力越强 | 卷2 p160–164 博弈 |
| **风险沿什么条款流到他头上**？ | 对照合同类型矩阵：固定总价=卖方担风险，成本补偿=买方担风险，分成=共担 | 卷1 p156–160 优先/劣后 |

### Step 3：画交易结构图

```
[角色A] --钱(方向+名目)--> [角色B]
[角色A] --货/数据/流量--> [角色C]
边标注：①结算方式(固定/剩余/分成) ②风险归属 ③对手方BATNA强弱(强/中/弱)
```
节点不超过 7 个；一条边一个方向；钱/货/数据/风险四类边用不同线型。

### Step 4：找结构性硬伤（红旗清单）

- [ ] **错配风险**：某条边的承担方无法控制该风险（如让施工方承担政策变更损失）→ 必谈条款重分配
- [ ] **断裂边**：某对手方 BATNA 强于我方认知，一旦有更好替代该边即断 → 结构不成立
- [ ] **白嫖边**：有角色只进不出且无竞争压力约束 → 找到"让他上桌"的机制（参考金球游戏：改规则比讲道德有效，卷2 p171–174）
- [ ] **补贴依赖**：利润表好看全靠某条补贴边 → 问"补贴停那天，哪几条边同时死"
- [ ] **伪交易**：说不清对手方"为什么愿意"的边 → 该边大概率不存在

## 2. 输出格式（一页纸）

```
## XX业务/项目 交易结构分析
### 结构图
（Step 3 图）
### 逐边三问表
| 边 | 对手方 | 为什么愿意 | 他的BATNA | 风险归属 | 红旗 |
### 硬伤与处置
1. [断裂边] ... → 处置：重谈/放弃/加排他条款
### 一句话结论
这个结构赚的是 ______ 的钱，来自 ______ 被让渡的利润；它成立的前提是 ______（该前提能维持多久？）。
```

## 3. 微型示例：政务项目联合体

某集成商牵头投标，拉两家软件公司入联合体，按资质分工、按合同额比例分款（牵头方60%）。
- 三问成员方：愿意=借牵头方资质入场；BATNA=**强**（他们同时接触另外两家集成商）；风险=违约责任按合同"各自承担所负责部分"，但业主只找牵头方——**牵头方实际承担成员方履约风险**。
- 红旗：错配风险（牵头方担了不可控风险）+ 断裂边（成员方BATNA强）。
- 处置：成员方保函/履约保证金（把风险流回可控方）；缩短成员方决策链条的背靠背条款；或改分成制让成员方分享提前完工收益（机制设计，不靠忠诚）。

## 4. 与现有工具的关系

| 工具 | 关系 |
|---|---|
| BMC 九格 | BMC 是"填什么"，本分析器是"填完后的复核"——每格先过 Step 2 三问再落笔 |
| 合同类型矩阵（pm-procurement-quality） | 本分析器 Step 2 第三问的查询表；从采购场景升格为通用风险分配判据 |
| Salience 模型 | Step 1 的扫描器 |
| perspective-kernel 第1步 | "本质在关系/结构"的操作化：交易结构图就是那张"关系" |
| Go/No-Go 8维 | 商业维（D1/D7）评估建议先出结构图再打分，避免对着叙事打分 |

## 5. 边界声明

- 本分析器不替代财务测算（economic-suite NPV/IRR 负责量化，本工具负责定性结构判断）
- 对手方"为什么愿意"的答案来自访谈与公开信息，无法验证时标注[假设]并列入待验证清单
