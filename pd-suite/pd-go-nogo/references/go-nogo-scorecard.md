# Go/No-Go 评估评分表（Go-NoGo Scorecard）

> 用途：在立项前对产品机会进行 8 维度量化评估，输出 Go/No-Go 决策。
> 适用场景：新产品立项、重大功能投入决策、资源分配优先级判断。
> 对标：NPDP Ch1 + `pd-go-nogo` Step 2

---

## 一、8 维度评分表（标准版）

> 权重口径与 `pd-go-nogo` SKILL.md Step 3 一致；本表为 Excel 友好的 0-10 分制版本，`SKILL.md` 的 1-5 分制按 ×2 换算。

| # | 评估维度 | 权重 | 评分(0-10) | 概率p | 支付V（金额） | 期望支付 p×V | 加权分 | 一票否决 |
|---|---------|------|-----------|-------|--------------|-------------|--------|---------|
| 1 | **市场吸引力**（TAM/SAM/SOM, 增长率） | 20% | | | SOM×毛利率（必填） | | | — |
| 2 | **技术可行性**（技术成熟度, 团队能力匹配） | 15% | | | — | — | | — |
| 3 | **财务回报**（ROI ≥ 30%, NPV > 0, 回收期 < 2年） | 20% | | | 3年净收益−初始投入（必填） | | | — |
| 4 | **战略契合度**（与公司战略/愿景对齐程度） | 15% | | | — | — | | — |
| 5 | **合规与政策风险**（法规/资质/数据合规） | 10% | | | — | — | | ⚠️ 可否决 |
| 6 | **资源可获得性**（人力/预算/设备是否到位） | 10% | | | — | — | | — |
| 7 | **竞争态势**（竞争格局, 进入壁垒） | 5% | | | — | — | | — |
| 8 | **时机窗口**（是否是最佳进入时机） | 5% | | | — | — | | — |
| | **合计** | **100%** | | | | **=SUM(期望支付)** | **=SUM(加权分)** | |

> **评分标准（分数 = 该维度判断成立的概率，不是"好/中/差"的印象）**：
>
> | 评分 | 概率区间 | 语言锚 | 举证要求 |
> |------|----------|--------|----------|
> | 9-10 | >70% | 极可能成立 | 已有硬证据（意向合同/实测数据/权威报告） |
> | 7-8 | 51–70% | 大概率成立 | 有支持证据，但存在反例 |
> | 5-6 | 31–50% | 可能成立 | 证据不充分，主要靠类比推断 |
> | 3-4 | 11–30% | 小概率成立 | 仅有零散信号 |
> | 0-2 | ≤10% | 几乎不成立 | 已有明确反证 |
>
> 给不出证据的维度，最高只能打 6 分。

**计算公式**：
```
加权总分 = Σ(评分 × 权重) × Π(通过_i ? 1 : 0)    i ∈ {否决项}
满分 = 10.00
任一否决项为 ❌ → 乘零因子 = 0 → 总分归零 → No-Go
```

## 二、一票否决项检查（必须先过这关）

| 否决项 | 检查标准 | 是否通过 | 说明 |
|---------|---------|---------|------|
| 合规性 | 产品不违反法律法规/行业监管 | ✅/❌ | |
| 核心资源 | 关键资源（专利/牌照/独家数据）可获得 | ✅/❌ | |
| 技术可行性 | 核心技术问题已有解决方案 | ✅/❌ | |
| 市场存在 | TAM > 1亿 或 SAM > 1000万 | ✅/❌ | |

> **规则**：任一否决项为 ❌ → 乘零因子 = 0 → 加权总分归零 → 直接输出 **No-Go**（否决项不是扣分项，不给任何维度"用高分抵分"的机会）。

## 三、评分结果判定

| 加权总分 | 决策建议 | 后续动作 |
|-----------|---------|---------|
| ≥ 7.6 | ✅ **Go（推荐推进）** | 进入下一阶段（PRD/立项报告） |
| 6.00 - 7.59 | ⚠️ **Conditional Go（有条件推进）** | 针对低分维度制定改进计划，1个月后重评 |
| 5.00 - 5.99 | ⏸️ **Hold（暂缓）** | 放入机会池，6个月后重评 |
| < 5.0 | ❌ **No-Go（不推荐推进）** | 终止或搁置，资源转向其他机会 |

> 阈值与 `pd-go-nogo` SKILL.md 的 1-5 分制阈值（3.80 / 3.00 / 2.50）×2 等价。
>
> **期望支付优先规则**：合计期望支付 ≤ 0 时，无论总分落在哪一档，一律降级一档（Go→Conditional、Conditional→Hold、Hold→No-Go）。概率高但赔率亏本的机会仍然是坏机会。

## 七、敏感性分析（Tornado Chart）

> **目的**：识别哪个变量对 NPV/EMV 影响最大，指导资源优先投入方向。  
> **调用工具**：`economic-sensitivity` SKILL（位于 `economic-suite/economic-sensitivity/SKILL.md`）

### 关键变量（默认5个）

| 变量 | 基准值 | -20% 情景 | +20% 情景 | 敏感度 |
|------|--------|-----------|-----------|--------|
| 市场渗透率（SOM占比） | ___% | ___% → EMV=___万 | ___% → EMV=___万 | ⭐⭐⭐⭐⭐ |
| 单价/ARPU | ___元 | ___元 → EMV=___万 | ___元 → EMV=___万 | ⭐⭐⭐⭐ |
| 毛利率 | ___% | ___% → EMV=___万 | ___% → EMV=___万 | ⭐⭐⭐ |
| 获客成本 CAC | ___元/用户 | ___元 → EMV=___万 | ___元 → EMV=___万 | ⭐⭐ |
| 折现率 WACC | ___% | ___% → NPV=___万 | ___% → NPV=___万 | ⭐ |

### 分析方法

1. **单变量扰动**：每个变量在基准值 ±20% 范围内变动，其他变量保持不变
2. **记录 NPV/EMV 变化幅度**：按影响幅度从大到小排序
3. **绘制 Tornado Chart**：可视化展示各变量的敏感度

### 决策启示

- **若渗透率敏感度最高** → 优先投入市场验证资源（客户访谈/着陆页测试/MVP）
- **若 CAC 敏感度低** → 不必过度优化获客成本，先验证核心需求
- **若折现率敏感度高** → 项目风险集中在融资端，需提前锁定资金

### 与 economic-sensitivity 的协作接口

```
pd-go-nogo Step 3 (D3财务回报)
  ↓ 完成NPV计算后调用
economic-sensitivity
  ↓ 输出敏感度排名 + BEP临界值
返回 Tornado Chart 数据表 + 风险应对建议
```

**调用示例**：
```markdown
用户输入：
"帮我做敏感性分析。基准 NPV = 5910 万，渗透率 3%，ARPU 500元，毛利率 40%，CAC 100元，WACC 10%。"

economic-sensitivity 输出：
## 敏感性分析结果

### 敏感度排名
| 变量 | 敏感度系数 | 盈亏平衡点 | 风险等级 |
|------|-----------|-----------|---------|
| 渗透率 | 2.8 | 下降至 1.8% | 🔴 高 |
| ARPU | 2.1 | 下降至 380元 | 🟡 中 |
| 毛利率 | 1.5 | 下降至 28% | 🟢 低 |

### 决策建议
- 项目可行性高度依赖**市场渗透率达标**
- 建议在立项前：与至少 3 家试点客户签订意向协议，确保渗透率 ≥2%
```
