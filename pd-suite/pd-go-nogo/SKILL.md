# pd-go-nogo · 产品机会评估与Go/No-Go决策

> **核心定位**：产品经理的"第一道关"——在投入资源之前，用量化方法判断"做还是不做"。
> **NPDP对标**：Ch1 产品战略（创新战略与产品路线图的对齐）+ Ch2 组合管理（机会筛选与优先级排序）

| 标准/框架 | 关联内容 |
|-----------|----------|
| NPDP Body of Knowledge | Ch1 战略对齐、Ch2 组合平衡、Ch7 生命周期决策 |
| PMBOK第6版 | Ch4 整合变更控制、Ch11 风险管理 |

> **调用说明**：
> 1. D3财务回报维度若涉及多期现金流（如3年以上项目），优先调用 `economic-npv` 计算净现值，而非使用"财务粗算模板"的简化ROI公式。调用路径：`pd-go-nogo` → 识别需要NPV计算 → 调用 `economic-npv` → 将NPV结果映射为D3维度得分（NPV>0=5分，NPV=0附近=3分，NPV<0=1分）。
> 2. D3财务回报维度若需要精确计算投资回收期（特别是政府项目，财政资金使用效率考核必看），优先调用 `economic-payback` 计算静态/动态回收期，而非使用"3分钟速算"。调用路径：`pd-go-nogo` → 识别需要回收期计算 → 调用 `economic-payback` → 将回收期结果映射为D3维度得分（回收期<行业基准=5分，接近基准=3分，>基准=1分）。

## 核心工作流程

### Step 1：机会信号捕捉

**8大机会信号来源**：

| # | 信号来源 | 捕捉方法 | 信号强度判断 |
|---|----------|----------|-------------|
| 1 | 客户反馈/投诉 | 客服工单分析、客户访谈、NPS | 反复出现的痛点=强信号 |
| 2 | 竞品动态 | 竞品监控、行业报告、招聘信息 | 头部竞品新动作=强信号 |
| 3 | 技术趋势 | Gartner Hype Cycle、论文、开源项目 | 技术成熟度曲线拐点=中强信号 |
| 4 | 政策法规 | 政府文件、行业白皮书、标准更新 | 新强制性标准=极强信号 |
| 5 | 销售前线 | 丢单分析、客户需求池、渠道反馈 | 3+客户同需求=强信号 |
| 6 | 内部战略 | 董事会决议、年度规划、OKR | 战略级要求=极强信号 |
| 7 | 数据异常 | 用户行为数据、转化漏斗、留存曲线 | 数据拐点=中信号，需验证 |
| 8 | 生态伙伴 | 供应商、集成商、平台方动态 | 头部伙伴战略转向=中强信号 |

**实操规则**：
- ≥3个独立信号指向同一方向 → 进入Step 2
- 仅1个弱信号 → 放入机会池观察，不启动评估

### Step 2：初筛过滤（3分钟快判）

在投入深度评估之前，用3个问题快速过滤：

```
┌──────────────────────────────────────────────────┐
│  初筛快判表（任一否决即终止，不浪费评估资源）      │
├──────────────────────────────────────────────────┤
│  Q1: 这是否属于我们的战略范围？                     │
│      ☐ 是（公司战略文档有明确支撑）                  │
│      ☐ 不确定（需要和上级确认）                      │
│      ☐ 否 → 终止                                  │
│                                                    │
│  Q2: 我们是否有能力做？（技术+团队+资金至少一项）    │
│      ☐ 有明确能力                                  │
│      ☐ 可通过合作/招聘获得                          │
│      ☐ 完全没有 → 终止                             │
│                                                    │
│  Q3: 是否有法律/合规硬伤？                          │
│      ☐ 无合规风险                                  │
│      ☐ 有风险但可规避                               │
│      ☐ 有硬性禁止 → 终止                           │
└──────────────────────────────────────────────────┘
```

**通过标准**：3题均非"终止" → 进入Step 3深度评估

### Step 3：8维度深度评估

#### 8维度评分卡（每维度1-5分，加权汇总）

| 维度 | 权重 | 1分（极差） | 3分（中等） | 5分（优秀） | 得分 |
|------|------|------------|------------|------------|------|
| **D1 市场吸引力** | 20% | TAM<1亿，增速<5% | TAM 1-10亿，增速5-15% | TAM>10亿，增速>15% | |
| **D2 技术可行性** | 15% | 核心技术不存在，需3年+研发 | 技术有验证但需适配 | 技术成熟，团队有经验 | |
| **D3 财务回报** | 20% | ROI<0，3年无法盈亏平衡 | ROI 10-30%，2年回本 | ROI>30%，1年内回本 | |
| **D4 战略对齐** | 15% | 与战略方向无关 | 间接相关，需转化 | 核心战略支撑 | |
| **D5 合规与风险** | 10% | 存在合规硬伤/重大风险 | 有风险但可控 | 完全合规，风险极低 | |
| **D6 资源就绪度** | 10% | 需新招核心团队+大额投资 | 需调配部分资源 | 团队+资金+基础设施均就绪 | |
| **D7 竞争态势** | 5% | 巨头垄断，无差异化空间 | 有竞品但存在差异化空间 | 蓝海或明显差异化优势 | |
| **D8 时机窗口** | 5% | 窗口已关闭或远未到来 | 窗口打开但即将关闭 | 正在最佳窗口期 | |

**加权总分计算公式**：
```
总分 = Σ(维度得分 × 权重)
满分 = 5.00
```

**决策阈值**：

| 加权总分 | 决策 | 后续动作 |
|----------|------|----------|
| ≥ 3.80 | ✅ **Go** | 立即启动，进入产品规划 |
| 3.00 - 3.79 | ⚠️ **Conditional Go** | 修正弱项后重新评估（最多1轮） |
| 2.50 - 2.99 | ⏸️ **Hold** | 放入机会池，6个月后重新评估 |
| < 2.50 | ❌ **No-Go** | 记录原因，归档，不启动 |

#### 一票否决项（Veto Items）

以下任一项成立 → **直接No-Go**，无论总分多高：

| # | 否决项 | 说明 | 典型场景 |
|---|--------|------|----------|
| V1 | 法律禁止 | 产品/功能违反现行法律法规 | 未经授权收集个人隐私数据 |
| V2 | 核心技术不可获得 | 关键技术无来源且无法自研 | 需要美国出口管制芯片 |
| V3 | 无市场准入资格 | 缺少行业必需资质/牌照 | 政企项目无相关安全资质 |
| V4 | 预算缺口>50% | 资金缺口大且无明确融资方案 | 需要2000万，仅1000万预算 |
| V5 | 战略严重冲突 | 与公司核心战略方向相悖 | 2C公司在没有2B战略下做政府项目 |
| V6 | 安全红线 | 产品存在不可接受的安全风险 | IoT设备无固件签名验证 |

**实操检查**：
```markdown
## 一票否决项检查清单
- [ ] V1 法律合规：确认不违反任何现行法律 → 法务签字
- [ ] V2 技术可获得：核心技术来源明确 → CTO签字
- [ ] V3 市场准入：必要资质/牌照齐全或可获取 → 业务负责人签字
- [ ] V4 资金到位：预算覆盖>50%成本且有融资方案 → CFO签字
- [ ] V5 战略对齐：不与核心战略冲突 → 战略负责人签字
- [ ] V6 安全可控：无不可接受安全风险 → 安全负责人签字
```

### Step 4：市场验证（Conditional Go必做，Go建议做）

**验证方法选择矩阵**：

| 市场确定性 ↓ | 技术确定性 → | 低 | 高 |
|-------------|-------------|-----|-----|
| **高** | 验证优先级：低 | 验证优先级：中（验证技术） |
| **低** | 验证优先级：高（验证市场+技术） | 验证优先级：高（验证市场） |

**5种验证方法（按成本从低到高）**：

| # | 方法 | 周期 | 成本 | 适用场景 | 输出 |
|---|------|------|------|----------|------|
| 1 | 老妈测试 | 1天 | 0 | 验证需求是否真实 | 非用户能否理解问题 |
| 2 | 着陆页测试 | 1-2周 | <5000元 | 验证需求是否存在 | 点击率/注册转化率 |
| 3 | 客户深度访谈 | 2-3周 | 0-5000元 | 验证需求痛度+付费意愿 | 5-8份访谈记录+洞察 |
| 4 | 低保真原型测试 | 3-4周 | 1-3万 | 验证解决方案方向 | 用户反馈+行为数据 |
| 5 | 众筹/MVP | 4-8周 | 5-20万 | 验证付费意愿+核心功能 | 预订单/首批用户数据 |

**验证通过标准**：
- 老妈测试：3/5非用户能准确复述问题
- 着陆页测试：点击率>5%或注册转化率>2%
- 客户访谈：5/8受访者确认痛点+4/8愿付费
- 原型测试：任务完成率>60%，SUS评分>65
- 众筹/MVP：达到预设目标的30%

## 踩坑预警

| # | 坑点 | 典型表现 | 规避方法 |
|---|------|----------|----------|
| 1 | **老板驱动vs市场驱动** | 老板说"做这个"但无市场验证 | 用8维度评分卡客观评估，用数据说话而非职级 |
| 2 | **沉没成本谬误** | "已经投入了这么多，不能停" | Go/No-Go只看未来投入产出，不看过往投入 |
| 3 | **幸存者偏差** | "竞品做了所以我们也要做" | 竞品没做但失败的你没看到，用8维度独立评估 |
| 4 | **伪需求** | 客户说"想要"但不愿付费 | 必须过Step 4市场验证，尤其是付费意愿验证 |
| 5 | **高估市场** | "全中国有14亿人，1%就是1400万" | 用TAM→SAM→SOM逐层收敛，SOM才是你的真实市场 |
| 6 | **低估复杂度** | "这个很简单，2周就能做" | 技术维度必须CTO签字，不允许产品经理单方面估算 |
| 7 | **忽视合规** | "先上线再说，合规后面补" | V1/V3/V6否决项必须前置检查，ToG/ToB无合规即无项目 |
| 8 | **独狼评估** | 产品经理一个人打分 | 8维度必须跨职能评审（技术/财务/法务各签各的维度） |

## 政企产品专项支持（ToG/ToB）

### ToG产品评估特殊维度

| 维度 | ToG特殊考量 | 评分调整 |
|------|------------|----------|
| D1 市场 | 市场规模看财政预算而非用户数；关注"数字政府""新基建"等政策驱动 | TAM以政府采购预算为上限 |
| D3 财务 | 回款周期长（3-12月），需考虑现金流压力；验收后才确认收入 | ROI计算需乘以回款折扣系数0.7-0.85 |
| D4 战略 | 必须对齐"十四五规划"等政策文件 | 战略文档=政府政策文件 |
| D5 合规 | 等保2.0/密评/国产化适配是硬门槛 | D5权重提升至15%，D7降至0% |
| D7 竞争 | 关系型竞争，非纯产品竞争 | 竞争分析加入"客户关系"维度 |
| D8 时机 | 政府预算周期（每年Q4申报，Q1审批） | 时机窗口与财政年度强相关 |

### ToG一票否决项补充

| # | 否决项 | 说明 |
|---|--------|------|

| V5-G | 与政策方向冲突 | 不符合"信创替代""国产化"等要求 |
| V6-G | 安全合规不达标 | 未通过等保2.0三级/二级要求 |

### 与pm-project-opportunity的对齐

两个SKILL都使用"8维度评估"，但视角不同：

| 维度 | pd-go-nogo视角 | pm-project-opportunity视角 |
|------|----------------|--------------------------|
| 市场 | 产品是否有市场？ | 项目是否有需求方？ |
| 技术 | 技术能否实现产品？ | 技术方案能否落地？ |
| 财务 | 产品能否赚钱？ | 项目能否在预算内完成？ |
| 战略 | 产品是否对齐战略？ | 项目是否支撑战略？ |
| 合规 | 产品是否合规？ | 项目是否合规？ |
| 资源 | 有没有能力做？ | 有没有资源执行？ |
| 竞争 | 产品是否有竞争力？ | 项目是否有竞标优势？ |
| 时机 | 上市窗口是否合适？ | 项目启动时机是否合适？ |

**流转规则**：pd-go-nogo先评产品可行性，Go后pm-project-opportunity再评项目可行性。两者Go才能正式启动。

## 输出规范

| 输出物 | 格式 | 必须/可选 |
|--------|------|----------|
| 产品机会评估报告 | 1页纸模板 | 必须 |
| 8维度评分卡 | 表格（含各维度签字） | 必须 |
| 一票否决检查清单 | 签字确认表 | 必须 |
| 市场验证结果 | 验证报告+数据 | Conditional Go必须/Go可选 |
| No-Go归档记录 | 含原因+教训 | No-Go必须 |

### 质量检查清单

- [ ] 8个维度均已评分，无空白
- [ ] 每个维度有具体证据支撑（非主观臆断）
- [ ] 一票否决6项全部检查并签字
- [ ] 加权总分计算正确
- [ ] 决策结论与分数逻辑一致（不允许3.5分但结论No-Go）
- [ ] 若Conditional Go，修正项和截止日期已明确
- [ ] 若Go，关键假设清单已列出（≤5条）
- [ ] 跨职能评审已完成（至少产品+技术+财务三方）

## 核心原则

1. **数据驱动，而非职级驱动**——8维度评分卡面前，CEO和实习生平等
2. **No-Go也是有价值的结论**——及时止损=节省资源，不启动错误项目就是最大贡献
3. **一票否决不可协商**——合规/安全/法律红线不存在"通融"
4. **假设必须显式列出**——Go决策基于的假设要在项目执行中持续验证
5. **跨职能评审不可省略**——产品独狼评估=盲人摸象，8维度必须各归其主
6. **ToG/ToB调整权重而非降标准**——合规权重提高不代表评估标准降低
7. **评估不是一次性事件**——Conditional Go需1轮修正，Hold需6月重评，Go也需在执行中验证假设
