## 核心工作流程

### Step 1：定义ICP理想客户画像

**ICP（Ideal Customer Profile）模板**：

```
ICP不是"所有可能买的人"，而是"最值得争取的前20%客户"

ICP 5要素：
1. 行业/规模：[如：100-500人的制造企业]
2. 痛点/触发条件：[如：刚被查出安全隐患，罚款压力]
3. 决策链：[谁决策→谁影响→谁使用]
4. 采购预算：[如：年IT预算50-200万]
5. 当前方案：[如：Excel+人工巡检，效率低且易出错]

评分标准：
3分=完美匹配 2分=较好匹配 1分=勉强匹配
ICP总分 ≥ 12/15 → 优先争取
ICP总分 8-11 → 可以争取但不是重点
ICP总分 < 8 → 暂不投入
```

**ToG/ToB ICP差异**：

| 维度 | ToC ICP | ToB ICP | ToG ICP |
|------|---------|---------|---------|
| 行业 | 人口统计标签 | 行业+规模 | 政府层级+部门 |
| 触发条件 | 朋友圈种草 | 业务增长瓶颈/合规要求 | 政策文件/领导批示 |
| 决策链 | 个人决策 | 采购+技术+业务3方 | 评审+审批+财政3关 |
| 采购预算 | 个人消费 | 年IT预算 | 财政预算+专项 |

### Step 2：定价策略

**6大定价模型对比**：

| # | 模型 | 做法 | 优势 | 风险 | 适用场景 |
|---|------|------|------|------|----------|
| 1 | **成本加成** | 成本×(1+利润率) | 简单、保底 | 忽略市场接受度 | 政府定价项目 |
| 2 | **竞争定价** | 参照竞品定价±调整 | 市场导向 | 价格战 | 成熟市场 |
| 3 | **价值定价** | 按用户获得的价值定价 | 利润空间大 | 价值难以量化 | 差异化产品 |
| 4 | **渗透定价** | 低价快速获取市场 | 快速占位 | 利润薄、难提价 | 平台型/SaaS |
| 5 | **撇脂定价** | 高价先赚早期用户 | 利润高 | 吸引竞品进入 | 技术领先产品 |
| 6 | **免费增值** | 基础免费+增值付费 | 用户基数大 | 免费转付费难 | 互联网产品 |

**定价决策矩阵**：

```
              竞争强度低
              │
     撇脂定价 │ 价值定价
              │
  ───────────┼───────────
              │
     渗透定价 │ 竞争定价
              │
              竞争强度高
     差异化低 ←─────→ 差异化高
```

**ToG定价特殊考量**：

| 因素 | 说明 |
|------|------|
| 财政评审 | 政府项目价格需过财政评审，不能随意定价 |
| 预算周期 | 预算1年1批，大项目需跨年预算 |
| 采购方式 | 公开招标→最低价中标风险；竞争性磋商→综合评分 |
| 运维费用 | 建设费用:运维费用 ≈ 100:15-20/年 |

> **💡 精确定价分析（可选）**
> 
> 以上的6大定价模型帮你选"定价方向"，如需进一步定量分析，可调用经济师工具：
> 
> | 分析目标 | 推荐工具 | 调用时机 |
> |---------|---------|-----------|
> | 不同价格点的NPV对比 | `economic-npv` | 需要精确计算价格对利润的影响时 |
> | 价格敏感性/弹性分析 | `economic-sensitivity` | 担心"涨价会丢客户"时 |
> | 价值定价支撑（V=F/C） | `economic-ve` | 需要证明"这个价格物有所值"时 |
> | 不同定价策略比选 | `economic-comparison` | 在多个定价方案中做决策时 |
> | 投资回收期计算 | `economic-payback` | 需要计算"多久回本"以支撑定价合理性时 |
> 
> → 是否需要调用经济师工具进行进一步分析？

### Step 4：理解技术采用生命周期

> **NPDP Ch4高频考点**：Everett Rogers的创新扩散理论（Innovation Diffusion Theory）是产品上市策略的理论基础。

**Rogers 5类采用者分类**：

| 类型 | 占比 | 特征 | 触达策略 | 产品经理启示 |
|------|------|------|---------|------------|
| **创新者(Innovators)** | 2.5% | 技术狂热者，愿意承担风险 | 技术社区、内测、产品发布会 | 不计较bug，关注技术前瞻性 |
| **早期采用者(Early Adopters)** | 13.5% | 意见领袖，追求新事物带来的竞争优势 | 行业KOL、行业大会、案例营销 | 看重"先发优势"，愿为领先付费 |
| **早期大众(Early Majority)** | 34% | 实用主义者，需要验证过的解决方案 | 案例复制、ROI分析、行业标杆 | **只有拿下这层才算真正进入主流市场** |
| **晚期大众(Late Majority)** | 34% | 保守派，跟风购买 | 套餐化、标准化、低成本 | 价格敏感，功能过剩是浪费 |
| **落后者(Laggards)** | 16% | 极度保守，只在万不得已时购买 | 不做主动营销 | 不要花精力争取 |

**跨越鸿沟（Geoffrey Moore理论）**：

```
创新者(2.5%) → 早期采用者(13.5%) → ═══鸿沟═══ → 早期大众(34%)
                                     ↑
                              最关键的跳跃
                              大多数产品死在这里
```

鸿沟产生原因：早期采用者买的是"竞争优势"，早期大众买的是"完整解决方案"——两群人需求完全不同。

### Step 5：选择滩头市场

**滩头市场选择（跨越鸿沟策略）**：

```
不要"全面开花"，先拿下1个滩头市场→再扩展

滩头市场3个条件：
1. 足够小——可以集中资源拿下
2. 足够痛——客户愿意为解决方案付费
3. 足够标杆——拿下后可复制到相邻市场

示例：
❌ "面向所有企业的AIoT平台"（太宽）
✅ "面向100-500人制造企业的安防设备管理平台"（滩头市场）

拿下滩头市场后扩展路径：
制造企业安防 → 园区安防 → 智慧社区安防 → 城市级安防平台
```

**滩头市场选择评分表**：

| 评分维度 | 权重 | 候选市场A | 候选市场B | 候选市场C |
|----------|------|----------|----------|----------|
| 市场规模(不大) | 20% | | | |
| 痛点强度 | 30% | | | |
| 竞争壁垒 | 20% | | | |
| 标杆价值 | 20% | | | |
| 资源匹配 | 10% | | | |
| **加权总分** | 100% | | | |

### Step 6：种子用户与早期用户

**3层用户策略**：

| 层级 | 角色 | 数量 | 获取方式 | 期望 |
|------|------|------|----------|------|
| **内测用户** | 产品验证 | 10-30 | 熟人/同事/已有客户 | 找Bug+核心流程验证 |
| **种子用户** | 口碑传播 | 100-500 | 定向邀请/行业社群 | 深度使用+推荐新用户 |
| **早期用户** | 规模验证 | 1000+ | 推广+渠道 | 验证商业模式+收入 |

**种子用户获取话术**：

```
"我们是做XX的团队，正在寻找[ICP描述]的用户参与早期体验。
作为种子用户，您将获得：
1. 终身免费/大幅折扣
2. 产品功能优先体验权
3. 您的需求将优先排入开发计划

作为交换，我们希望您：
1. 每周至少使用3次
2. 每月参加1次反馈访谈（30分钟）
3. 如果觉得好，愿意向同行推荐

有兴趣吗？"
```

## Step 9：发布说明模板

> **适用场景**：每次版本发布时，向用户/客户说明"变了什么"。好的发布说明能降低升级焦虑、提升用户信任。

### 发布说明模板

```markdown
# [产品名称] — [版本号 / 发布日期]

## 新功能
- **[功能名称]**：[1-2句话描述及对用户的价值]
- **[功能名称]**：[1-2句话描述]

## 改进
- **[改进方向]**：[什么变得更好了，最好有量化]
- 示例："筛选性能提升50%，万级数据不再卡顿"

## 缺陷修复
- 修复了 [用用户语言描述的问题，而非技术术语]
- 示例："修复了导出报表时偶发空白的问题"

## 破坏性变更（如有）
- **需要操作**：[用户需要做什么，如果有破坏性变更]
- 示例："旧版 API v1 将于下版本废弃，请迁移至 v2"
```

### 撰写原则

| 原则 | 说明 | 反面示例 → 正面示例 |
|------|------|----------------------|
| 以用户收益为先 | 不说"实现了XX"，而说"现在可以XX" | ❌ "实现Redis缓存层" → ✅ "仪表板加载速度提升最高3倍" |
| 使用通俗语言 | 避免技术行话 | ❌ "优化了InnoDB缓冲池" → ✅ "数据库响应更快了" |
| 每个条目1-3句话 | 不要写段落 | ❌ 3行描述 → ✅ 1-2行要点 |
| 量化改进 | 有数字更有说服力 | ❌ "快了很多" → ✅ "加载时间从3s降至0.8s" |

### 发布说明渠道

| 渠道 | 适用场景 | 格式建议 |
|------|----------|----------|
| 应用内弹窗 | 重要新功能 | 图文并茂，1-3个核心亮点 |
| 邮件推送 | ToB/SaaS版本更新 | 完整变更日志+操作引导 |
| 发布博客 | 大版本/里程碑 | 深度解读+使用案例 |
| ChangeLog文件 | 开源/开发者产品 | Markdown格式，按版本归档 |

## 踩坑预警

| # | 坑点 | 表现 | 规避 |
|---|------|------|------|
| 1 | **没有ICP就推市场** | "所有人都是我们的客户" | 先定义ICP，精准打击 |

| 6 | **发布不做复盘** | 上线1个月不知道好坏 | D+7/D+30必须复盘 |

## 政企产品专项支持（ToG/ToB）

### ToG产品上市特殊流程

```
1. 招标文件解读 → 确认我们能否满足技术参数
2. POC/演示 → 现场演示系统核心功能
3. 投标 → 技术+商务+报价（见pm-bid-proposal）
4. 中标+实施 → 项目交付
5. 验收 → 政府项目四步验收（见pm-gov-acceptance）
6. 运维期 → 持续服务+续约
```

**ToG首发关键**：
- 拿到第一个标杆项目比利润更重要
- 首个项目选择本地/关系好的客户
- 案例包装要包含"领导视察""媒体报道"等政企场景

### ToB SaaS发布策略

| 阶段 | 时间 | 关键动作 | 指标 |
|------|------|----------|------|
| 私测 | 1-2月 | 10-20家定向邀请 | NPS>30, 周活>3次 |
| 公测 | 1-2月 | 开放注册+内容营销 | 注册→激活>40% |
| 商业化 | 持续 | 定价+付费转化 | 付费率>5% |

## 核心原则

1. **ICP是上市的起点**——不知道卖给谁就推市场=浪费子弹
2. **定价是战略不是算术**——定价决定你的客户群和竞争位
3. **滩头市场先胜再扩**——不要全面开花，先拿下一个点再画线
4. **种子用户是免费的产品验证**——没有种子用户就全量发布=裸奔
5. **竞争战卡是销售的武器**——销售被竞品打脸=产品经理的失职
6. **发布只是开始不是结束**——上线后7天/30天必须复盘
7. **ToG首发靠标杆项目**——第一个案例比利润更重要
