## 核心工作流程

### Step 1：产品团队组建

**产品铁三角**（核心协作模型）：

```
         产品经理(PM)
         "做什么"
          /      \
         /        \
技术负责人(TL)  设计负责人(UD)
"怎么做"          "好用吗"
```

| 角色 | 核心职责 | 决策权 | 不做的事 |
|------|----------|--------|----------|
| **产品经理** | 需求定义+优先级+商业价值 | 做什么/不做什么 | ❌ 不写代码/不画设计稿 |
| **技术负责人** | 技术方案+架构+可行性 | 怎么做/技术选型 | ❌ 不定产品方向 |
| **设计负责人** | 用户体验+交互设计+视觉 | 怎么好用/设计规范 | ❌ 不定功能范围 |

**铁三角协作规则**：
- 每周1次30分钟同步（PM主持，TL+UD参加）
- 任何重大决策需2/3同意（不能1人拍板）
- 分歧升级：铁三角→产品总监→VP

**扩展团队配置**：

| 团队规模 | 配置 | 适用阶段 |
|----------|------|----------|
| 3人（最小） | PM+TL+UD | 探索/MVP阶段 |
| 5-7人（标准） | PM+TL+UD+2-3开发 | 开发阶段 |
| 8-12人（完整） | PM+TL+UD+5-8开发+QA | 规模化阶段 |
| 12+人（拆分） | 按产品线拆为2+个5-7人团队 | 多产品线 |

### Step 2：产品文化4维度

**NPDP创新文化4维度**：

| 维度 | 低成熟度表现 | 高成熟度表现 | 提升方法 |
|------|-------------|-------------|----------|
| **1. 战略对齐** | 各自为政，产品与战略脱节 | 所有产品决策有战略依据 | 季度战略对齐会+OKR |
| **2. 环境氛围** | 惩罚失败，不敢尝试 | 鼓励实验，容忍失败 | 失败复盘会+无责文化 |
| **3. 团队协作** | 部门墙，信息不共享 | 跨职能协作，信息透明 | 铁三角+共享看板 |
| **4. 管理实践** | 层层审批，响应慢 | 授权团队，快速决策 | RACI简化+决策权限下放 |

**文化自评打分**：

```
维度1 战略对齐：  1  2  3  4  5
维度2 环境氛围：  1  2  3  4  5
维度3 团队协作：  1  2  3  4  5
维度4 管理实践：  1  2  3  4  5

总分：____/20
≥16：健康   12-15：需改进   <12：严重问题
```

**每个维度≤3分的改进计划**（1页纸模板）：
```
当前问题：__________
目标状态：__________（3个月后达到X分）
改进动作：__________（具体可执行的3件事）
负责人：__________
检查点：每月1次评估
```

### Step 3：团队演进（塔克曼阶梯）

```
形成期 → 震荡期 → 规范期 → 表现期
(Forming) (Storming) (Norming) (Performing)
   │         │         │         │
   ▼         ▼         ▼         ▼
 礼貌客气   争吵冲突   规则建立   高效协作
 不敢发言   各自为政   信任建立   主动补位
 等待指令   情绪对立   流程顺畅   创新涌现
 
 PM角色：   PM角色：   PM角色：   PM角色：
 引导者     调解者     协调者     赋能者
```

**每个阶段的PM实操**：

| 阶段 | PM核心动作 | 避免的事 | 持续时间 |
|------|-----------|----------|----------|
| 形成 | 明确目标+角色+规则 | 过早要求高产出 | 1-2周 |
| 震荡 | 引导冲突解决+建立心理安全 | 回避冲突或强制压制 | 2-4周 |
| 规范 | 巩固流程+授权+庆祝小胜 | 事无巨细管理 | 2-4周 |
| 表现 | 赋能+移除障碍+关注成长 | 微观管理 | 持续 |

### Step 4：无授权领导力

产品经理最核心的能力之一——**在没有直接管理权的情况下推动事情发生**。

**5种无授权影响力**：

| 影响力类型 | 做法 | 适用场景 |
|-----------|------|----------|
| **数据影响** | 用数据/用户反馈说话 | 需要说服开发/设计改方案 |
| **专业影响** | 展示行业知识/竞品分析 | 需要建立专业权威 |
| **关系影响** | 提前沟通、一对一影响 | 需要获得跨部门支持 |
| **愿景影响** | 讲清楚"为什么要做" | 需要激发团队动力 |
| **互惠影响** | 先帮别人解决问题 | 需要请求他人帮忙 |

**实操：推动跨部门协作的4步法**：
1. **私下预热**——提前1对1沟通关键人物，了解顾虑
2. **数据武装**——带着用户数据/竞品分析进会议，而非"我觉得"
3. **利益对齐**——说明这件事对对方团队的好处
4. **降低门槛**——让对方需要做的事尽量简单

### Step 5：产品经理职业发展

**4级发展路径**：

| 级别 | 名称 | 核心能力 | 管理范围 | 典型年限 |
|------|------|----------|----------|----------|
| L1 | 产品助理/初级PM | 需求文档+竞品分析+数据整理 | 单一功能模块 | 0-2年 |
| L2 | 产品经理 | 需求分析+产品规划+用户研究 | 单一产品 | 2-5年 |
| L3 | 高级产品经理/产品总监 | 产品战略+组合管理+团队培养 | 产品线 | 5-8年 |
| L4 | VP产品/CPO | 公司战略+组织建设+商业决策 | 全部产品 | 8年+ |

**每级必备技能检查**：

| L1→L2 晋升关键 | L2→L3 晋升关键 | L3→L4 晋升关键 |
|----------------|----------------|----------------|
| 独立完成1个产品迭代 | 主导1个产品0→1 | 主导1个产品线战略 |
| 用户研究基本方法 | 商业分析能力 | 组织能力 |
| 数据分析能力 | 团队协作能力 | 商业决策能力 |

**NPDP 7大胜任力域**：

| 胜任力域 | 核心能力 | NPDP对应章节 | 自我评估(1-5分) |
|-----------|----------|---------------|-----------------|
| 1. 战略能力 | 战略思维/商业模式/路线图 | Ch1 产品战略 | |
| 2. 市场研究能力 | 市场分析/用户洞察/竞品分析 | Ch4 市场研究 | |
| 3. 创新管理能力 | 创新战略/创意管理/开发流程 | Ch3 新产品流程 | |
| 4. 产品开发能力 | 需求定义/PRD/跨职能协作 | Ch3 新产品流程 | |
| 5. 生命周期管理能力 | PLC各阶段/退市/版本管理 | Ch7 产品生命周期 | |
| 6. 工具与度量能力 | OKR/KPI/财务分析/优先级 | Ch6 工具与度量 | |
| 7. 领导力与文化 | 团队建设/无授权领导/创新文化 | Ch5 文化/团队/组织 | |

**产品铁三角胜任力分工**：

| 角色 | 核心胜任力 | 评估方式 |
|------|-----------|---------|
| **产品经理(PdM)** | 战略+市场+产品定义 | NPDP Level 1-2认证 |
| **项目经理(PgM)** | 交付+风控+资源 | PMP/软考 |
| **架构师/技术负责人** | 技术可行性+架构演进 | 技术评审+架构评审 | 

**NPDP认证3级能力对照表**：

| 级别 | 能力要求 | 对应产品工作 |
|------|---------|----------|
| **Level 1 (Associate)** | 掌握7大域基础知识 | 独立负责1个功能模块 |
| **Level 2 (Practitioner)** | 能独立负责1条产品线 | 主导1个产品从0→1 |
| **Level 3 (Master)** | 战略级产品决策 | 主导多产品线+平台战略 | 

**产品经理 vs 产品总监能力差异**：

| 能力维度 | 产品经理 | 产品总监 |
|-----------|----------|----------|
| 战略深度 | 执行产品战略 | 制定产品战略 |
| 市场广度 | 1-2个细分市场 | 全行业+跨行业机会 |
| 团队管理 | 跨职能协作 | 团队建设+人才培养 |
| 商业影响 | 产品线盈利 | 公司级商业结果 |

### NPDP 团队类型（轻量级/重量级/自治团队）

> **NPDP Ch5核心**：产品团队按产品经理的授权程度分为3类，不同类型的决策效率和跨职能协作深度不同。

| 类型 | 产品经理授权程度 | 团队构成 | 决策效率 | 适用场景 |
|------|-------------------|----------|---------|----------|
| **轻量级团队(Lightweight)** | 低——职能经理主导 | PM+N个职能代表（兼职） | 低——需多层审批 | 小型功能迭代、维护性产品 |
| **重量级团队(Heavyweight)** | 中——PM主导，职能经理支持 | PM+专职职能团队 | 中——PM有部分决策权 | 主流产品线、成长期产品 |
| **自治团队(Autonomous)** | 高——PM拥有完整决策权 | PM+跨职能全职团队 | 高——快速决策 | 战略性新产品、探索性项目 |

**选择原则**：

```
团队规模 < 5人 → 轻量级
产品处于导入期/成长期 → 重量级
产品是战略级/探索性 → 自治团队
```

**与塔克曼阶梯的对应**：

| 团队发展阶段 | 推荐团队类型 |
|----------------|--------------|
| 形成期(Forming) | 重量级（需要明确PM主导） |
| 震荡期(Storming) | 重量级（PM需有决策权） |
| 规范期(Norming) | 重量级→自治团队过渡 |
| 表现期(Performing) | 自治团队 |
| 解散期(Adjourning) | 轻量级（项目收尾） |

**产品经理授权能力建设**：

| 授权级别 | 可决策范围 | 需上报事项 |
|-----------|------------|------------|
| Level 1（执行） | 需求优先级排序、原型确认 | 资源申请、预算调整 |
| Level 2（协调） | 跨职能资源调配、版本规划 | 战略调整、人事变动 |
| Level 3（战略） | 产品线战略、定价策略 | 公司级战略调整 |

## 踩坑预警

| # | 坑点 | 表现 | 规避 |
|---|------|------|------|
| 1 | **PM当项目经理** | PM在排开发任务、催进度 | PM定"做什么"，TL定"怎么做" |
| 2 | **跳过震荡期** | 新团队直接要求高效产出 | 接受震荡期是正常的，2-4周可过 |
| 3 | **无授权=无影响** | PM抱怨"我管不了他们" | 用5种影响力方法，不靠职级靠能力 |
| 4 | **文化口号化** | 墙上贴"创新文化"但没人敢试错 | 文化自评量化+失败复盘会 |
| 5 | **铁三角缺一角** | PM+开发没有设计 | 缺设计=用户体验烂，必须补齐 |

## 核心原则

1. **铁三角是产品成功的最小单元**——缺任何一角（PM/TL/UD）都做不出好产品
2. **震荡期是正常的不是失败的**——新团队2-4周冲突期是必经阶段
3. **无授权领导力是PM的核心竞争力**——你的影响力不来自职级，来自专业+数据+关系
4. **文化不是口号是行为**——墙上贴标语不如每月做失败复盘会
5. **PM≠项目经理**——PM管"做什么"，TL管"怎么做"，混淆两者是团队混乱之源
