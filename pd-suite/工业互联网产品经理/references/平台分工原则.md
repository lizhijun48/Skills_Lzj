# PC端与移动端平台分工原则

> 本文档定义如何判断一个功能应该放在 PC 端还是移动端，适用于工业互联网、MES、微生产等 B 端管理系统。

---

## 一、分工核心原则

**操作复杂度决定平台，简单操作和实时查看优先移动端。**

| 维度 | PC端 | 移动端 |
|------|------|-------|
| **操作频率** | 低频（配置/分析） | 高频（报工/查看） |
| **操作复杂度** | 复杂（多字段/多步骤） | 简单（≤5步完成） |
| **输入方式** | 键盘+鼠标，精度高 | 触屏+扫码，快但粗 |
| **用户设备** | 办公室，有电脑 | 车间，工人用手机 |
| **网络环境** | 稳定（内网/WiFi） | 可能不稳定（4G/厂区信号差） |
| **实时性要求** | 一般 | 高（报工/告警需即时） |
| **数据量** | 大批量录入/查询 | 单条/少量快速操作 |
| **输出内容** | 报表/图表，需大屏 | 关键数字/状态，需一目了然 |

## 二、用户角色与平台对应

```
┌─────────────────────────────────────────────┐
│                   PC端                       │
│  生产经理 / 计划员 / 管理员                   │
│  场景：办公室，坐着，键盘鼠标，稳定网络       │
│  任务：订单配置、计划排程、数据分析           │
└─────────────────────────────────────────────┘

┌─────────────────────────────────────────────┐
│                   移动端                      │
│  班组长 / 一线工人                           │
│  场景：车间，站着/走着，手机，信号不稳定     │
│  任务：报工、点检、查看进度、处理异常        │
└─────────────────────────────────────────────┘
```

## 三、功能清单对照表

### 3.1 订单管理 — PC端专属

| 功能 | 平台 | 原因 |
|------|------|------|
| 新建/编辑订单 | PC | 多字段录入，键盘高效 |
| 订单评审 | PC | 需查看产能报表/历史数据 |
| 订单拆分 | PC | 涉及多个派工单生成，复杂操作 |
| 订单列表/查询 | PC | 大量数据筛选，键盘输入条件 |

### 3.2 生产计划 — PC端为主

| 功能 | 平台 | 原因 |
|------|------|------|
| 甘特图排程 | PC | 拖拽调整，需鼠标精度 |
| 派工单生成 | PC | 批量操作，配置复杂 |
| 派工单下发 | PC | 批量操作 |
| 插单/撤单 | PC | 涉及多方协调，复杂决策 |

### 3.3 基础数据 — PC端专属

| 功能 | 平台 | 原因 |
|------|------|------|
| 工艺库维护 | PC | 多工序编排，参数配置复杂 |
| 班组管理 | PC | 批量人员管理 |
| 设备台账 | PC | 大量设备信息维护 |
| 工序标准工时 | PC | 数据量大，需表格录入 |
| 人员权限配置 | PC | 复杂的多对多关系 |

### 3.4 报工 — 移动端专属

| 功能 | 平台 | 原因 |
|------|------|------|
| 扫码快速报工 | 移动 | 扫码只能用手机 |
| 报工（按件/按工时） | 移动 | 车间现场操作，站着/走着 |
| 报工历史查询 | 移动 | 工人查自己的报工记录 |
| 报工撤回/修改 | 移动 | 异常情况现场处理 |

### 3.5 审批 — 移动端为主

| 功能 | 平台 | 原因 |
|------|------|------|
| 班组长审批报工 | 移动 | 实时收到推送，审批要快 |
| 异常处理 | 移动 | 车间现场，快速响应 |
| 审批历史 | PC+移动 | 均可查看 |

### 3.6 数据看板 — PC+移动双端

| 功能 | 平台 | 说明 |
|------|------|------|
| 产量统计 | PC+移动 | PC看详细报表，移动看关键数字 |
| 派工单进度 | PC+移动 | PC全局视图，移动单条详情 |
| 产线/班组排名 | PC+移动 | PC全排名，移动端看自己排名 |
| 告警通知 | 移动 | 实时推送，必须手机 |

## 四、移动端设计规范

### 4.1 交互原则

- **5 步以内完成核心操作**：报工从扫码到提交最多 5 步
- **单手操作友好**：底部 TabBar，关键操作在屏幕下半部分
- **大按钮**：最小点击区域 44×44px（iOS HIG 标准）
- **容错设计**：提交前确认，操作后可撤回
- **扫码优先**：支持条码/二维码扫描快速定位派工单
- **网络容错**：离线缓存，网络恢复后自动同步

### 4.2 页面结构

```
┌──────────────────────────┐
│   导航栏（标题+操作按钮）  │  ← 小程序风格，居中标题
├──────────────────────────┤
│                          │
│       页面内容            │  ← 核心信息优先，辅助信息折叠
│       （可滚动）           │
│                          │
├──────────────────────────┤
│  TabBar（4个标签）         │  ← 底部固定：首页/报工/看板/我的
└──────────────────────────┘
```

### 4.3 信息密度

移动端信息密度要低：
- 单个卡片聚焦一个任务/一条数据
- 数字要大、关键状态要醒目（颜色+图标）
- 长文本折叠，点击展开
- 列表不超过 1 屏，必要时"查看更多"

## 五、决策树：判断功能放哪端

```
这个功能，谁来用？
    │
    ├── 工人 / 班组长 → 移动端优先
    │       │
    │       └── 操作复杂度？
    │               ├── 简单（≤5步）→ 移动端
    │               └── 复杂（多字段/批量）→ PC端，移动端看/查
    │
    └── 计划员 / 管理员 → PC端优先
            │
            └── 工人也需要用？
                    ├── 是 → PC端做，移动端做简化版（查/推）
                    └── 否 → PC端专属
```

## 六、反面案例（避免）

| 错误设计 | 问题 | 正确做法 |
|---------|------|---------|
| 移动端做订单录入 | 字段多，键盘输入痛苦 | PC端录入，移动端只查看 |
| 移动端做甘特图排程 | 触屏拖拽精度差 | PC端做，移动端推送变更通知 |
| PC端做实时报工 | 工人在车间，无法随时回办公室 | 移动端扫码报工 |
| 移动端展示大报表 | 手机屏幕小，数据密密麻麻 | PC端做大报表，移动端做关键数字卡片 |
