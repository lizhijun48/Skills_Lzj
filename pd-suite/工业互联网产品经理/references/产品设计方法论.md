# 产品设计方法论

> 本文档提供产品设计的系统性方法，包括用户角色分析、需求分析方法论、场景设计和产品文档输出规范。

---

## 一、用户角色分析

### 1.1 识别角色

产品设计的第一步是明确"谁在用这个系统"。对于微生产管理系统，典型角色包括：

| 角色 | 描述 | 使用场景 |
|------|------|---------|
| 一线工人 | 直接执行加工操作的人员 | 车间，手机，实时报工 |
| 班组长 | 负责班组日常管理和生产协调 | 车间+办公室，手机为主 |
| 生产计划员 | 负责排产、派工、订单管理 | 办公室，PC为主 |
| 生产经理 | 负责整体生产管理和决策 | PC+移动，查看看板和报表 |
| 系统管理员 | 负责基础数据维护和权限配置 | 办公室，PC |

### 1.2 角色分析维度

每个角色从以下四个维度分析：

```
角色
 ├── 目标（Goal）        — 他们想完成什么？
 ├── 痛点（Pain）        — 当前最大的困难是什么？
 ├── 场景（Scenario）   — 在什么时间/地点/情况下使用？
 └── 约束（Constraint）  — 他们的设备和网络条件如何？
```

### 1.3 需求优先级

按角色影响力和使用频率确定功能优先级：

```
                    高使用频率
                         │
        ┌────────────────┼────────────────┐
        │   1. 核心功能    │   2. 重要功能   │
        │  （必须做）     │  （尽快做）     │
        ├────────────────┼────────────────┤
        │   4. 辅助功能    │   3. 增强功能   │
        │  （暂不做）     │  （计划做）     │
        └────────────────┼────────────────┘
                         │
                    低使用频率

        高影响力 ◄─────────────────► 低影响力
```

## 二、需求分析方法

### 2.1 场景驱动设计

从具体使用场景出发，而非抽象功能列表：

```
❌ 错误：从功能出发
  "需要报工模块，需要看板模块，需要订单模块"

✓ 正确：从场景出发
  "工人老王早上8点到车间，拿出手机扫码，
   3步完成昨日派工单的报工，看到今日新工单，
   然后开始一天的工作"
```

### 2.2 用户故事格式

每个功能需求用用户故事格式描述：

```
作为 [角色]
我想要 [做某事]
以便 [达成某个目标]

示例：
作为 一线工人
我想要 扫码快速找到自己的派工单
以便 不用输入工单号就能开始报工，节省时间
```

### 2.3 需求分级

| 级别 | 含义 | 说明 |
|------|------|------|
| P0 | 核心功能 | 没有这个功能，系统无法使用 |
| P1 | 重要功能 | 显著提升效率，体验明显变好 |
| P2 | 增强功能 | 锦上添花，可后续迭代 |
| P3 | 优化项 | 体验微调，可忽略 |

## 三、信息架构设计

### 3.1 移动端信息架构

微生产移动端建议结构：

```
首页（今日概览）
  ├── 待报工任务（卡片列表）
  ├── 今日产量（数字+进度）
  └── 最新消息通知

报工（核心功能）
  ├── 扫码入口
  ├── 待报工列表
  └── 报工记录

看板（数据查看）
  ├── 产量达成率（环形图）
  ├── 各派工单进度（列表）
  └── 班组排名（可选）

我的（个人中心）
  ├── 我的报工历史
  ├── 设备点检
  └── 设置/退出
```

### 3.2 PC端信息架构

```
基础数据
  ├── 工艺库管理
  ├── 班组管理
  ├── 设备台账
  └── 人员管理

订单管理
  ├── 订单列表
  ├── 新建订单
  └── 订单分析

生产计划
  ├── 派工单管理
  ├── 甘特图排程
  └── 计划日历

数据报表
  ├── 生产日报
  ├── 产量统计
  ├── 良率分析
  └── 设备利用率
```

## 四、流程设计

### 4.1 主业务流程

```
客户需求（订单录入）
    ↓
产能评估（订单评审）
    ↓
生产计划（排产）
    ↓
任务派发（派工单 → 班组）
    ↓
生产执行（工人报工 → 班组长审批）
    ↓
过程监控（看板查看 → 异常处理）
    ↓
订单完成（数据汇总 → 报表分析）
```

### 4.2 移动端核心操作流程（5步以内）

**快速报工流程（最优路径）：**

```
第1步：扫码 / 选择派工单（< 2秒）
第2步：确认派工信息（< 1秒）
第3步：填写报工数量（< 5秒）
第4步：确认提交（< 1秒）
第5步：报工成功反馈（< 1秒）
```

## 五、数据流转设计

### 5.1 核心数据流

```
PC端录入/下发
    ↓ 订单/派工单
数据库（MySQL/SQLite/其他）
    ↓ 实时同步
移动端查询/报工
    ↓ 报工记录
数据库
    ↓ 汇总
PC端报表/看板
```

### 5.2 状态实时同步

- 移动端报工 → PC端派工单进度自动更新
- PC端派工单变更 → 移动端实时推送通知
- 移动端异常上报 → PC端班组长实时收到告警

## 六、产品文档输出规范

### 6.1 需求描述格式

每个功能需求按以下结构描述：

```markdown
## [功能名称]

### 背景
（为什么需要这个功能，解决了什么问题）

### 用户角色
（谁会用这个功能）

### 功能描述
（具体做什么，怎么做）

### 交互流程
（用户操作步骤，可附流程图）

### 信息展示
（展示哪些信息，数据来源）

### 边界条件
（异常情况如何处理：超时/无网络/数据异常）

### 优先级
（P0 / P1 / P2）

### 依赖
（依赖哪些前端/后端/接口）
```

### 6.2 移动端页面设计描述格式

```markdown
## [页面名称]

### 页面定位
（这个页面解决什么问题，属于哪个角色）

### 页面结构
├── 导航栏（标题：[名称]）
├── 主内容区
│   ├── 模块1（卡片/列表/图表）
│   └── 模块2
└── TabBar（标签1 / 标签2 / ...）

### 模块1
- 展示内容：...
- 交互行为：点击 → 跳转/弹窗
- 状态：无数据时显示...

### 状态定义
- 加载中：...
- 空状态：...
- 错误状态：...
- 成功反馈：...
```
