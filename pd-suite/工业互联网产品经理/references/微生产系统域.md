# 微生产管理系统 — 核心域知识

> 本文档定义微生产/MES 系统的核心实体、业务流程和状态机，是产品设计的基础参考。

---

## 一、核心实体关系

```
客户订单
    │
    │  ① 订单录入
    │  ② 订单评审
    │  ③ 拆分为派工单
    ↓
派工单  ←─────────────────────┐
    │                           │
    │  ④ 派发给班组/产线        │
    │  ⑤ 班组接收               │
    │  ▼                        │
    │  工序（派工单内含的工艺）  │  ⑨ 报工记录
    │  │                        │    │
    │  │  ⑥ 开始加工            │    │
    │  │  ⑦ 加工中（可多次报工） │    │
    │  │  ⑧ 完成加工            │    │
    │  ▼                        │    │
    └────────────────────────────┤
                                 │
                            ⑩ 汇总到派工单
                                 │
                                 ▼
                            订单完成 / 关闭
```

**核心原则：**
- 派工单是生产执行的最小单位
- 一张派工单对应一个工艺（完整加工流程）
- 报工记录是生产过程的数据沉淀

## 二、实体详细说明

### 2.1 客户订单

| 字段 | 说明 |
|------|------|
| 订单编号 | 系统生成，唯一标识 |
| 客户名称 | 客户信息 |
| 产品名称/型号 | 生产的具体产品 |
| 数量 | 订单总量 |
| 交期 | 客户要求的交付日期 |
| 优先级 | 普通/紧急/加急 |
| 状态 | 待评审 → 已评审 → 生产中 → 已完成 → 已发货 |
| 关联派工单 | 一对多关系 |

### 2.2 派工单

| 字段 | 说明 |
|------|------|
| 派工单编号 | 系统生成，唯一标识 |
| 关联订单 | 所属客户订单 |
| 派工工艺 | 工艺编号，定义完整加工程序 |
| 计划数量 | 本次派工的数量 |
| 班组 | 执行班组 |
| 计划开工日期 | 计划开始时间 |
| 计划完工日期 | 计划结束时间 |
| 实际开工 | 实际开始时间 |
| 状态 | 待派发 → 待接收 → 已接收 → 生产中 → 已完成 |

**工艺是什么：**
- 工艺 = 一套完整的加工流程定义（工序的组合）
- 工序 = 加工过程中的一个步骤（如：下料/冲压/焊接/喷涂/质检）
- 派工单不直接关联工序，而是关联工艺；执行时按工艺顺序依次加工

### 2.3 报工记录

| 字段 | 说明 |
|------|------|
| 报工编号 | 系统生成，唯一标识 |
| 关联派工单 | 所属派工单 |
| 报工工序 | 本次报工对应的具体工序 |
| 报工人员 | 提交报工的工人 |
| 报工时间 | 时间戳 |
| 报工数量 | 本次提交的数量 |
| 良品数量 | 其中合格品数量 |
| 不良品数量 | 其中不合格品数量 |
| 不良类型 | 不良原因分类（如：尺寸偏差/表面缺陷/材料问题） |
| 报工模式 | 按件 / 按工时 / 混合 |
| 备注 | 补充说明 |

**三种报工模式：**
- **按件报工**：记录本次完成多少件，实时累加到派工单进度
- **按工时报工**：记录本次工时（小时/分钟），用于工时统计和薪资核算
- **混合模式**：同一派工单内，既有按件记录也有按工时记录

## 三、状态机

### 3.1 订单状态流转

```
[待评审] → [已评审] → [已拆单] → [生产中] → [已完成] → [已发货]
              ↓
         [已取消]
```

### 3.2 派工单状态流转

```
[待派发] → [待接收] → [已接收] → [生产中] → [已完成]
               ↓
           [已取消]     ↓
                       ↓（如出现异常，可退回）
```

### 3.3 报工记录状态

```
[待提交] → [已提交] → [班组长确认] → [审核通过]
              ↓
         [被驳回]（数量异常/数据问题）
```

## 四、移动端核心流程

### 4.1 工人报工流程（移动端核心功能）

```
① 扫码 / 选择派工单
      ↓
② 查看派工信息（产品/工艺/计划数量/已报数量）
      ↓
③ 选择工序（若工艺含多工序）
      ↓
④ 填写报工数量
      ├── 良品数量（必填）
      └── 不良品数量 + 不良类型（选填）
      ↓
⑤ 确认提交
      ↓
⑥ 报工成功 → 刷新当前派工单进度
```

**设计要点：**
- 操作步骤 ≤ 5 步，最快 3 步完成一次报工
- 优先支持扫码快速定位派工单
- 不良类型预定义，减少输入成本
- 报工成功后显示当前完成进度

### 4.2 班组长审批流程（移动端）

```
① 收到报工待确认通知
      ↓
② 查看报工详情（数量/良品率/历史记录）
      ↓
③ 通过 / 驳回（需填写驳回原因）
      ↓
④ 审批记录存档
```

### 4.3 移动端查看流程

```
首页
  ├── 今日待报工列表
  ├── 当日产量统计
  └── 最新消息通知

看板
  ├── 产量达成率
  ├── 各派工单进度
  └── 班组/个人排名

我的
  ├── 我的报工记录
  ├── 设备点检记录
  └── 消息中心
```

## 五、PC端核心流程

### 5.1 订单管理

```
新建订单（录入产品/数量/交期）
      ↓
订单评审（评估产能/交期可行性）
      ↓
订单拆分（根据产品/工艺/交期拆成多个派工单）
      ↓
派工单生成（自动分配班组/计划日期）
      ↓
派工单下发（推送到对应班组）
```

### 5.2 生产计划

```
查看全部派工单列表
      ↓
甘特图排程（调整开工/完工日期）
      ↓
处理插单/撤单（调整计划）
      ↓
下发计划变更通知
```

### 5.3 基础数据管理

```
基础数据
  ├── 工艺库维护（定义工序和加工参数）
  ├── 班组管理（维护班组信息和成员）
  ├── 设备台账（设备基本信息）
  ├── 工序标准工时（用于排产参考）
  └── 人员绑定（工人→班组→工序权限）
```

### 5.4 数据报表

```
生产日报
  ├── 今日产量/良品率
  ├── 各班组产出对比
  └── 报工趋势

生产月报
  ├── 产量/产值统计
  ├── 良率分析
  ├── 设备利用率
  └── 订单准时交付率
```

## 六、关键设计原则

1. **数据一致性**：PC端和移动端共用同一数据库，同一订单/派工单编号，实时同步
2. **操作不可逆性**：报工数据一旦确认不可随意删除，只能冲销（新增反向记录）
3. **权限分层**：工人只能看/报自己的工单，班组长可看/审批全组，管理员可看全部
4. **离线容忍**：移动端在网络不稳定时支持本地缓存，网络恢复后自动同步
5. **状态可见**：报工状态/派工单进度对所有相关人员透明可查
