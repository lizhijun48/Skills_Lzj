## 核心工作流程

### Step 1：建立AARRR海盗指标体系

**AARRR漏斗全景**：

```
获取(Acquisition) → 激活(Activation) → 留存(Retention) → 推荐(Referral) → 收入(Revenue)
     ↑                                                                │
     └────────────────────── 付费回流/口碑回流 ──────────────────────┘
```

**每个环节的指标定义与实操**：

| 环节 | 核心问题 | 关键指标 | 计算方式 | 健康阈值 |
|------|----------|----------|----------|----------|
| **获取** | 用户从哪来？ | 渠道CAC | 渠道花费/渠道新增用户 | CAC < LTV/3 |
| | | 渠道占比 | 各渠道新增/总新增 | 单渠道≤40% |
| **激活** | 用户体验到价值了吗？ | 激活率 | 完成核心动作人数/注册人数 | >40% |
| | | 激活时长 | 注册到完成核心动作的时间 | <24h |
| **留存** | 用户还回来吗？ | 次日/7日/30日留存 | 第N天回访/新增日用户 | 次日>30%, 7日>15%, 30日>8% |
| | | 留存曲线斜率 | 第1→第30天衰减速率 | 第7天后趋于平缓 |
| **推荐** | 用户愿意分享吗？ | NPS | 推荐者%-贬损者% | >30(好) >50(优秀) |
| | | 病毒系数K | 每个用户带来新用户数 | K>1可自增长 |
| **收入** | 用户愿意付钱吗？ | ARPU | 总收入/活跃用户 | 因业务而异 |
| | | 付费转化率 | 付费用户/活跃用户 | >5% |
| | | LTV | ARPU × 平均生命周期 | LTV > 3×CAC |

**⚠️ 踩坑**：
- 不要只看PV/UV这些虚荣指标，关注留存和转化
- AARRR不是线性漏斗——用户可能在任何环节流失后回流
- 不同产品类型的健康阈值不同，以上为通用参考

### Step 2：漏斗分析找断点

**漏斗分析4步法**：

```
Step 1: 画出核心转化路径
  注册 → 完善资料 → 首次使用 → 付费转化 → 复购

Step 2: 计算每步转化率
  注册→完善资料：70%
  完善资料→首次使用：45%  ← 断点！
  首次使用→付费转化：8%
  付费转化→复购：35%

Step 3: 定位断点（转化率骤降的环节）
  断点在"完善资料→首次使用"（45%，远低于预期）

Step 4: 分析原因+设计实验
  假设1：资料表单太长，用户放弃 → 实验：减少必填项
  假设2：首次使用引导不足 → 实验：增加新手引导
```

**ToG/ToB漏斗差异**：

| 环节 | ToC产品 | ToG/ToB产品 |
|------|---------|-------------|
| 获取 | 广告投放/ASO/SEO | 招投标/销售线索/行业展会 |
| 激活 | 注册后首次体验 | 部署后首次使用/培训完成 |
| 留存 | 日活/月活 | 续约率/使用深度 |
| 推荐 | 社交分享/口碑 | 案例复购/转介绍 |
| 收入 | 订阅/增值服务 | 项目回款/运维续费/SaaS年费 |

### Step 3：增长实验设计

**增长实验标准流程**：

```
1. 提出假设 → 2. 设计实验 → 3. 执行+收集数据 → 4. 分析结果 → 5. 决策
```

**实验记录模板**：

| 字段 | 示例 |
|------|------|
| 实验ID | GX-2024-001 |
| 假设 | 如果简化注册流程（3步→1步），注册完成率将提升20% |
| 指标 | 注册完成率（北极星指标） |
| 对照组 | 现有3步注册流程 |
| 实验组 | 1步注册（OAuth/手机一键登录） |
| 样本量 | 每组≥1000用户（或使用统计功效计算器） |
| 运行时长 | 7天（覆盖完整周周期） |
| 结果 | 注册完成率从45%提升到62%，+17pp |
| 决策 | 全量上线1步注册 |

**实验优先级排序（ICE框架）**：

| 维度 | 评分(1-10) | 含义 |
|------|-----------|------|
| **I**mpact 影响力 | | 对核心指标的提升幅度 |
| **C**onfidence 信心 | | 假设成立的可能性 |
| **E**ase 容易度 | | 实验实施的成本和时间 |

```
ICE分数 = I × C × E / 1000
优先跑ICE分数最高的实验
```

### Step 4：A/B测试实操

**A/B测试6步法**：

```
Step 1: 确定测试目标
  "我要提升付费转化率"（不要说"我想试试换个按钮颜色"）

Step 2: 确定指标
  主要指标：付费转化率
  护栏指标：客单价不能下降（防止降价导致转化提升但收入下降）

Step 3: 计算样本量
  用在线计算器（如Evan Miller A/B测试计算器）
  输入：基准转化率、最小可检测效应(MDE)、统计显著性(95%)、统计功效(80%)

Step 4: 分流
  随机分流50/50，确保用户一致性（同一用户始终看到同一版本）

Step 5: 运行
  至少运行2周（覆盖完整行为周期）
  ⚠️ 不要提前看结果做决策！统计显著性需要足够样本

Step 6: 分析
  p-value < 0.05 → 结果显著，选优胜版本
  p-value ≥ 0.05 → 结果不显著，延长实验或放弃
```

**A/B测试常见错误**：

| # | 错误 | 后果 | 正确做法 |
|---|------|------|----------|
| 1 | 样本量不够就下结论 | 假阳性 | 先算样本量，达到再分析 |
| 2 | 同时测多个变量 | 不知道哪个变量起效 | 一次只测一个变量 |
| 3 | 测试时间太短 | 忽略周内行为差异 | 至少2周 |
| 4 | 只看主要指标不管护栏指标 | 优化了转化但损害了收入 | 必须设护栏指标 |
| 5 | 提前停止实验 | 第一天效果好不等于持续好 | 按计划运行完毕 |

### Step 5：用户运营策略

**4大用户运营策略**：

| 策略 | 目标 | 核心方法 | 关键指标 |
|------|------|----------|----------|
| **拉新** | 获取新用户 | 渠道投放/内容营销/邀请有礼/ASO | CAC, 渠道ROI |
| **促活** | 让沉默用户重新活跃 | Push/EDM/签到/任务体系 | DAU/MAU, 促活率 |
| **留存** | 让用户持续使用 | 会员体系/个性化推荐/社区 | 留存率, 流失率 |
| **转化** | 让用户付费 | 限时优惠/免费试用/阶梯定价 | 付费转化率, ARPU |

**用户分层运营（RFM模型）**：

```
R(Recency) = 最近一次活跃距今多久
F(Frequency) = 一定时间内活跃次数
M(Monetary) = 一定时间内付费金额

RFM打分(1-5分) → 用户分8类：

| 用户类型 | R | F | M | 运营策略 |
|----------|---|---|---|----------|
| 重要价值用户 | 高 | 高 | 高 | VIP服务，防流失 |
| 重要发展用户 | 高 | 低 | 高 | 提升活跃频次 |
| 重要保持用户 | 低 | 高 | 高 | 唤醒+专属优惠 |
| 重要挽留用户 | 低 | 低 | 高 | 一对一回访，了解流失原因 |
| 一般价值用户 | 高 | 高 | 低 | 引导付费升级 |
| 一般发展用户 | 高 | 低 | 低 | 培养使用习惯 |
| 一般保持用户 | 低 | 高 | 低 | 低成本触达(Push/EDM) |
| 一般挽留用户 | 低 | 低 | 低 | 自动化触达，不投入过多资源 |
```

### Step 6：灰度发布与特性开关

**灰度发布策略**：

| 策略 | 做法 | 适用场景 |
|------|------|----------|
| **按比例** | 1%→5%→10%→50%→100% | 通用 |
| **按用户** | 内部用户→种子用户→全部用户 | B端/企业产品 |
| **按功能** | 新功能只对特定用户组开放 | 付费功能A/B测试 |
| **按地域** | 先在1个城市上线验证 | 本地化功能/合规要求 |

**特性开关（Feature Flag）**：

```
作用：不重新部署就能开关功能

开关类型：
- 发布开关：灰度时控制功能可见性（短期，发布后移除）
- 实验开关：A/B测试分流（中期，实验结束后移除）
- 运维开关：紧急关闭出问题的功能（长期保留）
- 权限开关：按用户角色控制功能可见性（长期保留）

⚠️ 踩坑：
- 发布开关必须及时清理（否则变成技术债务）
- 开关数量需管理（>50个开关=维护噩梦）
- 开关状态变更需要记录审计日志
```

## 踩坑预警

| # | 坑点 | 表现 | 规避 |
|---|------|------|------|
| 1 | **只看PV/UV虚荣指标** | "日活很高"但付费转化低 | 关注AARRR全链路，尤其留存和转化 |
| 2 | **不做实验拍脑袋运营** | "我觉得发个优惠券就行了" | 所有运营动作都要量化验证 |
| 3 | **A/B测试不设护栏指标** | 转化率提升但客单价暴跌 | 主要指标+护栏指标同时监控 |
| 4 | **留存没看就做拉新** | 新用户来了就走 | 先修留存漏斗，再做拉新 |
| 5 | **灰度没回滚预案** | 灰度出问题影响5%用户 | 灰度前必须有Feature Flag一键关闭 |
| 6 | **Feature Flag不清理** | 代码里50+开关，没人敢删 | 发布后2周内清理发布开关 |

## 政企产品专项支持（ToG/ToB）

### ToG/ToB运营差异

| 维度 | ToC运营 | ToG/ToB运营 |
|------|---------|-------------|
| 核心指标 | DAU/MAU/付费率 | 续约率/NPS/使用深度/工单量 |
| 拉新 | 广告投放 | 招投标/销售打单/行业案例 |
| 留存 | Push/签到/会员 | 客户成功(CSM)/定期巡检/培训 |
| 转化 | 限时优惠/免费试用 | POC验证/试用→合同/增值模块 |
| 数据 | 自动化埋点+分析 | 客户私有化部署→数据获取受限 |

### ToB客户成功(CSM)运营框架

```
客户成功3阶段：

1. 交付期（0-30天）
   - 部署完成 → 管理员培训 → 关键用户培训
   - 指标：培训完成率、首次使用时间

2. 成长期（1-6月）
   - 使用推广 → 深度功能引导 → 定期回访
   - 指标：使用覆盖率（多少人用了）、功能渗透率（用了多少功能）

3. 续约期（6-12月）
   - 续约评估 → 增购/升级 → 合同续签
   - 指标：续约率、NDR(净收入留存率)

⚠️ ToB运营铁律：续约率>90%才健康，<80%要警觉
```

## 核心原则

1. **数据驱动而非直觉驱动**——"我觉得"不如"A/B测试证明"
2. **留存是1，其他是0**——拉来用户留不住=白费力气
3. **实验必须可量化**——没有指标的实验不是实验，是瞎试
4. **护栏指标保底线**——优化转化不能以牺牲客单价为代价
5. **灰度发布是安全网**——新功能不上灰度=拿全部用户当小白鼠
6. **Feature Flag及时清理**——僵尸开关是技术债务，发布后2周必清
7. **ToB运营看续约率**——ToC看日活，ToB看续约，续约率<80%要警觉
