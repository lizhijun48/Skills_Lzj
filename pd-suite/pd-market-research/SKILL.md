## 核心工作流程

### Step 1：定义研究问题（最易忽略）

**研究问题定义模板**：
```
我们想知道：________________________________
决策用途：☐进入/放弃市场 ☐定价 ☐功能优先级 ☐竞争策略
精度要求：☐方向性(±50%) ☐中等(±30%) ☐精确(±10%)
时间约束：☐1周内 ☐2-4周 ☐1-3月
预算约束：☐0 ☐<1万 ☐1-5万 ☐>5万
```

**⚠️ 踩坑**：最常见错误是"什么都想了解"——市场研究必须服务于具体决策，不是做大而全的"市场报告"。

### Step 2：选择研究方法

**12种研究方法选择矩阵**：

| 方法 | 类型 | 周期 | 成本 | 样本量 | 适用场景 |
|------|------|------|------|--------|----------|
| 1 次级数据研究 | 定量 | 1-3天 | 0 | N/A | 市场规模初判、行业趋势 |
| 2 专家访谈 | 定性 | 1-2周 | 0-5000 | 3-5人 | 行业深度、ToG政策解读 |
| 3 焦点小组 | 定性 | 1-2周 | 5000-2万 | 6-8人×2-3组 | 概念测试、需求探索 |
| 4 问卷调查 | 定量 | 2-4周 | 5000-5万 | 100+ | 需求验证、满意度测量 |
| 5 客户深度访谈 | 定性 | 2-3周 | 0-5000 | 8-12人 | 痛点挖掘、需求深度 |
| 6 竞品体验分析 | 定性+定量 | 1-2周 | 0 | 3-7竞品 | 功能/体验对标 |
| 7 用户行为分析 | 定量 | 1-2周 | 0 | 全量数据 | 已有产品的优化 |
| 8 A/B测试 | 定量 | 2-4周 | 0 | 1000+ | 功能/设计决策 |
| 9 社交聆听 | 定性 | 1-2周 | 0-1万 | N/A | 品牌认知、用户口碑 |
| 10 着陆页测试 | 定量 | 1-2周 | <5000 | 500+点击 | 需求验证、文案测试 |
| 11 现场观察 | 定性 | 1-2周 | 差旅费 | 5-8场景 | ToB/ToG使用场景理解 |
| 12 POC验证 | 定性+定量 | 2-4周 | 5-20万 | 1-3客户 | ToB解决方案验证 |

**选择决策表**：

| 研究目的 | 推荐方法组合 | 优先级 |
|----------|-------------|--------|
| 判断"做不做" | 次级数据+专家访谈+着陆页测试 | pd-go-nogo阶段 |
| 判断"怎么做" | 客户深度访谈+焦点小组+竞品分析 | pd-requirements-design阶段 |
| 判断"好不好" | 问卷调查+用户行为分析+A/B测试 | pd-product-operations阶段 |
| ToG政策研判 | 次级数据+专家访谈+现场观察 | 政企产品必备 |

### 高级定量方法

> **NPDP Ch4核心**：以下方法是NPDP认证高频考点，也是产品经理进阶必备的定量分析工具。

**联合分析（Conjoint Analysis）**：

| 维度 | 说明 |
|------|------|
| **用途** | 量化用户对不同产品属性的偏好权重，适用于功能取舍、定价研究 |
| **原理** | 让用户在多个属性组合中做选择，通过选择反推各属性的相对重要性 |
| **输出** | 各属性的效用值(Part-Worth Utility) + 属性相对重要性百分比 |

**简易联合分析4步法**：
```
Step 1：确定核心属性（如：价格/功能/品牌/响应速度，选3-5个）
Step 2：每个属性设置2-3档（如：价格=5万/10万/20万）
Step 3：设计6-8组对比场景，让每组的用户做出选择
Step 4：计算各属性的边际效用和相对重要性
```

**适用场景**：
- "免费版要砍掉哪个功能？"→ 联合分析看用户最不在乎哪个
- "定价10万还是15万？"→ 联合分析看价格vs功能的trade-off
- 与KANO的区别：KANO看"需求类型"，联合分析看"价值量化"

**德尔菲法（Delphi Method）**：

| 维度 | 说明 |
|------|------|
| **用途** | 通过多轮匿名问卷逐步收敛专家共识，适用于技术趋势预判、ToG政策走向 |
| **流程** | 第1轮(开放式收集意见)→第2轮(匿名反馈+评分)→第3轮(重评分收敛)→第4轮(确认共识) |
| **核心原则** | 匿名(避免权威影响)、迭代(多轮收敛)、反馈(告诉专家其他人怎么回答) |
| **样本量** | 一般15-30名专家，3-4轮 |

**德尔菲法 vs 普通专家访谈**：

| 维度 | 普通专家访谈 | 德尔菲法 |
|------|------------|---------|
| 专家互动 | 面对面，互相影响 | 匿名，互不知情 |
| 轮次 | 1次 | 3-4轮迭代 |
| 结果 | 个人观点 | 群体共识(收敛后的) |
| 适用 | 快速获取深度洞察 | 需要可信的集体判断 |

### Step 3：市场规模测算（TAM/SAM/SOM）

```
┌─────────────────────────────────────────────────────┐
│                                                       │
│  ┌──────────────────────────────────────────────┐    │
│  │  TAM（总可用市场）                             │    │
│  │  整个市场的全部需求量                           │    │
│  │  ┌────────────────────────────────────┐      │    │
│  │  │  SAM（可服务可用市场）               │      │    │
│  │  │  我们的产品/渠道能覆盖的市场         │      │    │
│  │  │  ┌────────────────────────────┐    │      │    │
│  │  │  │  SOM（可服务可获得市场）     │    │      │    │
│  │  │  │  考虑竞争后我们能拿到的份额   │    │      │    │
│  │  │  └────────────────────────────┘    │      │    │
│  │  └────────────────────────────────────┘      │    │
│  └──────────────────────────────────────────────┘    │
│                                                       │
│  计算方法：                                           │
│  TAM = 行业总规模（自上而下）或 目标用户数×ARPU（自下而上）│
│  SAM = TAM × 渠道覆盖率 × 地域覆盖率                  │
│  SOM = SAM × 预期市场份额（参考竞品市占率）             │
└─────────────────────────────────────────────────────┘
```

**TAM测算实操（自下而上法，推荐）**：

```
Step 1: 确定目标客户画像
  - 行业：__________
  - 规模：__________人以上 / __________万营收以上
  - 地域：__________

Step 2: 数量估算
  - 企查查/天眼查：搜索符合条件的公司数 = ______家
  - 减去不具备购买力的 = ______家（排除年营收<______万的）
  - SAM = ______家

Step 3: ARPU估算
  - 产品定价：______元/年
  - 实施服务：______元/次
  - 综合ARPU：______元/年

Step 4: 计算
  - TAM = 目标行业总IT支出（参考IDC/艾瑞报告）= ______亿
  - SAM = 目标客户数 × ARPU = ______亿
  - SOM = SAM × 预期3年市占率______% = ______亿

⚠️ 关键：SOM才是你向老板/投资人汇报的"真实市场"
```

### Step 4：宏观环境分析（PESTLE）

| 维度 | 分析要点 | 与产品的关联 | 数据来源 |
|------|----------|-------------|----------|
| **P 政治** | 产业政策、监管趋势、贸易政策 | 产品合规要求、准入门槛 | 政府官网、行业白皮书 |
| **E 经济** | GDP增速、行业投资、汇率 | 市场购买力、定价策略 | 国家统计局、行业报告 |
| **S 社会** | 人口结构、消费习惯、价值观 | 目标用户画像、需求趋势 | 艾瑞/CNNIC报告 |
| **T 技术** | 技术成熟度、替代技术、基础设施 | 技术选型、产品架构 | Gartner/技术社区 |
| **L 法律** | 行业法规、知识产权、数据保护 | 合规设计、风控 | 法务咨询、法规库 |
| **E 环境** | ESG、碳中和、可持续发展 | 产品可持续性设计 | 行业标准、ESG报告 |

**PESTLE评分**：每个维度1-5分，≤2分的维度需制定应对策略

### Step 5：行业竞争分析（波特五力）

```
            新进入者威胁
                │
  供应商议价能力 ─┼─ 买方议价能力
                │
            替代品威胁
       + 现有竞争者竞争强度
```

| 力量 | 评估维度 | 高/中/低 | 对产品策略的影响 |
|------|----------|---------|-----------------|
| 现有竞争者 | 竞品数量/差异化/退出壁垒 | | 高=需要明确差异化定位 |
| 新进入者 | 资本门槛/技术门槛/政策门槛 | | 高=建立护城河 |
| 替代品 | 替代方案数量/切换成本 | | 高=产品需提供不可替代价值 |
| 买方议价 | 客户集中度/信息透明度/切换成本 | | 高=产品需降低客户切换成本 |
| 供应商议价 | 供应商集中度/替代性/纵向整合 | | 高=产品需降低供应商依赖 |

### Step 6：竞品分析

**竞品分析5-7产品选择规则**：
- 直接竞品3-4个（同品类同市场）
- 间接竞品1-2个（不同品类但解决同一问题）
- 潜在竞品1个（大平台可能进入）

**竞品对比矩阵**：

| 渠道策略 | | | | |
| 优势 | | | | |

### 感知图分析（Perceptual Mapping）

> **NPDP Ch4核心**：感知图是多维尺度分析的可视化输出，用于理解用户对不同产品/品牌的认知定位，是竞品定位分析的核心工具。

**感知图示例（2D价格-功能矩阵）**：

```
功能多 ↑
       │  ● 竞品A           ● 我方（目标定位）
       │   (高端全功能)        (高性价比)
       │
       │      ● 竞品B
       │       (中端)
       │
       │  ● 竞品C               ● 竞品D
       │   (低端基础版)           (高端聚焦)
       │
       └──────────────────────────→ 价格高
```

**感知图构建3步法**：
1. **选维度**：选择用户最关心的2个维度（如：价格-功能、性能-易用性、创新-稳定）
2. **定位置**：根据用户调研/评分，将各竞品/产品放在2D矩阵的对应位置
3. **定策略**：基于位置关系制定定位策略

**基于感知图的定位策略**：

| 感知图发现 | 定位策略 | 动作 |
|-----------|---------|------|
| 高价值区无竞品 | **差异化占位** | 快速抢占空白地带 |
| 被竞品包围 | **重新定位** | 换个维度竞争（如：不打功能打服务） |
| 竞品扎堆一处 | **价格/服务区隔** | 在相邻位置建立差异 |
| 远离目标用户需求 | **产品调整** | 移动功能/价格定位点 |

**与SWOT/波特五力的关系**：
- SWOT告诉你"我们能做什么"，感知图告诉你"市场怎么看"
- 波特五力看行业结构，感知图看用户认知
- 感知图+SWOT=制定定位策略的完整输入

## 踩坑预警

| # | 坑点 | 表现 | 规避 |
|---|------|------|------|
| 1 | **研究无目的** | "做个市场调研"但不知道要回答什么问题 | 先填研究问题定义模板 |
| 2 | **数据来源不标注** | "市场规模1000亿"但不说哪里来的 | 每个数据标注来源+年份+口径 |
| 3 | **TAM当SOM** | "这个市场1000亿"但你能拿到的可能只有1亿 | 3层漏斗逐级收敛，SOM才是你的 |
| 4 | **只看竞品不看替代** | 忽略了用其他方式解决同一问题的产品 | 波特五力必须分析替代品 |
| 5 | **SWOT无策略** | 列了SWOT但没有TOWS行动 | SWOT只是输入，TOWS才是输出 |
| 6 | **一次研究管全年** | 市场变化快，半年前的数据可能已过期 | 季度更新关键假设 |

## 政企产品专项支持（ToG/ToB）

### ToG市场研究特殊方法

| 维度 | ToG差异 | 实操要点 |
|------|---------|----------|
| 市场规模 | 看政府采购预算而非用户数 | 用政府采购网数据+财政预算报告 |
| 竞品分析 | 关系型竞争，非纯产品竞争 | 加入"客户关系""资质壁垒"维度 |
| PESTLE | P(政策)是决定性力量 | 政策分析权重>50% |
| 研究方法 | 专家访谈+现场观察>问卷调查 | 政府客户无法做大规模问卷 |
| 数据来源 | 政府公开数据远少于2C | 用政府采购公告+规划文件替代 |

**ToG政策解读3步法**：
1. **找文件**：搜"十四五"+行业名+信息化/数字化，定位国家/省/市三级文件
2. **摘要点**：标注"建设目标""重点任务""保障措施"3段中的量化指标
3. **翻译为产品需求**：政策要求→功能需求映射表

### ToB市场研究特殊考量

| 维度 | ToB差异 | 实操要点 |
|------|---------|----------|
| 市场规模 | 按行业×规模分层计算 | SAM=目标行业×目标规模企业数×ARPU |
| 竞品分析 | 需加"生态位"维度 | 做平台商插件vs自建平台，路线不同 |
| 研究方法 | POC验证>问卷调查 | ToB产品验证靠POC，不是问卷 |

|--------|------|----------|
| 研究问题定义 | 模板 | 必须 |
| 市场规模测算 | TAM/SAM/SOM | 必须 |
| PESTLE分析 | 6维度表+评分 | 必须 |
| 波特五力分析 | 5力评估表 | 必须 |
| 竞品对比矩阵 | 5-7产品对比表 | 必须 |
| SWOT+TOWS | 矩阵+策略 | 必须 |
| 研究结论1页纸 | 模板 | 必须 |

---

## 核心原则

1. **研究服务于决策**——没有具体决策目标的研究=浪费钱，先定义问题再选方法
2. **SOM才是你的市场**——TAM让你兴奋，SOM让你清醒，汇报SOM不汇报TAM
3. **数据必须标注来源**——"据XX报告2025年"比"大概1000亿"有价值100倍
4. **竞品分析看替代品**——打败你的往往不是同行，而是另一种解决方案
5. **SWOT没有TOWS就是废纸**——列出优势劣势不是目的，转化为策略才是
6. **ToG研究看政策**——政策是ToG市场的"天气预报"，不看政策=盲飞
