## 核心工作流程

### Step 1：确定北极星指标

**北极星指标=最能衡量产品价值交付的唯一核心指标**

**选择规则**：

| 产品类型 | 推荐北极星 | 示例 |
|----------|-----------|------|
| 社交/内容 | 日活用户时长 | 抖音：日均使用时长 |
| 电商 | GMV或购买频次 | 淘宝：月均购买次数 |
| SaaS | 月度活跃用户数(MAU) | 飞书：MAU |
| 工具型 | 任务完成率 | Figma：每周创建文件数 |
| ToG/ToB | 核心业务覆盖度 | 某安防平台：设备在线率 |

**⚠️ 常见错误**：
- ❌ 注册量当北极星（注册≠使用）
- ❌ 收入当北极星（收入是结果不是驱动因素）
- ✅ 找到"用户获得价值"的那个指标

**北极星指标拆解公式**：
```
北极星 = 功能X使用率 × 用户留存率 × 付费转化率
         │              │            │
         ▼              ▼            ▼
      输入指标       过程指标      输出指标
```

### Step 2：OKR目标管理

**OKR写作规范**：

```
Objective（目标）：定性描述，鼓舞人心
  "成为XX行业最好用的XX平台"

Key Results（关键结果）：定量，可衡量，3-5条
  KR1: DAU从1万提升到5万
  KR2: 用户留存率从30%提升到45%
  KR3: NPS从20提升到40
  KR4: 月收入从50万提升到200万
```

**OKR质量检查**：

| 检查项 | ✅ 好的OKR | ❌ 差的OKR |
|--------|----------|----------|
| O是否鼓舞人心？ | "成为行业标杆" | "完成Q2功能开发" |
| KR是否可量化？ | "DAU提升至5万" | "提高用户活跃度" |
| KR是否3-5条？ | 4条 | 10条 |
| 完成度70%算好？ | 是（太容易=目标太低） | 100%才满意（说明目标太低） |
| 是否对齐上级OKR？ | 是 | 各自为政 |

**OKR vs KPI**：

| 维度 | OKR | KPI |
|------|-----|-----|
| 性质 | 方向性 | 考核性 |
| 完成度 | 70%=好 | 100%=达标 |
| 周期 | 季度 | 年度 |
| 用途 | 引领方向 | 衡量绩效 |
| 透明度 | 全公司可见 | 部门内可见 |

### Step 3：9种优先级排序框架

| # | 框架 | 适用场景 | 复杂度 | 示例 |
|---|------|----------|--------|------|
| 1 | **MoSCoW** | 需求分类 | ★ | Must/Should/Could/Won't |
| 2 | **RICE** | 功能优先级量化 | ★★ | Reach×Impact×Confidence/Effort |
| 3 | **KANO** | 需求类型分类 | ★★ | 基本/期望/兴奋/无差异/反向 |
| 4 | **价值-复杂度矩阵** | 快速分类 | ★ | 高价值低复杂度=先做 |
| 5 | **WSJF(SAFe)** | 大规模敏捷 | ★★★ | 用户价值+时间价值+风险降低/工作量 |
| 6 | **机会评分** | 多维度综合 | ★★ | (功能重要性-当前满意度)×用户数 |
| 7 | **Buy a Feature** | 多干系人协商 | ★★ | 每人虚拟货币"购买"功能 |
| 8 | **优先级矩阵(Eisenhower)** | 紧急vs重要 | ★ | 重要紧急/重要不紧急/紧急不重要/不重要不紧急 |
| 9 | **成对比较** | 争议大时强制排序 | ★★ | 每对比较→得分排序 |

**最常用的3个框架实操**：

#### RICE评分法（推荐作为默认框架）

```
RICE得分 = (Reach × Impact × Confidence) / Effort

Reach(覆盖面)：每季度受影响用户数
  ×3 = 10万+用户
  ×2 = 1-10万用户
  ×1 = <1万用户

Impact(影响力)：每个用户的影响程度
  ×3 = 巨大影响
  ×2 = 中等影响
  ×1 = 轻微影响
  ×0.5 = 极小影响

Confidence(信心度)：
  ×100% = 高信心(有数据支撑)
  ×80% = 中信心(有部分数据)
  ×50% = 低信心(凭直觉)

Effort(工作量)：人月
  ÷ 0.5 = 0.5人月
  ÷ 1 = 1人月
  ÷ 2 = 2人月
  ÷ 3 = 3+人月
```

#### 价值-复杂度矩阵

```
        高价值
          │  ●先做  ●先做
          │
  ─────────┼──────────
          │  ●后做  ●不做
        低价值
     低复杂度   高复杂度
```

| 象限 | 策略 | 动作 |
|------|------|------|
| 高价值低复杂度 | **Quick Win** | 立即做 |
| 高价值高复杂度 | **Major Project** | 规划后做 |
| 低价值低复杂度 | **Fill-in** | 有空再做 |
| 低价值高复杂度 | **Thankless Task** | 不做 |

### Step 4：财务分析

**4种核心财务指标**：

| 指标 | 公式 | 用途 | 判断标准 |
|------|------|------|----------|
| **ROI(投资回报率)** | (收益-投资)/投资×100% | 评估投入产出 | >30%为优 |
| **NPV(净现值)** | Σ CF_t/(1+r)^t | 评估长期价值 | >0即可行 |
| **IRR(内部收益率)** | NPV=0时的折现率 | 比较不同项目 | >资本成本率(15%) |
| **EVA(经济增加值)** | NOPAT-资本×资本成本率 | 评估真实盈利 | >0即创造价值 |

> **💡 精确计算调用工具**：当财务指标需要精确计算（而非3分钟速算）时，优先调用 `economic-suite/` 下的独立工具，避免重复造轮子：
> - **NPV计算** → 调用 `economic-npv`（支持多期现金流、不同折现率）
> - **IRR计算** → 调用 `economic-irr`（支持常规IRR、MIRR）
> - **投资回收期计算** → 调用 `economic-payback`（支持静态/动态回收期，含行业基准对比）
> - **价值工程分析** → 调用 `economic-ve`（V=F/C，功能成本价值比）
> - **多方案比选** → 调用 `economic-comparison`（增量分析/年值法）
> - **敏感性分析** → 调用 `economic-sensitivity`（单因素/多因素/场景分析）
> 
> 调用路径：`pd-tools-metrics` → 识别需要精确计算 → 调用对应 `economic-*` 工具 → 将结果映射回OKR/北极星指标体系。

**产品经理的3分钟财务速算**：

```
预估年收益 = ARPU × 目标用户数 × 渗透率
预估年成本 = 人月成本 × 团队人数 × 月数 + 运营成本
ROI = (年收益 - 年成本) / 年成本 × 100%
回本周期 = 初始投入 / 月净收益

举例：
ARPU = 5万/年
目标用户数 = 200家
渗透率 = 10%（首年）
年收益 = 5万 × 200 × 10% = 100万
团队 = 5人 × 2万/月 × 12月 = 120万
运营 = 20万/年
年成本 = 140万
ROI = (100-140)/140 = -28% ← 首年亏损正常
第2年：渗透率20% → 年收益200万，ROI = (200-140)/140 = 43%
```

| 字母 | 含义 | 提问 | 举例 |
|------|------|------|------|

#### QFD 质量功能展开（质量屋）

> **NPDP Ch6核心工具**：QFD（Quality Function Deployment）是将用户需求（VOC）转化为技术要求的系统性工具，"质量屋"（House of Quality）是其标志性输出。

**QFD适用场景**：新产品开发中，需要将用户需求精确转化为工程参数时（如制造业、硬件产品、复杂软件系统）。

**质量屋（HoQ）结构**：

```
┌──────────────┬─────────────────────┐
│              │  5. 屋顶：技术参数    │
│              │     相关关系矩阵     │
├──────────────┼─────────────────────┤
│ 1. VOC用户   │ 4. 关系矩阵          │
│    需求列表   │  (强◎/中○/弱△)      │
├──────────────┼─────────────────────┤
│              │ 6. 技术参数目标值     │
│ 2. 需求权重   │     与竞品对标       │
└──────────────┴─────────────────────┘
```

**质量屋6大组件**：

| # | 组件 | 说明 | 做法 |
|---|------|------|------|
| 1 | VOC用户需求 | 用户想要什么 | 列出8-12个关键需求（来自pd-user-research） |
| 2 | 需求权重 | 每个需求有多重要 | 1-5分评分或KANO权重 |
| 3 | 竞品对标 | 竞品在每个需求上的表现 | 1-5分评分，找出差距 |
| 4 | 关系矩阵 | 需求→技术参数的映射 | ◎强(9分)/○中(3分)/△弱(1分) |
| 5 | 技术相关性 | 技术参数之间的相互影响 | +强正相关/-强负相关 |
| 6 | 技术目标值 | 每个技术参数的目标 | 量化目标+我方/竞品当前水平 |

**QFD简化实操（产品经理版）**：
```
Step 1：列出8-12个用户需求（VOC），用KANO模型初筛
Step 2：为每个需求赋权重（1-5分）
Step 3：列出8-12个技术参数（HOW），每条必须是可量化的
Step 4：完成需求×技术参数的关系矩阵（◎○△）
Step 5：计算每个技术参数的重要性总分 = Σ(需求权重×关系分值)
Step 6：TOP 5技术参数=优先级最高的工程方向

不需要完整质量屋——产品经理通常只需要做到Step 4-5就够了
```

**实战示例（安防摄像头）**：

| VOC需求 | 权重 | 分辨率 | 帧率 | 夜视距离 | 防水等级 |
|---------|------|--------|------|---------|---------|
| 画面清晰 | 5 | ◎(9) | ○(3) | ○(3) |  |
| 夜间有效 | 5 | ○(3) |  | ◎(9) |  |
| 耐户外环境 | 3 |  |  |  | ◎(9) |
| 流畅回放 | 4 |  | ◎(9) |  |  |
| **技术重要性总分** | - | 55 | 63 | 60 | 27 |

→ 帧率>夜视>分辨率>防水——资源优先分配给帧率提升和夜视优化

## 踩坑预警

| # | 坑点 | 表现 | 规避 |
|---|------|------|------|
| 1 | **虚荣指标** | 只看PV/注册量，不看留存/付费 | 北极星指标必须反映真实价值交付 |
| 2 | **OKR太多** | 10个O+30个KR | 1个O+3-5个KR，少即是多 |
| 3 | **优先级框架换来换去** | 这周RICE下周KANO | 选定1-2个框架持续使用 |
| 4 | **财务只看收入** | 不算成本只看营收 | ROI是收入/成本，只看一半没意义 |
| 5 | **指标对不上行动** | 发现指标下降但不知道做什么 | 每个指标必须有Owner和改善行动 |
| 6 | **创新工具当圣经** | SCAMPER/TRIZ逐条硬套 | 这些工具是启发器不是检查清单 |

## 政企产品专项支持（ToG/ToB）

### ToG产品度量特殊考量

| 维度 | ToG差异 | 实操要点 |
|------|---------|----------|
| 北极星 | 不适用2C的DAU/留存 | 用"业务覆盖度""在线率""处置率"等政企指标 |
| OKR | 政府项目按合同KPI | OKR用于内部驱动，KPI用于合同考核 |
| 财务分析 | 回款周期长 | NPV用8-10%折现率反映回款风险 |
| 优先级 | 政策驱动>用户驱动 | 等保合规功能优先级最高 |

### ToB产品度量特殊考量

| 维度 | ToB差异 | 实操要点 |
|------|---------|----------|
| 北极星 | ARR/MRR+续约率 | SaaS看月度经常性收入+Net Retention |
| KPI | CAC<LTV/3 | 获客成本<客户终身价值1/3 |
| 优先级 | 大客户需求优先级权重高 | KA需求用加权RICE（KA权重×1.5） |

## 核心原则

1. **北极星只有一个**——多个"核心指标"=没有核心，所有人对齐一个方向
2. **OKR完成70%=好**——100%完成说明目标太低，50%说明目标太高或执行有问题
3. **虚荣指标≠价值指标**——PV/注册量让你感觉良好，留存/付费才是真价值
4. **优先级框架选1-2个用到底**——换来换去=没有框架
5. **财务是产品经理的必修课**——不会算ROI的PM和画图工没有区别
6. **创新工具是启发器不是检查清单**——打开思路，不是逐条打卡
